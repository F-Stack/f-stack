### 1.2 UMA zone max 强制执行验证

**结论：UMA zone max 在 f-stack 用户态栈中真正强制执行。**

证据链：

1. `socreate()` 调用 `soalloc()` 分配 socket（`uipc_socket.c:948-950`）：

```c
948: so = soalloc(CRED_TO_VNET(cred));
949: if (so == NULL)
950:     return (ENOBUFS);
```

2. `soalloc()` 使用 `uma_zalloc(socket_zone, M_NOWAIT | M_ZERO)`（`uipc_socket.c:797`），分配失败返回 NULL。

3. `uma_zalloc` 最终调用 `zone_alloc_item()`（`freebsd/vm/uma_core.c:4457`），其中有明确的 max 检查：

```c
4461: if (zone->uz_max_items > 0 && zone_alloc_limit(zone, 1, flags) == 0) {
4462:     counter_u64_add(zone->uz_fails, 1);
4463:     return (NULL);
4464: }
```

4. `zone_alloc_limit()`（`uma_core.c:4311-4338`）使用 `atomic_fetchadd_64(&zone->uz_items, count)` 原子递增已分配计数，与 `uz_max_items` 比较，超限则调用 `zone_alloc_limit_hard()` 进入等待/失败路径。

5. `uma_zone_set_max()`（`uma_core.c:4992-5017`）设置 `zone->uz_max_items = nitems` 并置 `UMA_ZFLAG_LIMIT` 标志：

```c
5009: zone->uz_max_items = nitems;
5010: zone->uz_flags |= UMA_ZFLAG_LIMIT;
```

**因此：当 socket_zone 分配数达到 maxsockets 时，`uma_zalloc` 返回 NULL → `soalloc` 返回 NULL → `socreate` 返回 `ENOBUFS`。强制执行链完整。**

### 1.3 f-stack 配置路径

| 配置文件位置 | 行号 | 内容 |
|-------------|------|------|
| `config.ini` `[freebsd.boot]` 段 | 327 | `kern.ipc.maxsockets=262144` |

加载链：
1. `lib/ff_config.c:171-209` `freebsd_conf_handler()` 解析 `[freebsd.boot]` 段，将 `kern.ipc.maxsockets=262144` 存入 `cfg->freebsd.boot` 链表。

3. `uipc_socket.c:747` `init_maxsockets()` 在 SYSINIT 阶段调用 `TUNABLE_INT_FETCH("kern.ipc.maxsockets", &maxsockets)` 从 kenv 读取值 → `maxsockets = 262144`。
4. `uipc_socket.c:689` `socket_init()` SYSINIT 调用 `uma_zone_set_max(socket_zone, maxsockets)` 将上限应用到 socket_zone。

### 1.4 结论

**完整可用。**

- maxsockets 变量定义、UMA zone max 设置、tunable 读取、sysctl 运行时修改路径全部完整。
- UMA zone max 在 f-stack 用户态栈中真正强制执行（`zone_alloc_item:4461` → `zone_alloc_limit:4311`）。
- f-stack `config.ini` 通过 `[freebsd.boot]` 段配置 `kern.ipc.maxsockets=262144`，经 kenv → TUNABLE_INT_FETCH → uma_zone_set_max 完整加载。

```c

1034: if (over) {
1036:     head->sol_overcount++;
// ... 日志记录后返回 NULL
```

`sonewconn()`（:1232）调用 `solisten_clone()`，如果 `sol_qlen`（完成队列长度）超过 `3 * sol_qlimit / 2`，则拒绝创建新连接（返回 NULL）。

- 半连接队列满时丢弃最老条目（`uipc_socket.c:1280-1293`）。

## 5. mbuf 池水位检查点（机制 E）

### 5.1 收包路径分析

f-stack 收包主循环（`lib/ff_dpdk_if.c:2810-2844`）：

```
rte_eth_rx_burst(port_id, queue_id, pkts_burst, MAX_PKT_BURST)  [L2815]
  → process_packets(port_id, queue_id, &pkts_burst[j], 1, ctx, 0)  [L2835/2840]
    → protocol_filter(data, len)  [L2096]
    → ff_veth_input(ctx, rtem)  [L2138/2145/2153/2156/2160]
      → ff_mbuf_gethdr(pkt, ...)  [L1852]  ← 从 pktmbuf_pool 分配 ff_mbuf_hdr
      → ff_veth_process_packet(ctx->ifp, hdr)  [L1890]
        → if_input(ifp, mb)  [ff_veth.c:558]
          → netisr → ip_input → TCP 栈
```

**当前收包路径中没有任何 mbuf 池水位检查。** 全路径搜索 `rte_mempool_avail`、`rte_mempool_count` 在 `lib/ff_dpdk_if.c` 中零命中。

### 5.2 mbuf 池创建与大小计算

mbuf 池创建（`lib/ff_dpdk_if.c:632-635`）：

```c
632: pktmbuf_pool[socketid] =
633:     rte_pktmbuf_pool_create(s, nb_mbuf,
634:         MEMPOOL_CACHE_SIZE, 0,
635:         data_room, socketid);
```

mbuf 池大小计算公式（`lib/ff_dpdk_if.c:583-593`）：

```c
583: unsigned nb_mbuf = RTE_ALIGN_CEIL (
584:     (nb_rx_queue * (max_portid + 1) * 2 * RX_QUEUE_SIZE          +
585:     nb_ports * (max_portid + 1) * 2 * nb_lcores * MAX_PKT_BURST    +
586:     nb_ports * (max_portid + 1) * 2 * nb_tx_queue * TX_QUEUE_SIZE  +
587:     nb_lcores * MEMPOOL_CACHE_SIZE +
588: #ifdef FF_KNI
589:     nb_ports * KNI_MBUF_MAX +
590:     nb_ports * KNI_QUEUE_SIZE +
591: #endif
592:     nb_lcores * nb_ports * DISPATCH_RING_SIZE),
593:     (unsigned)8192);
```

公式含义：
- `RX_QUEUE_SIZE * 队列数`：网卡 RX 描述符占用
- `MAX_PKT_BURST * lcores * ports`：突发收包缓冲
- `TX_QUEUE_SIZE * 队列数`：网卡 TX 描述符占用
- `MEMPOOL_CACHE_SIZE * lcores`：per-lcore 缓存
- `KNI_MBUF_MAX + KNI_QUEUE_SIZE`：KNI 通道占用（若启用）
- `DISPATCH_RING_SIZE * lcores * ports`：dispatch ring 占用
- 对齐到 8192

**注意：此公式是静态计算的，不考虑运行时并发连接数。** 如果 CC（并发连接数）远超公式预估，每个连接的 socket buffer、PCB、syncache 等虽然不直接从 pktmbuf_pool 分配（它们从 UMA zone 分配），但收包路径中 `ff_mbuf_gethdr()` 等辅助分配仍依赖 pktmbuf_pool。

### 5.3 ff_ipc 对 mbuf 的依赖

**ff_ipc 不依赖 pktmbuf_pool，依赖独立的 message_pool。**

证据：

| 对象 | 创建位置 | 用途 |
|------|---------|------|
| `pktmbuf_pool` | `ff_dpdk_if.c:632` `rte_pktmbuf_pool_create()` | DPDK 收发包 mbuf 池 |
| `message_pool` | `ff_dpdk_if.c:750` `rte_mempool_create(FF_MSG_POOL, ...)` | ff_ipc 消息通信池 |

`message_pool` 创建（`ff_dpdk_if.c:750-754`）：

```c
750: message_pool = rte_mempool_create(FF_MSG_POOL,
751:    MSG_RING_SIZE * 2 * nb_rings,
752:    MAX_MSG_BUF_SIZE, MSG_RING_SIZE / 2, 0,
753:    NULL, NULL, ff_msg_init, NULL,
754:    socketid, 0);
```

ff_ipc 工具端（`tools/compat/ff_ipc.c:77`）：

```c
77: message_pool = rte_mempool_lookup(FF_MSG_POOL);
```

**因此：pktmbuf_pool 耗尽不影响 ff_ipc 通信（ff_ipc 用独立的 message_pool）。** 但需注意：如果系统内存整体紧张，两个池可能都会受到影响。

### 5.4 水位检查插入点（如需 f-stack 特有方案）

如果需要实现 mbuf 池水位检查（在 mbuf 耗尽前主动丢弃新 SYN，保护已有连接），可插入点如下：

**插入点 1：`process_packets()` 入口**（`ff_dpdk_if.c:2024`）

在处理每个收到的包之前，检查 pktmbuf_pool 的可用数量。优点是粒度细（每个包都检查），缺点是检查频率高。

```c
// 伪代码（仅示意，未实际实现）
unsigned avail = rte_mempool_avail(pktmbuf_pool[socket_id]);
if (avail < THRESHOLD) {
    // 对 SYN 包执行早期丢弃
    if (is_syn_packet(data, len)) {
        rte_pktmbuf_free(rtem);
        ff_traffic.rx_dropped++;
        continue;
    }
}
```

**插入点 2：`ff_veth_input()` 入口**（`ff_dpdk_if.c:1839`）

在将 DPDK mbuf 转换为 FreeBSD mbuf 之前检查。优点是此时还知道原始 mbuf 来源，可以区分新 SYN 和已建立连接的数据包。

**插入点 3：TCP SYN 处理入口**

在 TCP 栈收到 SYN 准备分配 syncache 条目时检查 mbuf 水位。这是最精确的插入点（只影响新连接，不影响已有连接数据），但需要深入 TCP 栈内部。

**推荐方案：** 插入点 1（`process_packets` 入口），配合 SYN 包早期识别。理由：
1. 在协议栈之前，不影响已有连接
2. 粒度可控（可在 burst 级别检查而非每包检查）
3. 实现简单，对现有代码侵入最小

## 6. 总结表

| 机制 | 完整性 | 可用性 | 局限 |
|------|--------|--------|------|
| **A. maxsockets** | 完整 | **完整可用** | UMA zone max 强制执行链完整（`uma_core.c:4461`）。config.ini 通过 `[freebsd.boot]` tunable 配置 262144。无局限。 |
| **B. ipfw limit** | 完整 | **完整可用** | 工具端编译完整，内核端 O_LIMIT 处理完整，动态状态跟踪（分配/查找/插入/aging）完整非 stub。达限行为 = `IP_FW_DENY`。ff_ipfw 工具通过 ff_ipc 消息设置规则。无局限。 |
| **C. somaxconn** | 完整 | **完整可用** | backlog 截断完整，半连接队列满丢弃最老，全连接队列 `3*qlimit/2` 检查。config.ini 通过 `[freebsd.sysctl]` 运行时设置 32768。无局限。 |
| **D. syncache** | 完整 | **完整可用** | 桶满丢弃最老 + syncache_pause，zone 耗尽降级 syncookies。config.ini 配置 hashsize=4096, bucketlimit=100。无局限。 |
| **E. mbuf 水位** | 不完整 | **不可用（当前无水位检查）** | 收包路径无 `rte_mempool_avail/count` 检查。mbuf 池大小为静态公式计算，不考虑运行时 CC。但 ff_ipc 依赖独立 message_pool，mbuf 耗尽不影响 ff_ipc。插入点已定位（`process_packets` 入口）。 |

### 关键发现

1. **机制 A-D 均完整可用**，f-stack 的 FreeBSD 用户态栈保留了 FreeBSD 原生的全部 CC 限制机制，代码路径完整、强制执行链无断裂。

2. **机制 E（mbuf 水位检查）是唯一缺失项**，但这是 FreeBSD 原生也没有的机制（FreeBSD 内核依赖 mbuf 自身的 zone max 和应急分配路径），f-stack 作为用户态栈额外缺少 DPDK mbuf 池的水位预警。如需实现 f-stack 特有的 CC 保护方案，需在 `process_packets()` 入口添加水位检查。

3. **ff_ipc 不受 mbuf 耗尽影响**：ff_ipc 使用独立的 `message_pool`（`FF_MSG_POOL`），与 `pktmbuf_pool` 是不同的 mempool。即使 mbuf 池耗尽，ff_ipc 工具（如 `ff_ipc netstat`）仍可正常通信（除非 message_pool 也耗尽）。

4. **config.ini 配置路径正确**：
   - maxsockets 和 syncache hashsize/bucketlimit 作为 **boot tunable**（`[freebsd.boot]` 段），经 `kern_setenv` → kenv → `TUNABLE_INT_FETCH` 加载，在 SYSINIT 阶段生效。
   - somaxconn 作为 **运行时 sysctl**（`[freebsd.sysctl]` 段），经 `kernel_sysctlbyname` 在启动后设置。
