# F-Stack LRO/TSO 性能基线方案（中文）

> 文档层级：性能基线方案（M4 阶段产出之二）
> 设计依据：`01-需求规格.md`（动机与价值：LRO 降收包 CPU、TSO 降发包 CPU）、`04-方案与架构设计.md`（诚实边界清单）、`07-测试与验收规格.md`（零回归红线、诚实边界分层）。
> 权威版本：DPDK `dpdk-stable-24.11.6`、FreeBSD 15.0 移植。
> 铁律：本轮为**纯文档阶段**（不写代码、不改 lib、不提交、不实测）。本文定义"后续实现阶段（CM6）"性能基线如何采集与判读；**不预设 offload 一定更快，报实际结果**。所有 file:line 附代码坐实位置，编码时以最新代码为准。

## 一、目标与判读原则

1. **零回归优先**：首要目标是证明 `lro=0` / `tso=0`（默认关闭）相对"引入 LRO/TSO 特性之前的现状"**无可测性能回归**（吞吐、CPU、延迟、内存均不劣化）。这是硬红线，优先于任何"开启更快"的诉求。
2. **不预设结论、报实际结果**：LRO/TSO 开启是否更快取决于本机 PMD（virtio）实际能力、流量特征、CPU 主频等。**不假设 offload 必然提升性能**；采集到什么报什么，允许出现"开启无明显提升"甚至"轻微下降"的诚实结果，并分析原因。
3. **可测项 vs 不可测项分层**：硬件 LRO 端到端性能强依赖 virtio 是否宣告并执行 LRO（04 文档诚实边界 1、07 文档第五节 HB-1）。本机 virtio 不支持时，LRO 端到端聚合性能属**不可测项**，须显式标注，不得以"代码路径通过"冒充性能收益。
4. **方法可复现**：固定所有变量（lcore、文件/流大小、并发、时长、预热），多轮取中位数并报离散度，保证结论可被独立复现。

## 三、测试矩阵

> 完整矩阵：`{lro∈{0,1}} × {tso∈{0,1}} × {IPv4,IPv6}`，每格采集 4 类指标。为聚焦，按主线拆分：LRO 主看收方向、TSO 主看发方向。

### 3.1 指标定义（每格采集）

| 指标 | 定义 | 采集 |
| --- | --- | --- |
| 吞吐 | 稳态 Gbps（或 pps） | iperf3 `bits_per_second` / xstats pps |
| 延迟 P50/P99 | 请求-响应型负载的延迟分位（如 `iperf3 --udp` 或额外 ping/req-resp 探测） | 分位统计脚本 |
| CPU 每包/每字节 | f-stack 轮询核 CPU% ÷ (pps 或 Bps) | mpstat + xstats |
| mbuf 内存 | mbuf pool 在用/峰值（LRO 大段占用多个 mbuf） | DPDK mempool 统计 |

### 3.2 LRO 收包性能矩阵

| 用例 | 配置 | 负载 | 主观测 | 判读 |
| --- | --- | --- | --- | --- |
| PB-LRO-01 | `lro=0`（基线） | 大流量 TCP 收（`f-stack-client` → `9.134.214.176`，大文件/长流 iperf3） | 吞吐、收包核 CPU、rx pps、平均段大小(=MTU) | 基线 |
| PB-LRO-02 | `lro=1` | 同上 | 同上，对比 CPU/pps/段大小 | LRO 生效时应 rx pps 下降、平均段大小 > MTU、每字节 CPU 下降；**若 virtio 不支持则与 PB-LRO-01 无差（诚实记录）** |
| PB-LRO-03 | `lro=1` IPv6 | IPv6 大流量收 | 同上 | 同 PB-LRO-02，v6 单列 |

**LRO 性能核心观测量**：`平均收段大小 = 应用层收字节 ÷ rx_packets`。LRO 真正生效时该值应显著大于链路 MTU（合并多个报文成一段）；rx_packets 相应减少 → 协议栈 per-packet 处理次数下降 → 收包核 CPU（尤其每字节 CPU）下降。这是判断"LRO 端到端是否生效"的量化依据（对齐 07 文档 HB-1/HB-3）。

### 3.3 TSO 发包性能矩阵

| 用例 | 配置 | 负载 | 主观测 | 判读 |
| --- | --- | --- | --- | --- |
| PB-TSO-01 | `tso=0`（基线） | 大 TCP 段发（f-stack 作服务端被 `f-stack-client` 拉大文件） | 吞吐、发包核 CPU、tx pps、软件分段数 | 基线 |
| PB-TSO-02 | `tso=1` | 同上（IPv4） | 同上，对比 CPU/分段路径 | TSO 生效时发包侧 per-segment 协议栈开销下降、发包核 CPU 下降；报实际 |
| PB-TSO-03 | `tso=1` IPv6 | IPv6 大 TCP 段发 | 同上 + **对端校验和正确性**（关联 07 IT-TSO-21） | 验证 v6 TSO 修复后性能与正确性；本项目 TSO 核心 |

**TSO 性能核心观测量**：发包侧 `tcp_output` 分段次数与发包核 CPU。TSO 生效时协议栈交付大段、由 PMD/网卡分段，发包核每字节 CPU 应下降。若本机 virtio 不宣告 TX TSO（07 IT-START-03 显示 "TSO is not supported"），则实际走软件分段，PB-TSO-02/03 主要验证"lib 改动不劣化软件分段路径"，须标注端到端硬件 TSO 为不可测项。

### 3.4 组合与交互

| 用例 | 配置 | 目的 |
| --- | --- | --- |
| PB-MIX-01 | `lro=1,tso=1` | 收发双向同时开启，验证互不劣化、资源（mbuf/CPU）无异常 |
| PB-JUMBO-01 | `tso=1 + mtu_enable`（jumbo） | TSO 与 jumbo 组合下吞吐/段长（关联 04 文档 2.3 if_hw_tsomax、07 IT-TSO-23） |

## 四、测试方法（可复现规程）

> 每个矩阵格按下列规程执行，保证跨轮次可比。

1. **固定变量**（每轮一致，记录到结果表）：
   - lcore 绑定与数量（`lcore_mask`）、队列数、RSS 配置；
   - 负载：文件大小 / iperf3 流大小、并发连接数 `-P`、时长 `-t`（建议 ≥30s 稳态）；
   - MTU / jumbo 设置；预热时长（丢弃前 N 秒，取稳态窗口）。
2. **预热**：正式采集前预热（如 10s），排除冷启动/缓存/连接建立抖动。
3. **多轮取中位数 + 离散度**：每格**≥5 轮**，报**中位数**为主指标，同时报 min/max 或标准差/变异系数（CV），CV 过大（如 >10%）须复测或说明原因。
4. **零回归判定**：`lro=0`/`tso=0` 组相对"特性引入前基线"（CM0 记录的基线 commit 编译产物同口径跑一次）差异须落在测量噪声内（建议阈值：中位数差异 ≤ 测量 CV，且无系统性单向偏移）。超阈值即视为回归 → 打回对应 CM（07 文档 bounce≤3）。
5. **开启态判读**：开启组与基线组对比，报实际差异（提升/持平/下降）并给因果分析（结合 dev_info 能力、段大小、pps、CPU 分解）。
6. **证据留档**：每格保存 iperf3 JSON、xstats dump、mpstat 采样、netstat 前后差、config 快照（去除本地敏感值），路径写入结果表。

**结果表模板**（每格一行）：
```
用例  配置  轮数  吞吐(中位/CV)  P50/P99  每字节CPU  平均段大小  mbuf峰值  证据路径  判读
```

## 五、基线要求与验收

| 编号 | 要求 | 判据 |
| --- | --- | --- |
| PBA-01 | `lro=0` 相对现状无可测回归 | PB-LRO-01 各指标与基线差异 ≤ 噪声（第四节 4） |
| PBA-02 | `tso=0` 相对现状无可测回归 | PB-TSO-01 同上 |
| PBA-03 | `lro=1` 结果如实记录 | PB-LRO-02/03 报实际差异 + 因果分析（不预设提升） |
| PBA-04 | `tso=1` 结果如实记录 + v6 正确 | PB-TSO-02/03 报实际 + IT-TSO-21 校验和正确 |
| PBA-05 | 组合/jumbo 无资源异常 | PB-MIX-01 / PB-JUMBO-01 无 mbuf 耗尽/无吞吐塌陷 |
| PBA-06 | 诚实边界分层 | 不可测项（virtio 不支持 LRO/TSO 硬件）显式标注，附 dev_info 证据 |

**关键要求（重申）**：**不预设 offload 一定更快**。PBA-03/PBA-04 的通过标准是"如实记录 + 有因果分析"，而非"必须提升"。零回归（PBA-01/02）才是硬门禁。

## 六、诚实边界（本机 virtio 能力限制）

> 对齐 04 文档诚实边界清单与 07 文档第五节 HB 分层，明确本机环境下性能基线的可测项与不可测项。

| 项 | 可测（有意义的性能数据） | 不可测 / 受限（须标注） | 关联 |
| --- | --- | --- | --- |
| LRO 端到端聚合性能 | 仅当 CM0 `dev_info` 显示 virtio 宣告 `RTE_ETH_RX_OFFLOAD_TCP_LRO` 且实际聚合（段大小 > MTU） | virtio 不宣告 LRO 时，PB-LRO-02/03 与基线无差异，**LRO 性能收益不可测**（非"无收益"，而是"本环境无法验证"） | 07 HB-1/HB-3 |
| TSO 端到端硬件加速 | 仅当 virtio 宣告 `RTE_ETH_TX_OFFLOAD_TCP_TSO` 且硬件分段 | 不宣告时走软件分段，硬件 TSO 加速**不可测**；仍可测"lib 改动不劣化软件路径" | 07 HB-5、IT-START-03 |
| max_lro_pkt_size 上限对内存的影响 | 可测 mbuf 峰值随 max_lro_pkt_size 变化 | 精确最优值依 PMD/data_room（运行时校准） | 07 HB-2 |
| 多进程 per-queue 聚合性能 | 单进程可测 | 多进程 per-queue LRO 聚合行为 | 07 HB-7 |
| IPv6 扩展头场景 | 无扩展头可测 | 含扩展头（本轮不实现） | 07 HB-4 |

**记录模板**（每不可测项须填）：`{项} 本机 dev_info=<capa 位实测> 结论=<可测并给数据 | 不可测（原因）> 证据=<路径>`。禁止把"本环境不可测"写成"无性能收益"或"性能通过"。
