# F-Stack LRO/TSO 里程碑与工作清单（中文）

> 文档层级：里程碑与工作清单（M3 阶段产出之三）
> 设计依据：`04-方案与架构设计.md`、`05-接口与配置设计.md`。
> 用途：把方案分解为**可执行、可门禁、可回滚**的编码里程碑，供后续实现阶段直接对照。
> 铁律：本轮为文档阶段，以下里程碑为**后续实现阶段**的规划，本轮不执行。编码阶段强制遵循：改代码先 `make clean` 再完整编译、lib 最小注释、commit message 英文 1-3 句、config.ini 本地测试值不入库、rm/kill/chmod 走脚本。

---

## 一、里程碑总览与依赖关系

```
CM0 (基线冻结/环境)
  └─> CM1 (config/结构/解析: lro 开关)         [LRO 主线]
        └─> CM2 (LRO DPDK 使能 + max_lro_pkt_size + 收包路径)
              └─> CM3 (IFCAP_LRO + 协议栈接收验证)
CM1 独立于 ──> CM4 (TSO IPv6 分流 + IP_CKSUM 自洽 + CSUM_IP6_TSO)   [TSO 主线]
                └─> CM5 (if_hw_tsomax 上限 + 双份逻辑收敛 + 组合约束)
CM3 + CM5 ──> CM6 (单测/集成/性能基线测试)
                └─> CM7 (spec 审核门禁 + 提交)
```

- **LRO 主线**：CM1 → CM2 → CM3（逐层打通，强顺序依赖）。
- **TSO 主线**：CM4 → CM5（可与 LRO 主线并行，仅共享 CM1 的 config 基建部分）。
- **汇合**：CM6 测试依赖 LRO+TSO 均完成；CM7 门禁在最后。

## 二、里程碑明细

### CM0：基线冻结与环境准备

- **工作项**：
  1. 记录当前 lib/ 相关文件 git 基线 commit，作为回滚锚点。
  2. 确认 clean build 基线通过（`make clean` → `make`），记录编译产物基线。
  3. 确认测试环境：DPDK 独占网卡 IP `9.134.214.176`（`ssh f-stack-client` 侧发起测试），内核栈测 `127.0.0.1` 的 `lo`。
  4. 运行时读 `dev_info` 确认本机 PMD（virtio）的 `rx_offload_capa`/`tx_offload_capa`/`max_lro_pkt_size` 实际宣告值（回填 04 文档诚实边界清单）。
- **DoD**：基线 commit 记录、clean build 通过、`dev_info` offload 能力表落档。
- **门禁**：clean build PASS。
- **回滚点**：基线 commit。

### CM1：config / 结构 / 解析（LRO 开关基建）

- **工作项**（对应 05 文档一/二/三）：
  1. `config.ini`：新增 `lro=0`（注释形式，入库默认 0）。
  2. `ff_config.h`：dpdk 结构 `int tso;` 后加 `int lro;`（L295 后）。`rx_lro`（L114）已存在不动。
  3. `ff_config.c`：`MATCH("dpdk","tso")` 后加 `MATCH("dpdk","lro")` 解析分支；确认/设置默认 `lro=0`（坐实 tso 默认赋值处对齐）。
- **DoD**：clean build 通过；`lro=0` 时行为与现状一致；`lro=1` 能被解析进 `dpdk.lro`。
- **门禁**：clean build PASS；单测覆盖解析（CM6 补）；默认关闭零回归静态复核。
- **回滚点**：CM1 提交前 commit。
- **提交建议（英文）**：`Add dpdk.lro config option (default off) for LRO support.`

### CM2：LRO DPDK 使能 + max_lro_pkt_size + 收包路径

- **工作项**（对应 04 文档 1.2/1.3/1.4，05 文档四）：
  1. `ff_dpdk_if.c:891-898`：删 `#if 0`，改宏 `RTE_ETH_RX_OFFLOAD_TCP_LRO`，挂 `if (dpdk.lro)` 门控，按 capa 探测置 offloads + `rx_lro=1`，三态日志。
  2. 同块设 `port_conf.rxmode.max_lro_pkt_size`（优先 `dev_info.max_lro_pkt_size`，`>= mtu`）。
  3. `ff_veth_input`（`ff_dpdk_if.c:1694-1742`）：复核 LRO 大段经 `pkt_len` + 多段遍历的搬运正确性；`RTE_MBUF_F_RX_LRO` 感知列为可选增强（首版可不改，仅依赖长度搬运）。
- **DoD**：clean build 通过；`lro=1` 且 PMD 支持时 offloads 含 LRO 位、`max_lro_pkt_size` 已设；`lro=0` 零回归。
- **门禁**：clean build PASS；运行时（CM6）验证 offloads 位实际生效、聚合段能进收包路径。
- **回滚点**：CM2 提交前 commit。
- **提交建议**：`Enable hardware LRO offload with max_lro_pkt_size on rx path.`

### CM3：IFCAP_LRO + 协议栈接收

- **工作项**（对应 04 文档 1.5，05 文档 5.1）：
  1. `ff_veth.c:941-956`：`if (rx_lro)` 时 `if_setcapabilitiesbit(ifp, IFCAP_LRO, 0)`。
  2. 运行时验证 LRO 大段经 `IFCAP_LRO` 后被 FreeBSD 协议栈正确接收（02 文档 1.5 主风险点）。
- **DoD**：clean build 通过；`lro=1` 时接口声明 IFCAP_LRO；LRO 段被协议栈接收（运行时）。
- **门禁**：clean build PASS；运行时 LRO 端到端收包正确（TCP 大流量下无丢包/无异常，CPU 改善为加分项）。
- **回滚点**：CM3 提交前 commit。
- **提交建议**：`Declare IFCAP_LRO capability so stack accepts LRO segments.`

### CM4：TSO IPv6 分流 + IP_CKSUM 自洽 + CSUM_IP6_TSO

- **工作项**（对应 04 文档 2.1/2.2/2.6，05 文档 4.3/5.3）：
  1. 坐实 `CSUM_IP6_TSO` 与 `CSUM_TSO` 宏位关系（编码阶段第一项），据此决定 `ff_veth.c:304-306` 是否扩展识别 `CSUM_IP6_TSO`。
  2. `ff_dpdk_if.c:2455-2465`：TSO 分支按 `iph->version` 分流——IPv4 用 `rte_ipv4_phdr_cksum` + `RTE_MBUF_F_TX_IP_CKSUM` + `l3_len=iph_len`；IPv6 用 `rte_ipv6_phdr_cksum` + `RTE_MBUF_F_TX_IPV6`（无 IP_CKSUM）+ `l3_len=40`。分支内自洽填 l2_len/TCP_SEG/l4_len/tso_segsz。
  3. `ff_memory.c:358-368`：同步同样修改（或先临时同步，CM5 收敛）。
- **DoD**：clean build 通过；IPv4 TSO 行为不变；IPv6 TSO 伪头/l3_len/标记正确（静态 + 运行时）。
- **门禁**：clean build PASS；`tso=0` 零回归；IPv4/IPv6 TSO 运行时对端校验和正确（CM6）。
- **回滚点**：CM4 提交前 commit。
- **提交建议**：`Fix IPv6 TSO offload: split by IP version, use ipv6 pseudo-header cksum.`

### CM5：if_hw_tsomax 上限 + 双份逻辑收敛 + 组合约束

- **工作项**（对应 04 文档 2.3/2.4/2.5，05 文档 5.2/4.4）：
  1. 坐实 `if_sethwtsomax*` 确切 API（FreeBSD 15.0 `if.h`/`if_var.h`），在 `ff_veth.c:951-953` TSO 块设三项非 0 上限（保守默认，运行时校准）。
  2. 双份逻辑收敛：优先抽取 `ff_fill_tx_offload` 公共函数（方案 A），`ff_dpdk_if.c` 与 `ff_memory.c` 两调用点改为调用；若跨编译单元复杂退方案 B（同步 + 交叉引用注释）。
  3. 组合约束：TSO 使能处（`ff_dpdk_if.c:931`）对 `tso=1 && tx_csum_offoad_skip=1` 记 WARN 日志（不强改行为）。
- **DoD**：clean build 通过；tsomax 三项非 0；收敛后单一逻辑源；组合不一致有 WARN。
- **门禁**：clean build PASS；收敛前后 IPv4/IPv6 TSO 行为等价（CM6 回归）。
- **回滚点**：CM5 提交前 commit（收敛重构风险高，单独 commit 便于回滚）。
- **提交建议**：`Set if_hw_tsomax limits and consolidate duplicated tx offload logic.`

### CM6：单测 / 集成 / 性能基线测试

- **工作项**：
  1. **单测**（Unity 框架，参考 `c-unittest-expert` 技能）：config 解析（lro 项）、`ff_mbuf_tx_offload` v4/v6 TSO 映射、offload 填充函数 version 分流。
  2. **集成**：`lro=0/tso=0` 零回归对照；`tso=1` IPv4/IPv6 TCP 大段分段发送（`ssh f-stack-client` 抓包验证对端校验和）；`lro=1` TCP 大流量收包聚合验证（`dev_info` 支持前提）。
  3. **性能基线**：LRO 开/关的收包 CPU/吞吐对比；TSO 开/关的发包 CPU/吞吐对比（待运行时环境）。
- **DoD**：单测全绿；零回归对照逐字节一致；v4/v6 TSO 对端校验和正确；LRO 端到端无异常。
- **门禁**：单测 PASS + 集成关键用例 PASS；性能不劣化（改善为加分）。
- **回滚点**：测试不涉及产品代码回滚（若发现 bug 打回对应 CM）。

### CM7：spec 审核门禁 + 提交

- **工作项**：
  1. 由**独立审核 agent**（非编码 agent）对 CM1-CM6 产出做门禁审核（代码 vs spec 一致性、file:line 可复核、零回归验证、诚实边界闭环）。
  2. config.ini review：确认只含 `lro=0` 特性改动，无本地测试值残留（`git diff` 逐项）。
  3. 分里程碑提交（英文 commit message 1-3 句）。
- **DoD**：门禁全 PASS；config.ini 无本地残留；提交完成。
- **门禁**：审核 agent 签署 PASS；bounce≤3（失败打回对应 CM 修复，超 3 次转人工）。

## 三、门禁与回滚机制（贯穿全里程碑）

- **每里程碑门禁**：clean build PASS 为硬门禁（先 `make clean` 再编译，禁增量）；功能门禁按各 CM 的 DoD。
- **回滚点**：每 CM 提交前打 commit 锚点，门禁失败可回滚到上一 CM。
- **bounce 规约**：任一门禁失败必须打回上一步修复，同一步骤打回不超过 3 次，超 3 次转人工决策（不搁置、不带病放行）。
- **角色分离**：编码（CM1-CM5）与审核（CM7）必须不同 agent。

## 四、编码规约清单（实现阶段强制）

| 规约 | 要求 |
| --- | --- |
| 编译 | 改代码先 `make clean` 再完整编译，禁增量编译作为通过依据 |
| 注释 | lib 最小注释，仅契约/不直观处；禁自解释代码加注释 |
| config.ini | 只提交 `lro=0` 特性改动，本地测试值（lcore_mask/vlan_filter/portN IP 等）提交前回滚；`git add` 前 review `git diff` |
| commit message | 英文，1-3 句，描述特性改动 |
| rm/kill/chmod | 走 `rm_tmp_file.sh` / `kill_process.sh` / `chmod_modify.sh`，禁直接调用 |
| 宏名 | LRO 宏用 `RTE_ETH_RX_OFFLOAD_TCP_LRO`（禁旧宏 `DEV_RX_OFFLOAD_TCP_LRO`） |
| 默认关闭 | `lro=0`/`tso=0` 零回归为红线，任何改动不得破坏默认路径 |
