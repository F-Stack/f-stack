# F-Stack LRO/TSO 里程碑与工作清单（中文）

> 文档层级：里程碑与工作清单（M3 阶段产出之三）
> 设计依据：`04-方案与架构设计.md`、`05-接口与配置设计.md`。
> 用途：把方案分解为**可执行、可门禁、可回滚**的编码里程碑，供后续实现阶段直接对照。

## 一、里程碑总览与依赖关系

```
CM0 (基线冻结/环境)
  └─> CM1 (config/结构/解析: lro 开关)         [LRO 主线]
        └─> CM2 (LRO DPDK 使能 + max_lro_pkt_size + 收包路径)
              └─> CM3 (IFCAP_LRO + 协议栈接收验证)
CM1 独立于 ──> CM4 (TSO IPv6 分流 + IP_CKSUM 自洽 + CSUM_IP6_TSO)   [TSO 主线]
                └─> CM5 (if_hw_tsomax 上限 + 双份逻辑收敛 + 组合约束)
CM3 + CM5 ──> CM6 (单测/集成/性能基线测试)
                └─> CM7 (spec 审核门禁 + 提交)
```

- **LRO 主线**：CM1 → CM2 → CM3（逐层打通，强顺序依赖）。
- **TSO 主线**：CM4 → CM5（可与 LRO 主线并行，仅共享 CM1 的 config 基建部分）。
- **汇合**：CM6 测试依赖 LRO+TSO 均完成；CM7 门禁在最后。

## 三、门禁与回滚机制（贯穿全里程碑）

- **每里程碑门禁**：clean build PASS 为硬门禁（先 `make clean` 再编译，禁增量）；功能门禁按各 CM 的 DoD。
- **回滚点**：每 CM 提交前打 commit 锚点，门禁失败可回滚到上一 CM。
- **bounce 规约**：任一门禁失败必须打回上一步修复，同一步骤打回不超过 3 次，超 3 次转人工决策（不搁置、不带病放行）。
- **角色分离**：编码（CM1-CM5）与审核（CM7）必须不同 agent。

## 四、编码规约清单（实现阶段强制）

| 规约 | 要求 |
| --- | --- |
| 编译 | 改代码先 `make clean` 再完整编译，禁增量编译作为通过依据 |
| 注释 | lib 最小注释，仅契约/不直观处；禁自解释代码加注释 |
| config.ini | 只提交 `lro=0` 特性改动，本地测试值（lcore_mask/vlan_filter/portN IP 等）提交前回滚；`git add` 前 review `git diff` |
| commit message | 英文，1-3 句，描述特性改动 |
| rm/kill/chmod | 走 `rm_tmp_file.sh` / `kill_process.sh` / `chmod_modify.sh`，禁直接调用 |
| 宏名 | LRO 宏用 `RTE_ETH_RX_OFFLOAD_TCP_LRO`（禁旧宏 `DEV_RX_OFFLOAD_TCP_LRO`） |
| 默认关闭 | `lro=0`/`tso=0` 零回归为红线，任何改动不得破坏默认路径 |

## 六、软件 LRO 编码里程碑（第二轮补充）

> 依据 `11-软件LRO方案.md`、`13-软硬offload对接方案.md`。软件 TSO 无编码（`12` 文档：协议栈 MSS 分段固有）。以下里程碑为**后续实现阶段**规划，本轮仅文档。上一轮硬件 offload（CM0-CM7）已完成并提交，软件 LRO 里程碑接续编号 SM。

### 依赖关系

```
（硬件 offload CM1-CM7 已完成）
  └─> SM1 (sw_lro 字段/推导: ff_hw_features 加 sw_lro + 探测块互斥推导)
        └─> SM2 (软件 LRO 接入 ff_veth_input: per-lcore lro_ctrl + tcp_lro_init/rx/flush_inactive/free)
              └─> SM3 (IFCAP_LRO 条件扩展 rx_lro||sw_lro + 1261 NULL 裸调规避验证)
                    └─> SM4 (单测/集成/性能 + 软硬互斥验证)
                          └─> SM5 (独立门禁 + 提交)
```

### SM1：sw_lro 字段与推导

- **工作项**：
  1. `ff_config.h:112-118`：`ff_hw_features` 新增 `uint8_t sw_lro;`（与 `rx_lro` 并列，`13` 文档 3.3 决策）。
  2. `ff_dpdk_if.c` LRO 探测块：按 `13` 文档 2.2 推导——`lro=1 && PMD 支持`→`rx_lro=1,sw_lro=0`；`lro=1 && !支持`→`rx_lro=0,sw_lro=1`；`lro=0`→均 0。三态日志（hardware/fallback software/disabled）。
- **DoD**：clean build 通过；互斥不变量 `rx_lro & sw_lro == 0` 恒成立；`lro=0` 零回归。
- **提交建议**：`Add sw_lro fallback flag with hardware-first LRO selection.`

### SM2：软件 LRO 接入 ff_veth_input

- **工作项**（`11` 文档 2 节）：
  1. per-lcore/per-port 上下文新增 `struct lro_ctrl lro`；端口/lcore 初始化路径 `tcp_lro_init(&lro)` 绑 `lro.ifp=ctx->ifp`（经典模式），仅 `sw_lro` 时。
  2. `ff_veth_input`（`ff_dpdk_if.c:1720` 之后）：`if(ctx->hw_features.sw_lro) { if(tcp_lro_rx(&lro,hdr,0)==0) return; }` 否则原路径上送。
  3. 收包批处理末：`tcp_lro_flush_inactive`（**不用** `tcp_lro_flush_all`，规避 `tcp_lro.c:1261` NULL 裸调）。
  4. 端口/lcore 清理：`tcp_lro_free(&lro)`。
- **DoD**：clean build 通过；`sw_lro=1` 时软件聚合生效、无 1261 NULL 崩溃；`sw_lro=0` 时收包路径零回归。
- **提交建议**：`Wire software LRO into rx path using classic tcp_lro_rx mode.`

### SM3：IFCAP_LRO 条件扩展 + 1261 规避验证

- **工作项**：
  1. `ff_veth.c:945-947`：`IFCAP_LRO` 条件从 `rx_lro` 扩展为 `rx_lro || sw_lro`（`13` 文档 3.3）。
  2. 坐实 `tcp_lro_flush_tcphpts`（`tcp_lro.h:220`）在 F-Stack 是否 NULL（若是，经典 flush 走 `tcp_lro_condense` 完全安全，`11` 文档 3.2）；确认经典模式路径不触碰 `tcp_lro.c:1261`。
- **DoD**：clean build 通过；软件 LRO 时接口声明 IFCAP_LRO；经典模式路径静态确认不含 1261 裸调。
- **提交建议**：`Extend IFCAP_LRO to cover software LRO fallback.`

### SM4：测试（单测/集成/性能）

- **工作项**（`07` 文档八、`08` 文档八）：UT-SWLRO-01/02/03（推导/互斥/IFCAP）；IT-SWLRO-10/11/12（本机 virtio 软件回退+聚合+无崩溃）；性能 lro on/off 对比。
