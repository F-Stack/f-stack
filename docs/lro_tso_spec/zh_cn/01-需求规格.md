# F-Stack LRO/TSO 需求规格说明书（中文）

> 文档层级：需求规格（M1 阶段产出之一）
> 适用范围：/data/workspace/f-stack/ 用户态协议栈（DPDK 24.11.6 + FreeBSD 15.0 内核栈移植）
> 说明：本轮为**纯 spec 文档阶段**，只做设计与现状坐实，不写代码、不改 lib、不提交。所有论断均附精确 `file:line`，与 plan mode 预读结论不一致处以实际代码为准并标注纠正。

## 1. 背景

### 1.1 LRO（Large Receive Offload，大接收卸载）

LRO 是网卡/驱动侧的收包卸载技术：网卡将同一 TCP 流的多个连续小报文在进入协议栈前合并成一个大 mbuf 段上送，从而减少协议栈按包处理次数（per-packet overhead），显著降低高吞吐场景下的 CPU 占用。

F-Stack 现状（详见 02 文档）：

- **LRO 当前完全未启用**。DPDK 侧的 LRO 使能代码被 `#if 0` 包裹（`lib/ff_dpdk_if.c:891-898`），且其中使用的宏 `DEV_RX_OFFLOAD_TCP_LRO` 在 DPDK 24.11.6 中**已不存在**（仅存 `RTE_ETH_RX_OFFLOAD_TCP_LRO`），即使去掉 `#if 0` 也会编译失败。
- `struct ff_hw_features` 中**已存在** `uint8_t rx_lro;` 字段（`lib/ff_config.h:114`），但全流程无任何赋值/消费点（config 无解析项、ifnet 无 `IFCAP_LRO`、收包路径无 LRO 感知逻辑）。
- 因此 LRO 属于**从配置到协议栈完全未打通**的空能力，本轮按"全新开发完整支持、采用硬件 LRO / DPDK offload 路径"实施。

**动机与价值**：在大流量 TCP 收包（如反向代理、下载服务）场景下，硬件 LRO 可成倍降低协议栈 CPU，提升单核吞吐；F-Stack 作为高性能用户态栈，补齐 LRO 能力对标内核栈/商用栈是重要竞争力补强。

### 1.2 TSO（TCP Segmentation Offload，TCP 分段卸载）

TSO 是发包侧卸载：协议栈把一个超过 MSS 的大 TCP 段交给网卡，由网卡按 MSS 切分成多个符合链路 MTU 的报文并各自填好 IP/TCP 头与校验和，减少发包侧 per-segment 的协议栈开销。

F-Stack 现状（详见 02 文档）：

- **TSO 已基本支持**：config 项 `tso`（`config.ini:22`、`ff_config.c:1054-1055`）、能力探测与 rxmode/txmode 使能（`ff_dpdk_if.c:931-942`，宏 `RTE_ETH_TX_OFFLOAD_TCP_TSO`）、ifnet 侧 `IFCAP_TSO`+`CSUM_TSO`（`ff_veth.c:951-954`）、offload 字段填充（`ff_dpdk_if.c:2455-2465` 与 `ff_memory.c:358-368`）均已存在。
- 但存在**若干可完善点**（详见 02 文档差距表）：IPv6 TSO 路径缺失（下游只按 IPv4 `rte_ipv4_phdr_cksum` 处理）、`if_hw_tsomax` 系列上限在 lib 侧从未设置、两处 offload 填充逻辑重复且都以 IPv4 为前提等。

**动机与价值**：完善 TSO 使其在 IPv6、jumbo/MTU、多段（scatter）等组合场景下正确且健壮，避免默认关闭之外一旦开启即出现 IPv6 发包异常等隐患。

### 1.3 LRO/TSO 与既有 MTU 特性的关系

LRO/TSO 与此前已完成的 MTU 巨帧项目（jumbo frame / offload 上下文，含 IPv6 分片修复 commit `0f25ac495`、KNI/MTU 互斥解除 `989f1d2da`）强相关：LRO 合并后的大段、TSO 前的大段都与 jumbo mbuf、`mtu_enable`、多段 mbuf（`MULTI_SEGS`）处理路径交织，设计时须一并考虑其交互。

## 2. 目标

### 2.1 LRO 目标（全新支持）

打通 LRO 从配置到协议栈的**完整通路**，具体分层目标：

1. **配置层**：新增 `dpdk.lro` 配置项（`config.ini` + `ff_config.c` 解析），默认关闭（`lro=0`），语义与 `tso` 对称。
2. **能力探测层**：修正 `ff_dpdk_if.c` 中被 `#if 0` 的 LRO 代码，改用 DPDK 24.11.6 正确宏 `RTE_ETH_RX_OFFLOAD_TCP_LRO`，按 `dev_info.rx_offload_capa` 探测并置 `pconf->hw_features.rx_lro`。
3. **rxmode 使能层**：当 `dpdk.lro` 开启且 PMD 支持时，向 `port_conf.rxmode.offloads` 置 `RTE_ETH_RX_OFFLOAD_TCP_LRO`，并按需配置 `max_lro_pkt_size`。
4. **收包路径层**：`ff_veth_input`/`ff_mbuf_gethdr`/`ff_veth_process_packet` 正确处理硬件 LRO 上送的大段 mbuf（`nb_segs`、`pkt_len`、csum 标记、`RTE_MBUF_F_RX_LRO` 标记的透传）。
5. **协议栈/ifnet 层**：ifnet 侧设置 `IFCAP_LRO` 能力位，使 FreeBSD 协议栈感知并正确接收 LRO 合并段。
6. **默认关闭零回归**：`lro=0`（默认）时行为与现状完全一致，不引入任何回归。

### 2.2 TSO 目标（完善）

在不破坏现有 IPv4 TSO 的前提下补齐完善点：

1. **IPv6 TSO 支持**：下游 offload 填充区分 IPv4/IPv6，IPv6 使用 `rte_ipv6_phdr_cksum` 并正确设置 `l3_len`/`RTE_MBUF_F_TX_IPV6`/`RTE_MBUF_F_TX_TCP_SEG`。
2. **offload 字段完整性**：确保 TSO 路径完整填充 `l2_len`+`l3_len`+`l4_len`+`tso_segsz` 与 `RTE_MBUF_F_TX_TCP_SEG`（及 IPv4 的 `RTE_MBUF_F_TX_IP_CKSUM`）。
3. **tsomax 上限设置**：评估并按需在 ifnet 侧设置 `if_hw_tsomax`/`if_hw_tsomaxsegcount`/`if_hw_tsomaxsegsize`，使 FreeBSD `tcp_output` 分段决策与 PMD 实际能力/jumbo 上限匹配。
4. **重复逻辑收敛**：`ff_dpdk_if.c` 与 `ff_memory.c` 两处近乎重复的 offload 填充逻辑评估是否可收敛，降低维护分叉风险。
5. **组合正确性**：TSO 与 checksum offload、`tx_csum_offoad_skip`、scatter/`MULTI_SEGS`、`mtu_enable`（jumbo）组合场景的正确性验证。

### 3.2 本轮范围外（Out of Scope）

- **不写任何代码、不改 lib、不提交**（纯文档阶段）。
- **不做运行时实测**：本轮 spec 只做设计；硬件 LRO 强依赖具体 PMD 能力（virtio / ixgbe / i40e / mlx5 等各不相同），凡涉及 PMD 实际行为的结论一律标注"**待运行时验证**"。
- **不改动 FreeBSD 通用协议栈语义**：LRO/TSO 的协议栈侧接收/分段逻辑沿用 FreeBSD 15.0 原生语义，仅做 F-Stack 移植层（lib/）的适配对接。
- 软件 LRO（`tcp_lro.c` 的软件合并路径）非本轮首选；本轮聚焦**硬件 LRO / DPDK offload 路径**（`tcp_lro.c` 已在 `lib/Makefile:513` 编译，但当前无 F-Stack 调用点，是否启用软件 LRO 作为补充留作后续评估）。

### 3.3 依赖与假设

- DPDK 版本以 **24.11.6** 为准（`/data/workspace/dpdk-stable-24.11.6/`），offload 宏名以该版本 `lib/ethdev/rte_ethdev.h` 为唯一权威。
- FreeBSD 内核栈以移植到 `f-stack/freebsd/` 的 15.0 版本为准。
- 网络测试环境：DPDK 独占网卡 IP `9.134.214.176`（需 `ssh f-stack-client` 侧发起测试），内核栈测试走 `127.0.0.1` 的 `lo`（本轮不实测，仅记录以备后续里程碑）。

## 5. 术语表

| 术语 | 全称 / 含义 |
| --- | --- |
| **LRO** | Large Receive Offload，网卡/驱动侧将同流多个 TCP 报文合并为大段上送，降低收包侧协议栈开销 |
| **TSO** | TCP Segmentation Offload，协议栈交付大 TCP 段由网卡按 MSS 切分发送，降低发包侧开销 |
| **GRO** | Generic Receive Offload，软件侧的通用收包合并（DPDK 亦有 `rte_gro`）；与硬件 LRO 目的相近、路径不同 |
| **offload** | 卸载，将协议处理（校验和/分段/合并等）下放到网卡硬件执行 |
| **rxmode.offloads / txmode.offloads** | DPDK `struct rte_eth_conf` 中收/发方向 offload 使能位掩码字段 |
| **rx_offload_capa / tx_offload_capa** | DPDK `dev_info` 中 PMD 宣告的收/发 offload 能力位掩码 |
| **RTE_ETH_RX_OFFLOAD_TCP_LRO** | DPDK 24.11.6 中 LRO 收卸载能力宏（`= RTE_BIT64(4)`，`rte_ethdev.h:1556`）；**旧名 `DEV_RX_OFFLOAD_TCP_LRO` 在 24.11.6 已移除** |
| **RTE_ETH_TX_OFFLOAD_TCP_TSO** | DPDK 24.11.6 中 TSO 发卸载能力宏 |
| **tso_segsz** | mbuf 中 TSO 分段大小（每段 payload 字节数，通常等于 MSS） |
| **l2_len / l3_len / l4_len** | mbuf 中各层头部长度（以太头 / IP 头 / TCP 头），TSO/csum offload 必填 |
| **RTE_MBUF_F_TX_TCP_SEG** | mbuf `ol_flags` 中 TSO 请求标记（旧名 `PKT_TX_TCP_SEG`），隐含 TCP 校验和卸载 |
| **RTE_MBUF_F_TX_IPV4 / _IPV6** | mbuf `ol_flags` 中 IP 版本标记，配合 offload 使用 |
| **RTE_MBUF_F_RX_LRO** | mbuf `ol_flags` 中收包侧标记，表明该 mbuf 是硬件 LRO 合并段 |
| **IFCAP_LRO / IFCAP_TSO** | FreeBSD ifnet 能力位，声明接口支持 LRO / TSO |
| **CSUM_TSO / CSUM_IP6_TSO** | FreeBSD mbuf `csum_flags`，标记该 mbuf 需 TSO（IPv4 / IPv6） |
| **if_hw_tsomax / _tsomaxsegcount / _tsomaxsegsize** | FreeBSD ifnet 侧 TSO 上限（总长/段数/段大小），`tcp_output` 依此约束分段 |
| **nb_segs** | DPDK mbuf 链中的分段数（LRO 大段、scatter、TSO 前大段均涉及） |
| **max_lro_pkt_size** | DPDK `rxmode` 中 LRO 合并后单包最大字节数上限 |
| **PMD** | Poll Mode Driver，DPDK 轮询模式网卡驱动（virtio/ixgbe/i40e/mlx5/ice/ena 等） |

## 6. 关键纠正记录（预读 vs 实际代码）

> 本节汇总 plan mode 预读结论与实际代码不一致处，全部以实际代码为准。

1. **`rx_lro` 字段**：预读疑问"是否有 `uint8_t rx_lro;`" → **实际已存在**（`ff_config.h:114`），但无任何赋值/消费点。
2. **LRO 宏名**：预读列出 `DEV_RX_OFFLOAD_TCP_LRO` 与 `RTE_ETH_RX_OFFLOAD_TCP_LRO` 两候选 → **实际 DPDK 24.11.6 只有 `RTE_ETH_RX_OFFLOAD_TCP_LRO`（`rte_ethdev.h:1556`），无 `DEV_` 兼容别名**。现有 `#if 0` 代码用的是已失效的 `DEV_RX_OFFLOAD_TCP_LRO`（`ff_dpdk_if.c:893/895`），启用即编译失败。
3. **TSO offload 字段**：预读担心"只见 l4_len/tso_segsz" → **实际 l2_len/l3_len 在 tcp_csum 分支已填，TSO 分支填 l4_len/tso_segsz/TCP_SEG 标记**；真正缺口是 **IPv6 路径**（下游一律按 IPv4 `rte_ipv4_phdr_cksum` 处理，`ff_dpdk_if.c:2460`、`ff_memory.c:363`）。
4. **stub**：`tcp_lro_hpts_init/uninit` 确为空 stub（`ff_stub_14_extra.c:629-639`）；`tcp_lro.c` 已编译（`Makefile:513`）、`tcp_hpts.c` 已编译（`Makefile:572`），但 **`tcp_lro_hpts.c` 未在 Makefile 编译列表**（搜索 0 命中）。
