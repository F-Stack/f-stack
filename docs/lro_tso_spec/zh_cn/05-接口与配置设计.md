# F-Stack LRO/TSO 接口与配置设计（中文）

> 文档层级：接口与配置设计（M3 阶段产出之二）
> 设计依据：`04-方案与架构设计.md`。本文档把方案落到**具体文件的变更点、接口契约、返回码、默认策略**，供后续编码里程碑直接对照。
> 铁律：本轮**不写代码、不改 lib、不提交**。以下"变更点"为设计说明，非实际改动；所有 `file:line` 附代码坐实位置，编码时以最新代码为准（先 read_file 复核）。

---

## 一、config.ini 变更设计

### 1.1 新增 `[dpdk] lro` 项

**位置**：`[dpdk]` 段，紧邻 `tso=0`（`config.ini:22`），对齐 tso 写法（注释 + 键值，默认关闭）。

**设计内容**（注释形式说明语义）：
```ini
# TCP large receive offload, default: disabled.
lro=0
```

**约束（config.ini 本地测试值不入库规约）**：
- 入库默认值必须为 `lro=0`。本地运行/调试若临时改为 `lro=1`，提交前必须回滚为 `0`。
- 该项与 `tso=0` 语义对称：`0`=关闭（默认，零回归）、`1`=尝试启用（受 PMD 能力门控）。

**兼容性**：老 config.ini 无 `lro` 项时，解析层不命中 `MATCH("dpdk","lro")`，`dpdk.lro` 保持默认值 `0`（见 3.2 默认策略），行为与现状一致。

## 二、ff_config.h 变更设计

### 2.1 `struct ff_hw_features`（`ff_config.h:112-118`）

- **`uint8_t rx_lro;`（L114）已存在**，无需新增。本轮将其从"死字段"激活：生产点在 `ff_dpdk_if.c` LRO 探测块（04 文档 1.2），消费点在 `ff_veth.c` `IFCAP_LRO` 设置（04 文档 1.5）。
- 无其他 `ff_hw_features` 变更（`tx_tso` L117 复用于 TSO 完善，不新增字段）。

### 2.2 `struct ... dpdk`（`ff_config.h:288-300`）

- **新增** `int lro;`，放在 `int tso;`（L295）之后，与 `tso` 对称：
  ```c
  int tso;
  int lro;                 /* TCP large receive offload switch, 0=off */
  int tx_csum_offoad_skip;
  ```
- 类型 `int`（与 `tso` 一致，`atoi` 解析）。

**契约**：`dpdk.lro` 是**用户配置意图**（0/1）；`hw_features.rx_lro` 是**实际生效状态**（PMD 支持且开启才为 1）。二者分离，与 `dpdk.tso`（意图）vs `hw_features.tx_tso`（生效）的既有分离范式一致。

## 三、ff_config.c 变更设计

### 3.1 解析分支（`ff_config.c:1054-1057` 附近）

在 `MATCH("dpdk", "tso")` 分支（L1054-1055）之后新增：
```c
} else if (MATCH("dpdk", "lro")) {
    pconfig->dpdk.lro = atoi(value);
}
```
- **契约**：与 `tso` 解析逐字对称（`atoi(value)`）。
- **返回**：`ini_parse_handler` 命中赋值分支后返回 1（成功，沿用该 handler 的既有返回约定，编码时 read_file 复核该 handler 的成功返回值）。

### 3.2 默认值设置

- **要求**：在配置默认初始化路径（`ff_default_config` 或结构清零 + 显式默认设置处）令 `pconfig->dpdk.lro = 0`。
- **坐实待办（编码阶段）**：`ff_config.c` 是否有集中的 `ff_default_config` 显式设 `tso` 默认值，还是依赖 memset 清零。若依赖清零，则 `int lro` 自然为 0，无需显式设置；若有显式默认块，则按 tso 同处新增 `lro=0`。编码时 read_file 定位 `tso` 默认赋值处并对齐。
- **默认关闭兼容策略**：无论 config.ini 是否含 `lro` 项，`dpdk.lro` 默认 0，保证老配置零回归。

**校验/错误处理**：`lro` 取值只做 `atoi`（与 tso 一致），不做范围校验（非 0 即视为开启，受 PMD 能力门控最终裁决）；无需新增错误码。

## 四、ff_dpdk_if.c 变更点

### 4.1 LRO 使能块重写（`ff_dpdk_if.c:891-898`）

- **删除** `#if 0 ... #endif`（L892/L898）。
- **改宏**：`DEV_RX_OFFLOAD_TCP_LRO` → `RTE_ETH_RX_OFFLOAD_TCP_LRO`（`rte_ethdev.h:1556`）。
- **加开关门控**：整块挂在 `if (ff_global_cfg.dpdk.lro)` 下（对齐 TSO 的 `if (ff_global_cfg.dpdk.tso)` L931）。
- **加 `max_lro_pkt_size`**：见 4.2。
- **接口契约**：
  - 输入：`dev_info.rx_offload_capa`、`ff_global_cfg.dpdk.lro`。
  - 输出：`port_conf.rxmode.offloads |= RTE_ETH_RX_OFFLOAD_TCP_LRO`、`pconf->hw_features.rx_lro = 1`（仅当 lro=1 且 PMD 支持）。
  - 日志：支持→"LRO is supported"；不支持→"LRO is not supported"；关闭→"LRO is disabled"（对齐 TSO 三态日志 L933/938/941）。

### 4.2 `max_lro_pkt_size` 设置（同 4.1 块内）

- 在置 `rx_lro=1` 时设置 `port_conf.rxmode.max_lro_pkt_size`：
  - 优先 `dev_info.max_lro_pkt_size`（`rte_ethdev.h:1792`，PMD 宣告可配置上限）。
  - PMD 未宣告（为 0）时取保守默认（不超过 mbuf 承载能力，且 `>= mtu`）。
- **契约**：`max_lro_pkt_size` 必须 `>= mtu`（04 文档 1.3）；取值须在 `dev_configure` 之前设置到 `port_conf.rxmode`。

### 4.3 TSO offload 填充 IPv6 分流（`ff_dpdk_if.c:2455-2465`）

- TSO 分支按 `iph->version` 分流（04 文档 2.1 代码）：
  - IPv4：`RTE_MBUF_F_TX_IPV4 | RTE_MBUF_F_TX_IP_CKSUM`，`rte_ipv4_phdr_cksum`，`l3_len=iph_len`。
  - IPv6：`RTE_MBUF_F_TX_IPV6`（无 IP_CKSUM），`rte_ipv6_phdr_cksum`，`l3_len=40`（无扩展头首版）。
- **自洽**：TSO 分支内显式置 `l2_len=RTE_ETHER_HDR_LEN`、`RTE_MBUF_F_TX_TCP_SEG`、`l4_len`、`tso_segsz`，不依赖前置 `ip_csum`/`tcp_csum` 分支命中。
- **接口契约**：输入为 `offload.tso_seg_size`（来自 `ff_mbuf_tx_offload`）+ mbuf 数据区 IP 头；输出为 `head->ol_flags`/`l2_len`/`l3_len`/`l4_len`/`tso_segsz` 与 TCP 伪头 checksum。

### 4.4 双份逻辑收敛（`ff_dpdk_if.c:2405-2472` 与 `ff_memory.c:331-375`）

- 首选抽取公共函数（04 文档 2.4 方案 A）：
  ```c
  /* 建议签名（放在两处均可 include 的公共位置） */
  void ff_fill_tx_offload(struct rte_mbuf *head, void *data,
                          const struct ff_tx_offload *offload,
                          uint8_t tx_csum_l4);
  ```
- 两个调用点（`ff_dpdk_if.c:2410-2472`、`ff_memory.c:326-375`）改为调用该函数。
- 若跨编译单元依赖复杂，退方案 B（两处同步改 + 交叉引用注释）。

## 五、ff_veth.c 变更点

### 5.1 `IFCAP_LRO` 设置（`ff_veth.c:941-956`）

- 在能力设置块新增（与 `IFCAP_TSO` L951-953 并列）：
  ```c
  if (cfg->hw_features.rx_lro) {
      if_setcapabilitiesbit(ifp, IFCAP_LRO, 0);
  }
  ```
- `if_setcapenable(ifp, if_getcapabilities(ifp))`（L956）自动使能。
- **契约**：仅当 `rx_lro=1`（04 文档 1.2 生产）时声明；LRO 收方向无 hwassist 需求。

### 5.2 `if_hw_tsomax` 系列设置（`ff_veth.c:951-953` TSO 块内）

- 在 `IFCAP_TSO` 设置后新增三项上限（04 文档 2.3）：
  ```c
  if_sethwtsomax(ifp, <总长上限>);
  if_sethwtsomaxsegcount(ifp, <段数上限>);
  if_sethwtsomaxsegsize(ifp, <段大小上限>);
  ```
- **坐实待办（编码阶段）**：`if_sethwtsomax`/`if_sethwtsomaxsegcount`/`if_sethwtsomaxsegsize` 的确切 API 名以 FreeBSD 15.0 移植 `freebsd/net/if.h`/`if_var.h` 实际导出为准（部分版本用 `ifp->if_hw_tsomax = ...` 直赋）。read_file 复核后选正确接口。
- **取值契约**：三项须为**非 0**（0 时 `tcp_output.c:927` 不生效，退回不约束）；取值遵循 04 文档 2.3 原则（总长 ≤ IP_MAXPACKET 维度、segcount/segsize 保守默认 + 运行时校准）。

### 5.3 `ff_mbuf_tx_offload` 兼容 `CSUM_IP6_TSO`（`ff_veth.c:304-306`）

- 扩展 TSO 识别（04 文档 2.6）：
  ```c
  if (mb->m_pkthdr.csum_flags & (CSUM_TSO | CSUM_IP6_TSO)) {
      offload->tso_seg_size = mb->m_pkthdr.tso_segsz;
  }
  ```
- **坐实待办（编码阶段第一项）**：确认 `CSUM_IP6_TSO` 与 `CSUM_TSO` 宏位关系（`freebsd/sys/... mbuf` 头）。若 `CSUM_IP6_TSO` 已含 `CSUM_TSO` 位则本改动可省；若为独立位则必需。

## 六、接口契约汇总表

| 接口/变量 | 类型/位置 | 生产者 | 消费者 | 契约 |
| --- | --- | --- | --- | --- |
| `dpdk.lro` | `int`，`ff_config.h` dpdk 结构（新增，L295 后） | `ff_config.c` 解析（新增 MATCH）；默认 0 | `ff_dpdk_if.c:891` 探测块 | 0=关（默认零回归），1=尝试启用 |
| `hw_features.rx_lro` | `uint8_t`，`ff_config.h:114`（已存在） | `ff_dpdk_if.c` LRO 探测（新增置 1） | `ff_veth.c` IFCAP_LRO（新增消费） | lro=1 且 PMD 支持才为 1 |
| `rxmode.offloads` LRO 位 | DPDK `port_conf` | `ff_dpdk_if.c:891` 块 | DPDK `dev_configure` | 仅置 PMD `rx_offload_capa` 宣告的位 |
| `rxmode.max_lro_pkt_size` | `uint32_t` `rte_ethdev.h:432` | `ff_dpdk_if.c:891` 块（新增） | DPDK PMD | `>= mtu`；优先 `dev_info.max_lro_pkt_size` |
| `IFCAP_LRO` | ifnet 能力位 | `ff_veth.c:941-956`（新增） | FreeBSD 协议栈 | 声明接口支持 LRO 段接收 |
| TSO offload 字段 | mbuf `ol_flags`/`l2_len`/`l3_len`/`l4_len`/`tso_segsz` | `ff_dpdk_if.c:2455` / `ff_memory.c:358`（改：version 分流） | DPDK PMD | IPv4 带 IP_CKSUM+v4 伪头；IPv6 带 v6 伪头无 IP_CKSUM |
| `if_hw_tsomax*` | ifnet 上限 | `ff_veth.c:951`（新增） | `tcp_output.c:905-931` | 非 0；约束 TSO 分段 |
| `offload.tso_seg_size` | `ff_tx_offload` | `ff_veth.c:304`（改：加 CSUM_IP6_TSO） | `ff_dpdk_if.c`/`ff_memory.c` TSO 分支 | 协议无关，v4/v6 由下游 version 判 |

## 七、返回码与错误处理设计

| 场景 | 处理 | 理由 |
| --- | --- | --- |
| config.ini 无 `lro` 项 | 默认 0，不报错 | 老配置兼容 |
| `lro=1` 但 PMD 不支持 | 记 "LRO is not supported" 日志，`rx_lro` 保持 0，继续启动 | 与 TSO 不支持处理一致（`ff_dpdk_if.c:938`），不 fatal |
| `max_lro_pkt_size` 被 PMD 拒绝 | `dev_configure`/`rte_eth_dev_start` 返回错误 → 沿用现有端口初始化错误处理（rte_exit/日志） | 运行时暴露，非 spec 阶段 |
| `tso=1` + `tx_csum_offoad_skip=1` 不一致组合 | 记 WARN 日志（04 文档 2.5），不强改行为 | 避免改变既有默认路径 |
| IPv6 含扩展头 TSO | 首版按 l3_len=40 处理，扩展头场景标注待增强 | 已知边界，不阻塞核心 |
| `CSUM_IP6_TSO` 独立位未识别 | 编码阶段坐实宏关系后决定是否扩展 | 见 5.3 |

## 八、默认关闭兼容策略（零回归保证）

1. **LRO**：`dpdk.lro` 默认 0 → `if (dpdk.lro)` 不进入 → LRO 探测块、`max_lro_pkt_size`、`rx_lro` 全不生效 → `ff_veth.c` `if (rx_lro)` 不设 `IFCAP_LRO` → 收包路径无任何 LRO 分支变化。**结论：lro=0 时与现状逐字节一致**。
2. **TSO**：`tso=0`（默认）→ `if (dpdk.tso)` 不进入 → `tx_tso=0` → `ff_veth.c` `if (tx_tso)` 不设 IFCAP_TSO/tsomax；发包路径 `if (offload.tso_seg_size)` 依赖 `CSUM_TSO`，`tso=0` 时协议栈不置 CSUM_TSO → TSO 分支不进入。**结论：tso=0 时 IPv6 分流/tsomax 等新增逻辑全不触及**。
3. `IFCAP_LRO`/`if_hw_tsomax` 均挂在 `hw_features` 开关下，默认关闭时不声明、不设置。

## 九、lib 最小注释原则（编码约束）

- 新增代码只在**契约/不直观处**加简洁注释，例如：
  - `dpdk.lro` 结构成员：一行说明"TCP large receive offload switch, 0=off"。
  - IPv6 TSO 分支：一行说明"IPv6 has no IP header checksum"。
  - `max_lro_pkt_size`：一行说明取值来源（dev_info 优先）。
- **禁止**给 `atoi(value)`、`if_setcapabilitiesbit` 等自解释调用加注释。
- 沿用文件既有注释风格（如 TSO 分支现有大段 DPDK 契约注释 `ff_dpdk_if.c:2440-2454` 可保留/复用，不重复堆砌）。
