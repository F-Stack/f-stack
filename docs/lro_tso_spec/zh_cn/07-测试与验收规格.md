> 文档层级：测试与验收规格（M4 阶段产出之一）

## 一、测试总原则（红线）

1. **所有"通过"来自实际执行，不臆测**：任何用例的 PASS 必须有实际运行证据（单测二进制退出码、编译输出、抓包文件、`netstat`/xstats 计数、日志行）。禁止以"代码看起来对"作为通过依据。
2. **先证默认关闭零回归，再验证开启**：先证明 `dpdk.lro=0` / `dpdk.tso=0`（默认值）时行为与现状逐字节一致（04 文档 0.2 设计不变量、05 文档八），再验证 `lro=1` / `tso=1` 的功能。零回归是硬红线，任何开启态的 bug 都不得以牺牲默认路径为代价修复。
3. **硬件依赖项区分"代码路径通过"vs"端到端通过"**：硬件 LRO 强依赖具体 PMD 能力（本机 virtio，见 04 文档诚实边界清单）。当本机 PMD 不宣告 `RTE_ETH_RX_OFFLOAD_TCP_LRO` 时，**可标记通过**的项（config 解析 / 能力探测优雅降级 / 编译 / 默认零回归）与**不可标记通过**的项（端到端 LRO 聚合收包）必须显式分层，不得用代码路径通过冒充端到端通过。
4. **代码为准、file:line 可复核**：测试断言引用的现状/变更点一律附 `file:line`；与预读或外网结论不一致处以实际代码为准。
5. **门禁失败必须打回修复（bounce≤3）**：任一门禁失败打回对应里程碑（CM1-CM5）修复，同一步骤打回不超过 3 次，超 3 次转人工，禁止搁置或带病放行（06 文档三）。
6. **编译规约**：单测/集成前的每次 lib 改动，先 `make clean` 再完整编译，禁以增量编译作为通过依据。

### 2.2 test_ff_dpdk_if：LRO 能力探测与 max_lro_pkt_size

**被测点**：`ff_dpdk_if.c:891-898` 重写后的 LRO 使能块（04 文档 1.2、05 文档 4.1/4.2）。该块位于端口初始化路径，深度依赖 `dev_info`/`port_conf`，现有 `test_ff_dpdk_if.c` 仅覆盖 7 个 trivial getter/setter（其头部注释 §NOT tested）。故本组测试**优先以可宿主编译的纯逻辑抽取 + stub `dev_info` 方式**覆盖探测判定分支；若探测逻辑内联在大型初始化函数内无法独立调用，则降级为"集成测试静态启动日志断言"（见第四节 IT-LRO-01），并在用例表标注该降级。

| 用例 | 构造 | 断言 | 依据 |
| --- | --- | --- | --- |
| TC-LRO-CAP-01 capa 支持 | stub `dev_info.rx_offload_capa` 含 `RTE_ETH_RX_OFFLOAD_TCP_LRO`（`rte_ethdev.h:1556`），`dpdk.lro=1` | `port_conf.rxmode.offloads & RTE_ETH_RX_OFFLOAD_TCP_LRO` 置位；`hw_features.rx_lro==1` | 04 文档 1.2、05 文档 4.1 契约 |
| TC-LRO-CAP-02 capa 不支持 | stub `rx_offload_capa` 不含 LRO 位，`dpdk.lro=1` | offloads 不置 LRO 位；`rx_lro==0`；记 "LRO is not supported" 日志（优雅降级不 fatal） | 05 文档 7"lro=1 但 PMD 不支持"、04 文档 1.2 |
| TC-LRO-CAP-03 开关关闭 | `dpdk.lro=0`（capa 无论是否支持） | 不进入探测块；offloads 无 LRO 位；`rx_lro==0`；记 "LRO is disabled" | 05 文档 4.1 三态日志、八零回归 |
| TC-LRO-CAP-04 max_lro_pkt_size 取 dev_info | capa 支持且 `dev_info.max_lro_pkt_size != 0` | `port_conf.rxmode.max_lro_pkt_size == dev_info.max_lro_pkt_size` | 05 文档 4.2 优先 dev_info |
| TC-LRO-CAP-05 max_lro_pkt_size 保守默认 | capa 支持且 `dev_info.max_lro_pkt_size == 0` | `max_lro_pkt_size` 取保守默认且 `>= mtu`（`rte_ethdev.h:432` 语义） | 05 文档 4.2、04 文档 1.3 `>=mtu` |

**诚实边界（TC-LRO-CAP-\* 降级说明）**：上述断言检验的是"代码路径依 capa/开关正确置位"，属**代码路径通过**层；本机 virtio 是否真的宣告 LRO capa 属**端到端通过**层，须运行时 `dev_info` 实测（见第四节 IT-LRO-\* 与 05 文档诚实边界）。

### 2.3 test_ff_dpdk_if / 独立单测：TSO offload 填充（IPv4/IPv6 分流）

**被测点**：`ff_dpdk_if.c:2455-2465` TSO 分支按 `iph->version` 分流（04 文档 2.1、05 文档 4.3）；若 CM5 收敛为公共函数 `ff_fill_tx_offload`（05 文档 4.4），则直接对该函数做纯逻辑单测（**推荐**：收敛后该函数无 DPDK 运行时依赖、可宿主编译，覆盖率最高）。

| 用例 | 构造（mbuf 数据区伪造 IP/TCP 头 + `offload.tso_seg_size` 非 0） | 断言 | 依据 |
| --- | --- | --- | --- |
| TC-TSO-FILL-01 IPv4 TSO | `iph->version==4`，`offload.tso_seg_size=1448` | `ol_flags` 含 `RTE_MBUF_F_TX_IPV4 \| RTE_MBUF_F_TX_IP_CKSUM \| RTE_MBUF_F_TX_TCP_SEG`；`l2_len==RTE_ETHER_HDR_LEN`；`l3_len==iph_len`（IHL<<2）；`l4_len==tcph_len`；`tso_segsz==1448`；`tcph->cksum==rte_ipv4_phdr_cksum(...)` | 04 文档 2.1/2.2、05 文档 4.3 |
| TC-TSO-FILL-02 IPv6 TSO | `iph->version==6`，无扩展头，`tso_seg_size=1448` | `ol_flags` 含 `RTE_MBUF_F_TX_IPV6 \| RTE_MBUF_F_TX_TCP_SEG`，**不含** `RTE_MBUF_F_TX_IP_CKSUM`；`l3_len==40`（`sizeof(struct rte_ipv6_hdr)`）；`l4_len`/`tso_segsz` 正确；`tcph->cksum==rte_ipv6_phdr_cksum(...)` | 04 文档 2.1（IPv6 无 IP 头校验和） |
| TC-TSO-FILL-03 l2_len 自洽 | 单独 TSO 分支命中（不先命中 `ip_csum`/`tcp_csum` 分支） | `l2_len==RTE_ETHER_HDR_LEN` 仍被填（04 文档 2.1"l2_len 移入 TSO 分支内自洽"，修复现状 L2436 依赖前置分支的缺陷） | 04 文档 2.1、02 文档 2.3 表 l2_len 行 |
| TC-TSO-FILL-04 无 TSO 不触发 | `offload.tso_seg_size==0`（`tso=0` 默认态） | 不进入 TSO 分支，`ol_flags` 不含 `RTE_MBUF_F_TX_TCP_SEG`，行为与现状一致 | 05 文档八零回归、`ff_dpdk_if.c:2455 if(offload.tso_seg_size)` |

**IPv6 扩展头边界**：TC-TSO-FILL-02 仅覆盖无扩展头（`l3_len=40`）；含扩展头场景标注**待增强**（04 文档 2.1 诚实边界、05 文档 7），不在本组断言范围。

### 2.4 单测：ff_mbuf_tx_offload 的 CSUM_TSO / CSUM_IP6_TSO 映射

**被测点**：`ff_veth.c:282-307 ff_mbuf_tx_offload`，尤其 L304-306 `if (mb->m_pkthdr.csum_flags & CSUM_TSO)`（现状仅识别 `CSUM_TSO`）；CM4 视宏位坐实结论决定是否扩展为 `& (CSUM_TSO | CSUM_IP6_TSO)`（04 文档 2.6、05 文档 5.3）。

| 用例 | 构造 mbuf `csum_flags` | 断言 | 依据 |
| --- | --- | --- | --- |
| TC-TSO-MAP-01 CSUM_TSO | `csum_flags |= CSUM_TSO`，`tso_segsz=1448` | `offload.tso_seg_size==1448` | `ff_veth.c:304-306` |
| TC-TSO-MAP-02 CSUM_IP6_TSO | `csum_flags |= CSUM_IP6_TSO`（若为独立位） | `offload.tso_seg_size==1448`（扩展后应识别） | 04 文档 2.6、05 文档 5.3 |
| TC-TSO-MAP-03 无 TSO 标记 | `csum_flags` 无 TSO 位 | `offload.tso_seg_size==0` | 现状默认 |
| TC-TSO-MAP-04 v4/v6 csum 合并 | `CSUM_TCP` / `CSUM_TCP_IPV6` | 均映射 `tcp_csum==1`（回归护栏，不因 TSO 改动破坏 L292） | `ff_veth.c:290-294` |

**坐实前置（CM4 第一项）**：TC-TSO-MAP-02 的成立性依赖 `CSUM_IP6_TSO` 与 `CSUM_TSO` 是否为**独立位**（编码阶段 `read_file` `freebsd/sys/.../mbuf.h` 坐实，05 文档 5.3）。若二者等价，则 TC-TSO-MAP-02 退化为 TC-TSO-MAP-01 覆盖、扩展代码可省，用例表须相应标注坐实结论。

> **注**：`ff_veth.c` 因依赖 FreeBSD 内核头，多数无法直接宿主编译（参见 `test_ff_zc_send.c` 头部对 ff_veth.c 不可宿主编译的说明）。故 TC-TSO-MAP-\* 优先采用"自包含 mbuf shim + 抽取被测逻辑"的算法一致性测试方式（同 `test_ff_zc_send.c` 范式），或在集成测试（第四节）中以对端抓包间接验证 v6 TSO 映射生效。

### 2.5 收包路径：LRO 大段搬运

**被测点**：`ff_veth_input`（`ff_dpdk_if.c:1694-1742`）以 `pkt->pkt_len` 建 mbuf 头（L1708）+ 多段遍历（L1725-1739）；`ff_mbuf_gethdr`（`ff_veth.c:464-485`）。方案坐实"长度搬运已天然支持 LRO 大段"（04 文档 1.4）。

| 用例 | 构造大段 mbuf | 断言 | 依据 |
| --- | --- | --- | --- |
| TC-LRO-RX-01 大 pkt_len | 单 mbuf，`pkt_len` 远超 MTU（如 60KB） | 建出的 FreeBSD mbuf `m_pkthdr.len == pkt_len` | 04 文档 1.4、`ff_dpdk_if.c:1708` |
| TC-LRO-RX-02 nb_segs>1 | mbuf 链 `nb_segs>1`，总 `pkt_len` 大 | 多段逐段挂链，最终 mbuf 链总长 == pkt_len | `ff_dpdk_if.c:1725-1739` |
| TC-LRO-RX-03 RX_LRO 标记透传（可选） | `ol_flags |= RTE_MBUF_F_RX_LRO` | 现状不因该标记改变搬运（首版 LRO 感知为可选增强，04 文档 1.4 步骤 2）；若实现了透传则断言语义正确 | 04 文档 1.4 |
| TC-LRO-RX-04 csum 标记 | `rx_csum` 开 + LRO 大段 csum good | `ff_mbuf_gethdr` 置 `CSUM_DATA_VALID\|CSUM_PSEUDO_HDR`（`ff_veth.c:479-483`）对大段同样成立 | 04 文档 1.4 步骤 1 |

> **注（宿主编译限制）**：`ff_veth_input`/`ff_mbuf_gethdr` 依赖 FreeBSD mbuf，宿主编译困难。TC-LRO-RX-\* 优先以"抽取长度/多段搬运算法 + mbuf shim"的一致性测试覆盖（同 zc_send 范式）；真实 LRO 大段收取的端到端正确性由第四节 IT-LRO-\* 运行时验证，属**端到端通过**层。

**被测点**：`ff_dpdk_if.c:2405-2472` 与 `ff_memory.c:331-375` 两处填充逻辑（02 文档 2.3、04 文档 2.4、05 文档 4.4）。
