## 复现方案

### 目标

验证 issue #535 描述的场景：IPFW 规则数 >400 时 `ff_ipfw list` 失败。

### 步骤

1. 启动 helloworld primary 进程（`example/helloworld -c config.ini`）
2. 等待 DPDK 初始化完成（~18 秒）
3. `tools/sbin/ipfw -P 0 flush` 清空现有规则
4. 逐条添加 IPFW 规则: `tools/sbin/ipfw -P 0 add <num> allow tcp from any to any`
5. 执行 `tools/sbin/ipfw -P 0 list` 获取全部规则（触发 GET 路径）
6. 二分搜索找到精确 breaking point

### 判定标准

- `list` 返回 "ipfw: retrieving config failed: Invalid argument" = EINVAL 失败（bug 复现）
- `list` 正常输出所有规则 = 成功

## 修复验证方案

### 目标

验证修复后 IPFW 大规则集（252/500/1000 条）可正常 list。

### 步骤

1. `make clean && make` 重编 ff_ipfw 工具
2. 启动 helloworld primary 进程
3. 添加指定数量规则
4. 执行 `list` 验证全部规则正常输出
5. 对比修复前 breaking point（252 条）

## 性能回归方案

### 目标

验证修复未引入 TCP 数据面性能回归。

### 步骤

1. 对齐 config.ini 与上次基线测试配置（lcore_mask=10, idle_sleep=20）
2. 启动 helloworld primary 进程
3. T1 预热: `wrk -t2 -c10 -d5s --latency http://9.134.214.176:80/`
4. T2 Trial 1: `wrk -t4 -c100 -d30s --latency http://9.134.214.176:80/`
5. 间隔 30 秒等待 TIME_WAIT 回收
6. T2 Trial 2: `wrk -t4 -c100 -d30s --latency http://9.134.214.176:80/`
7. 对比基线: 上次 #331 修复后 1 核 T2 median = 193,405 req/s, p99 = 762us

### 判定标准

- 吞吐偏差 < 6%（基线报告记载的跨日噪声范围）
- p99 延迟无显著退化
