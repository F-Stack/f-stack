# 03 — 根因分析与修复方案

## 一、根因分析

### 1.1 直接原因

`tools/ipfw/compat.c` 的 `ipfw_ctl()` 函数在 IPC 消息缓冲区不足时直接返回 EINVAL，而非动态分配更大缓冲区。

**修复前代码** (`tools/ipfw/compat.c:59-64`):
```c
len = sizeof(struct ff_ipfw_args) + *optlen + sizeof(socklen_t);
if (len > msg->buf_len) {
    errno = EINVAL;
    ff_ipc_msg_free(msg);
    return -1;
}
```

### 1.2 缓冲区大小限制

`lib/ff_msg.h:131` 定义 `MAX_MSG_BUF_SIZE = 10240`（10KB），mempool 元素大小以此为准。`ff_msg_init` 设置实际可用缓冲区:

```c
msg->buf_addr = (char *)msg + sizeof(struct ff_msg);
msg->buf_len = mp->elt_size - sizeof(struct ff_msg);
```

实际可用 ≈ 10240 - sizeof(struct ff_msg) ≈ 10112 字节。

### 1.3 IPFW 规则数据量

每条 IPFW 规则在二进制序列化后约 39.8 字节。当规则数超过 253 条（含 2 条默认规则 = 255 总）时，`getsockopt(IP_FW3)` 返回的规则数据总量超过 10KB 缓冲区限制。

### 1.4 issue #535 场景对应

- issue 报告 >400 条规则/进程时崩溃
- 实测 breaking point = 252 条用户规则
- 400 条规则的数据量 ≈ 400 × 39.8 = 15.9KB，远超 10KB 限制
- EINVAL 失败导致 `ff_ipfw list/show` 无法获取规则集，工具表现为"挂起"
- 多进程场景下（32 worker），每个 secondary 进程独立分配 IPC 消息，可能触发 mempool 耗尽导致 EAL 分配错误

### 1.5 为什么 sysctl 不受影响

`tools/compat/sysctl.c` 已实现动态缓冲区方案（`rte_malloc` + `original_buf` 备份），当数据超过 `buf_len` 时自动分配更大缓冲区。而 `ipfw/compat.c` 未采用此模式，直接失败。

## 二、修复方案

### 2.1 方案选择

**采用方案**: 将 `tools/compat/sysctl.c` 的动态缓冲区模式应用到 `tools/ipfw/compat.c`。

**排除方案**: 增大 `MAX_MSG_BUF_SIZE` — 会增加所有 IPC 消息的 per-element 内存（mempool 大小 = `MSG_RING_SIZE * 2 * nb_rings * MAX_MSG_BUF_SIZE`），32 进程场景下 hugepage 占用显著增加；且无法确定"多大够用"，无上限保护。

### 2.2 修改内容

**修改 1** — 添加头文件 (`tools/ipfw/compat.c:32`):
```c
#include <rte_malloc.h>
```

**修改 2** — 替换 EINVAL 块为动态缓冲区分配 (`tools/ipfw/compat.c:61-72`):
```c
if (len > msg->buf_len) {
    char *extra_buf = rte_malloc(NULL, len, 0);
    if (extra_buf == NULL) {
        errno = ENOMEM;
        ff_ipc_msg_free(msg);
        return -1;
    }
    msg->original_buf = msg->buf_addr;
    msg->original_buf_len = msg->buf_len;
    msg->buf_addr = extra_buf;
    msg->buf_len = len;
}
```

### 2.4 动态缓冲区生命周期

```
secondary (ff_ipfw)                    primary (helloworld)
    │                                       │
    │ ff_ipc_msg_alloc() 从 mempool 获取     │
    │ len > buf_len?                        │
    │   → rte_malloc 动态分配                │
    │   → 保存 original_buf, 切换 buf_addr   │
    │   → ipfw.optval 指向动态缓冲区          │
    │                                       │
    │ ──── ff_ipc_send(msg) ──────────────→ │
    │                                       │ handle_ipfw_msg()
    │                                       │   ff_getsockopt_freebsd()
    │                                       │   响应写入 ipfw.optval (动态缓冲区)
    │                                       │
    │ ←──── enqueue to OUT ring ─────────── │
    │                                       │
    │ ff_ipc_recv() 接收 retmsg             │
    │ 读取 retmsg->ipfw.optval (动态缓冲区)   │
    │                                       │
    │ ff_ipc_msg_free(msg):                 │
    │   rte_free(动态缓冲区)                 │
    │   恢复 original_buf                    │
    │   归还到 mempool                       │
```

### 2.5 内存安全保证

| 路径 | 动态缓冲区处理 | 安全? |
|------|-------------|-------|
| 正常完成 (send→recv→free) | `ff_ipc_msg_free` 检测 `original_buf` → `rte_free` → 恢复 | 是 |
| `rte_malloc` 失败 | `original_buf` 未设置 → `ff_ipc_msg_free` 直接归还 mempool | 是 |
| `ff_ipc_send` 失败 | `original_buf` 已设置 → `ff_ipc_msg_free` 释放动态缓冲区 | 是 |
| 主进程 enqueue 失败 | `lib/ff_dpdk_if.c:2338-2344` 检测 `original_buf` → `rte_free` → 恢复 | 是 |

### 2.6 为何不影响 TCP 数据面性能

- 修改仅在 `tools/ipfw/compat.c`（ff_ipfw 工具的 IPC 客户端层）
- 不修改 `lib/`（协议栈库）、不修改 `example/helloworld`（应用层）
- 动态缓冲区仅在规则数据 > 10KB 时分配，正常小规则集走原始 mempool 路径
- `rte_malloc` 从 DPDK hugepage 分配，与 mempool 性能相当
