# 测试结果与数据分析

## T1：默认配置（tx_csum_offoad_skip=0）

### 配置
```ini
tx_csum_offoad_skip=0
```

### 结果
- **TCP 连接**：成功
- **Echo 数据**：发送 15 字节 "hello-csum-test"，收到 15 字节，完全匹配
- **服务器日志**：ACCEPT → RECV 15 bytes → SENT 15 bytes → CLOSE

### tcpdump 抓包分析

F-Stack 服务器发出的包（9.134.214.176 → 9.134.211.87）：

| 包类型 | TCP cksum | IP cksum | 结果 |
|--------|-----------|----------|------|
| SYN-ACK | 0x3c99 (correct) | 正确（无 bad cksum） | ✅ |
| ACK | 0x5e72 (correct) | 正确 | ✅ |
| ACK | 0x5e63 (correct) | 正确 | ✅ |
| PSH-ACK (echo) | 0x3a84 (correct) | 正确 | ✅ |
| ACK | 0x5e53 (correct) | 正确 | ✅ |
| FIN-ACK | 0x5e52 (correct) | 正确 | ✅ |

**结论**：所有 IP checksum 和 TCP checksum 均正确。virtio NIC 不支持 TX checksum offload，FreeBSD 软件计算所有 checksum。

## 综合分析

### 三组测试对比

| 测试 | 配置 | IP offload | L4 offload | TCP 连接 | IP cksum | TCP cksum |
|------|------|-----------|-----------|----------|----------|-----------|
| T1 | 默认 | 禁用（virtio不支持） | 禁用（virtio不支持） | ✅ | ✅ | ✅ |
| T2 | skip=1 | 禁用 | 禁用 | ✅ | ✅ | ✅ |
| T3 | ip_skip=1 | 禁用 | 禁用（virtio不支持） | ✅ | ✅ | ✅ |

### 关键发现

1. **virtio NIC 不支持 TX checksum offload**：F-Stack 日志无 "TX ip checksum offload supported" 消息，`hw_features.tx_csum_ip` 和 `tx_csum_l4` 均为 0
2. **FreeBSD 软件计算所有 checksum**：由于硬件不支持 offload，FreeBSD ip_output/tcp_output 在软件层计算 IP 和 TCP checksum
3. **新增配置项工作正常**：`tx_csum_ip_skip=1` 被正确解析，不影响正常功能
4. **TX 路径守卫修复有效**：`ctx->hw_features.tx_csum_ip && offload.ip_csum` 守卫确保即使 `offload.ip_csum` 为 true（理论上不会发生），也不会错误设置 `RTE_MBUF_F_TX_IP_CKSUM`
