# 测试方案与环境

## 测试环境

| 项目 | 内容 |
|------|------|
| F-Stack 版本 | 1.26（本地编译，FreeBSD 15.0 基础） |
| DPDK 版本 | 24.11.6 LTS |
| 本机类型 | 物理机（虚拟化环境中的 VM） |
| DPDK 端口 | 0000:00:09.0 Virtio (igb_uio)，IP 9.134.214.176 |
| 内核网卡 | 0000:00:05.0 Virtio (virtio-pci)，eth1，IP 9.134.211.87 |
| 测试客户端 | f-stack-client (9.134.211.87)，通过 ssh 连接 |
| TCP 测试端口 | 15200 |

## 环境限制

本机为物理机+DPDK 环境（virtio NIC），非 VMware ESXi。无法直接复现 VMware 的"虚拟网卡声称支持但不实际计算"问题。但可验证：
1. 默认配置下 TX checksum offload 工作状态
2. `tx_csum_offoad_skip=1` 时软件计算 checksum 正确性
3. 新增 `tx_csum_ip_skip=1` 细粒度控制工作正常

virtio NIC 不支持 TX IP/L4 checksum offload（F-Stack 日志无 "TX ip checksum offload supported" 消息），FreeBSD 软件计算所有 checksum。

## 测试矩阵

| 测试 | 配置 | 验证方法 | 预期 |
|------|------|----------|------|
| T1 | 默认（skip=0） | TCP 连接 + tcpdump 抓包 | 连接成功，checksum 正确 |
| T2 | skip=1 | 同上 | 连接成功，checksum 正确（软件计算） |
| T3 | ip_skip=1, l4_skip=0 | 同上 | 连接成功，checksum 正确（软件计算 IP） |

## 测试程序

### F-Stack TCP Echo Server (`csum_test_server.c`)

- 使用 F-Stack API：`ff_socket`/`ff_bind`/`ff_listen`/`ff_kqueue`/`ff_kevent`/`ff_accept`/`ff_recv`/`ff_send`
- 监听端口 15200，接收数据并原样返回
- 关键：`ff_bind` 和 `ff_accept` 需使用 `(struct linux_sockaddr *)` 强制转换

### Python TCP Client (`csum_test_client.py`)

- 连接到 F-Stack 服务器，发送 "hello-csum-test"（15 字节），验证 echo 数据正确性

### tcpdump 抓包

- 在 f-stack-client 上执行：`tcpdump -i eth1 -n -v 'host 9.134.214.176 and tcp port 15200'`
- 验证 F-Stack 服务器发出的包的 IP checksum 和 TCP checksum 是否正确
