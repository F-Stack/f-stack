# 根因分析与修复方案

## Issue #520 根因

### 问题描述

VMware ESXi 5.5.0 虚拟网卡声称支持 TX IP checksum offload（`RTE_ETH_TX_OFFLOAD_IPV4_CKSUM` capability 为 true），但实际不计算 IP 校验和。F-Stack 的 `ff_dpdk_if.c` 根据 capability 启用 offload 并设置 `hw_features.tx_csum_ip=1`，FreeBSD 栈因此设置 `CSUM_IP` hwassist 并在 mbuf `csum_flags` 中标记 `CSUM_IP`，请求硬件计算 IP checksum。TX 路径设置 `RTE_MBUF_F_TX_IP_CKSUM` ol_flag。但 VMware 虚拟网卡不执行计算，导致 IP checksum 为 0。

### 数据包路径

```
config.ini: tx_csum_offoad_skip=0
    ↓
ff_dpdk_if.c:983-988: 检测到 RTE_ETH_TX_OFFLOAD_IPV4_CKSUM → hw_features.tx_csum_ip=1
    ↓
ff_veth.c:987-989: tx_csum_ip=1 → IFCAP_TXCSUM + CSUM_IP hwassist
    ↓
FreeBSD ip_output: CSUM_IP in hwassist → mbuf csum_flags |= CSUM_IP（请求硬件 IP offload）
    ↓
ff_veth.c:289: ff_mbuf_tx_offload 提取 offload.ip_csum=1
    ↓
ff_dpdk_if.c:2502: offload.ip_csum → 设置 RTE_MBUF_F_TX_IP_CKSUM
    ↓
DPDK PMD: VMware 虚拟网卡不计算 → IP checksum=0 ← 问题在此
```

### 临时方案

`tx_csum_offoad_skip=1`：禁用所有 TX checksum offload（IP+L4），FreeBSD 软件计算所有 checksum。缺点：同时禁用 L4 offload，性能损失过大。

## 修复方案

### 1. 细粒度控制（新增配置项）

新增 `tx_csum_ip_skip` 和 `tx_csum_l4_skip` 配置项，支持独立控制 IP 层和 L4 层 TX checksum offload。

#### 向后兼容矩阵

| `tx_csum_offoad_skip` | `tx_csum_ip_skip` | `tx_csum_l4_skip` | IP offload | L4 offload |
|---|---|---|---|---|
| 0（默认） | 0（默认） | 0（默认） | 启用 | 启用 |
| 1 | * | * | 禁用 | 禁用 |
| 0 | 1 | 0 | **禁用** | 启用 |
| 0 | 0 | 1 | 启用 | **禁用** |

#### VMware 场景使用方式

```ini
# 只禁用 IP 层 checksum offload（VMware 虚拟网卡不计算 IP checksum）
# 保留 L4 checksum offload（VMware 虚拟网卡可能正确计算 L4 checksum）
tx_csum_offoad_skip=0
tx_csum_ip_skip=1
```

### 2. TX 路径守卫修复

**发现的问题**：TX 路径中 IP checksum offload 仅检查 `offload.ip_csum`（来自 mbuf csum_flags），缺少 `ctx->hw_features.tx_csum_ip` 守卫。而 L4 路径正确地有 `ctx->hw_features.tx_csum_l4` 守卫。

| 文件 | 行号 | 修改前 | 修改后 |
|------|------|--------|--------|
| `ff_dpdk_if.c` | 2502 | `if (offload.ip_csum)` | `if (ctx->hw_features.tx_csum_ip && offload.ip_csum)` |
| `ff_memory.c` | 319 | `if (offload.ip_csum)` | `if (ctx->hw_features.tx_csum_ip && offload.ip_csum)` |

**影响分析**：
- 当前不会出问题（`CSUM_IP` 只在 hwassist 包含 `CSUM_IP` 时设置，即 `hw_features.tx_csum_ip=1` 时）
- 但添加守卫是防御性编程的正确做法，且与 L4 路径对称
- 细粒度控制启用后，`tx_csum_ip_skip=1` 时 `hw_features.tx_csum_ip=0`，守卫确保不会错误设置 `RTE_MBUF_F_TX_IP_CKSUM`

### 3. TSO 警告条件更新

TSO 依赖 L4 checksum offload。更新 TSO 警告条件也检查 `tx_csum_l4_skip`：

```c
// 修改前：
if (ff_global_cfg.dpdk.tx_csum_offoad_skip) { ... }

// 修改后：
if (ff_global_cfg.dpdk.tx_csum_offoad_skip ||
    ff_global_cfg.dpdk.tx_csum_l4_skip) { ... }
```

## FreeBSD 软件 checksum 机制

当 `hw_features.tx_csum_ip=0` 时（IP offload 禁用或不支持）：
- `if_sethwassistbits` 不设置 `CSUM_IP`
- FreeBSD `ip_output.c` 检测到 `CSUM_IP` 未设置 → 软件计算 IP checksum（`in_cksum`）
- mbuf `csum_flags` 不含 `CSUM_IP` → `offload.ip_csum=0` → 不设置 `RTE_MBUF_F_TX_IP_CKSUM`

当 `hw_features.tx_csum_l4=0` 时（L4 offload 禁用或不支持）：
- `if_sethwassistbits` 不设置 `CSUM_DELAY_DATA`
- FreeBSD `tcp_output.c`/`udp_output.c` 软件计算 L4 checksum
- mbuf `csum_flags` 不含 `CSUM_TCP`/`CSUM_UDP` → `offload.tcp_csum=0` → 不设置 `RTE_MBUF_F_TX_TCP_CKSUM`
