# Issue #795 调研总览

## 一、Issue 信息

- **Issue**: [#795 Specifying devargs parameter?](https://github.com/F-Stack/f-stack/issues/795)
- **作者**: whatmatrix
- **创建日期**: 2024-01-22
- **状态**: open → 已修复并关闭

## 二、需求分析

用户希望能够针对 PCI 设备指定 DPDK devargs 参数（如 `scalar_enable=1` 关闭 PMD vector mode），并通过 F-Stack 配置传递给 DPDK PMD。

当前 F-Stack 的 config.ini 支持部分 DPDK EAL 参数（`allow` 白名单、`file_prefix`、`nb_vdev` 虚拟设备等），但不支持任意 DPDK EAL 启动参数透传。

### 核心痛点
F-Stack 的 `allow` 配置项用逗号分隔多个 PCI 设备（`lib/ff_config.c:1191` `strtok_r(rest, ",", &rest)`），导致无法在 allow 中附加 devargs（如 `allow=0000:00:09.0,scalar_enable=1` 会被误解析为两个设备）。

## 三、修复方案

### 通用 DPDK EAL 参数透传

新增 `extra_eal_args` 配置项（`[dpdk]` 段），支持空格分隔的多个 EAL 参数，原样追加到 `rte_eal_init()` argv 末尾。

### 配置示例
```ini
[dpdk]
# 任意 DPDK EAL 启动参数，空格分隔，追加到 rte_eal_init() argv 末尾
extra_eal_args=--allow=0000:00:09.0,scalar_enable=1
extra_eal_args=--log-level=pmd:8 --iova-mode=pa
extra_eal_args=-d /path/to/driver.so --legacy-mem
```

### 覆盖场景
- `--allow=<bdf>,<devargs>` —— 传递 PMD devargs（issue #795 原始诉求）
- `--log-level=<type>:<num>` —— 调整日志级别
- `-d <path>` —— 加载额外驱动
- `--iova-mode=<pa|va>` —— 切换 IOVA 模式
- `--legacy-mem` / `--single-file-segments` —— 内存布局调整
- 其他任何 DPDK EAL 支持的参数

## 五、设计原则

1. **通用性**：一个配置项覆盖所有 DPDK EAL 参数，而非为每个参数单独加配置项。
2. **向后兼容**：不改变现有 F-Stack 自动构建参数的行为；用户参数追加在末尾。
3. **DPDK 语义保留**：DPDK EAL 规则是"后出现的同名参数覆盖前者"，用户参数放末尾可覆盖 F-Stack 默认值。
4. **安全边界**：用户参数只透传给 DPDK，不参与 F-Stack 内部逻辑解析。

## 六、重要发现

`--device` 不是 DPDK EAL 标准参数（被 EAL 拒绝，报 `EAL: Invalid 'command line' arguments`）。DPDK devargs 的正确传递方式是 `--allow=<bdf>,<devargs>` 或 `-a <bdf>,<devargs>`。本修复通过 `extra_eal_args` 支持这两种格式。
