# 根因分析与修复方案

## 一、根因分析

### 问题本质
F-Stack 的 config.ini 不支持任意 DPDK EAL 启动参数透传。用户想传递 devargs（如 `scalar_enable=1`），但：

1. `allow` 配置项用逗号分隔多个 PCI 设备（`lib/ff_config.c:1191`），无法附加 devargs。
2. 没有通用的 EAL 参数透传机制，只能修改 `lib/ff_config.c` 源码手动添加。

### 代码追踪
- `lib/ff_config.c:1151-1308`：`dpdk_args_setup()` 按固定顺序构建 EAL 参数，无扩展点。
- `lib/ff_config.h:35`：`DPDK_CONFIG_NUM 16`，dpdk_argv 数组上限，固定参数已占用较多槽位。

## 二、修复方案

### 新增 `extra_eal_args` 配置项

在 `[dpdk]` 段新增 `extra_eal_args`，空格分隔多个 EAL 参数，原样追加到 `dpdk_argv[]` 末尾。

### 修改详情

#### 1. `lib/ff_config.h:34-35` — 提升 DPDK_CONFIG_NUM
```c
// dpdk argc, argv, max argc: 32, member of dpdk_config
#define DPDK_CONFIG_NUM 32
```
从 16 提升到 32，为用户自定义参数预留空间。M1 子 agent 确认无硬编码 16 依赖，所有引用通过宏自动跟随（含测试桩文件）。

#### 2. `lib/ff_config.h:285-288` — 新增字段
```c
        /* pci whiltelist */
        char *allow;

        /* extra DPDK EAL args, appended to rte_eal_init argv */
        char *extra_eal_args;

        int nb_channel;
```

#### 3. `lib/ff_config.c:1044-1047` — 新增解析
```c
    } else if (MATCH("dpdk", "allow")) {
        pconfig->dpdk.allow = strdup(value);
    } else if (MATCH("dpdk", "extra_eal_args")) {
        pconfig->dpdk.extra_eal_args = strdup(value);
    } else if (MATCH("dpdk", "port_list")) {
```

#### 4. `lib/ff_config.c:1284-1298` — dpdk_args_setup 末尾追加
```c
    }

    if (cfg->dpdk.extra_eal_args) {
        char* token;
        char* rest = cfg->dpdk.extra_eal_args;

        while ((token = strtok_r(rest, " ", &rest))) {
            if (n >= DPDK_CONFIG_NUM) {
                printf("extra_eal_args exceed DPDK_CONFIG_NUM, truncated\n");
                break;
            }
            dpdk_argv[n++] = strdup(token);
        }
    }

    dpdk_argc = n;
```

#### 5. `lib/ff_config.c:1764-1766` — 释放逻辑
```c
    if (ff_global_cfg.dpdk.extra_eal_args) {
        free(ff_global_cfg.dpdk.extra_eal_args);
        ff_global_cfg.dpdk.extra_eal_args = NULL;
    }
```

#### 6. `config.ini:74-78` — 配置项注释
```ini
#allow=02:00.0,03:00.0

# Extra DPDK EAL args, space-separated, appended to rte_eal_init() argv.
# e.g. extra_eal_args=--allow=02:00.0,scalar_enable=1
# e.g. extra_eal_args=--log-level=pmd:8 --iova-mode=pa
#extra_eal_args=
```

## 三、向后兼容性

| 场景 | 行为 |
|------|------|
| 不配置 extra_eal_args | 无影响（NULL，不追加任何参数） |
| 配置 extra_eal_args | 参数追加到 dpdk_argv 末尾 |
| 参数与 F-Stack 自动构建同名 | DPDK EAL 后者覆盖前者（预期行为） |
| 参数超过 DPDK_CONFIG_NUM | 打印警告并截断（防越界） |

## 四、安全边界

1. **纯透传**：extra_eal_args 不参与 F-Stack 内部逻辑解析，只透传给 DPDK。
2. **用户责任**：用户需确保参数格式正确（如 `--device` 不是 DPDK EAL 参数，应用 `--allow`）。F-Stack 不做白名单限制，与 DPDK 原生行为一致。
3. **上界保护**：`n >= DPDK_CONFIG_NUM` 检查防止数组越界。
