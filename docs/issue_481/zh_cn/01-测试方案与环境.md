## 3. 测试程序

### 3.1 F-Stack TCP Padding 测试服务器 (`padding_test_server.c`)

- 基于 F-Stack kqueue/kevent 的 TCP echo server
- 监听端口 15320
- 接收数据后打印字节数和十六进制内容
- 如果填充未被剥离，会看到额外字节

### 3.2 F-Stack UDP Padding 测试服务器 (`udp_padding_server.c`)

- 基于 F-Stack ff_run 的 UDP echo server
- 监听端口 15321
- 接收数据后打印字节数和十六进制内容
- 如果填充未被剥离，会看到额外字节

### 3.3 Python TCP 客户端 (`padding_test_client.py`)

- 连接到 F-Stack TCP server
- 禁用 Nagle (TCP_NODELAY)
- 依次发送 1 字节、6 字节、2 字节
- 检查 echo 回来的数据是否精确

### 3.4 Python UDP 客户端

- 通过 ssh 在 f-stack-client 上执行内联 Python 脚本
- 依次发送 1 字节、6 字节、2 字节、18 字节 UDP 包
- 检查 F-Stack server 收到的数据是否精确

## 4. 以太网填充计算

以太网最小帧长 = 60 字节（不含 FCS 4 字节）

| 数据长度 | 以太网帧组成 | 帧大小 | 需填充 |
|---------|------------|--------|--------|
| TCP 1字节 | 14+20+20+1 | 55 | 5字节 |
| TCP 2字节 | 14+20+20+2 | 56 | 4字节 |
| TCP 6字节 | 14+20+20+6 | 60 | 0字节 |
| UDP 1字节 | 14+20+8+1 | 43 | 17字节 |
| UDP 2字节 | 14+20+8+2 | 44 | 16字节 |
| UDP 6字节 | 14+20+8+6 | 48 | 12字节 |
| UDP 18字节 | 14+20+8+18 | 60 | 0字节 |

## 5. 关键配置

### 客户端 TCP 时间戳关闭

```
ssh f-stack-client "sudo sysctl -w net.ipv4.tcp_timestamps=0"
```

TCP 时间戳选项会增加 12 字节 TCP 头开销，导致小包 > 60 字节，无法触发填充。关闭后 TCP 头 = 20 字节，1 字节数据包 = 55 字节，触发 5 字节填充。

### F-Stack 配置

- `lro=0`（禁用 LRO，确保测试的是非 LRO 路径）
- `tx_csum_offoad_skip=0`
- `vlan_strip=1`
- `ipforwarding=0`（默认，确保 M_FASTFWD_OURS 不触发）
