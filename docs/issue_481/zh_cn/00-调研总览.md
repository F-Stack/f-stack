# Issue #481 调研总览

## 1. Issue 信息

- **标题**: Padding bytes not removed from the ethernet frame
- **编号**: [#481](https://github.com/F-Stack/f-stack/issues/481)
- **作者**: freak82
- **日期**: 2020-02-20
- **状态**: Open (label: todo)
- **评论**: 0

## 2. 问题描述

DPDK PMD 驱动不会从小于 64 字节的以太网帧中剥离填充字节。F-Stack 的 `ff_mbuf_gethdr()` 直接使用 DPDK 的 `pkt_len/data_len` 设置 `m->m_pkthdr.len/m->m_len`，包含填充字节。当以太网帧 < 60 字节（不含 FCS）时需填充到 60 字节，导致 FreeBSD 协议栈可能错误地将填充字节当作有效数据处理。

### 复现条件

1. 运行基于 F-Stack epoll 的服务器
2. 客户端关闭所有 TCP 选项（特别是 TCP 时间戳），使数据包达到最小可能尺寸
3. 客户端关闭连接时发送 FIN+ACK 包（14以太网 + 20IP + 20TCP = 54 字节 < 60，需 6 字节填充）
4. FreeBSD 协议栈剥离所有头部后 `m->m_len` = 6 字节（剩余填充字节），被当作接收数据上报给应用层

## 3. 调研结论

**Issue #481 在 F-Stack 1.26 + FreeBSD 15.0 + DPDK 24.11.6 LTS 环境中不复现。**

### 测试结果摘要

| 测试 | 协议 | 栈 | 发送数据 | 以太网帧大小 | 需填充 | 服务器收到 | 结果 |
|------|------|-----|---------|------------|--------|----------|------|
| T1 | TCP | F-Stack | 1字节 | 55字节 | 5字节 | 1字节 | ✅ PASS |
| T1 | TCP | F-Stack | 6字节 | 60字节 | 0字节 | 6字节 | ✅ PASS |
| T1 | TCP | F-Stack | 2字节 | 56字节 | 4字节 | 2字节 | ✅ PASS |
| T2 | UDP | F-Stack | 1字节 | 43字节 | 17字节 | 1字节 | ✅ PASS |
| T2 | UDP | F-Stack | 6字节 | 48字节 | 12字节 | 6字节 | ✅ PASS |
| T2 | UDP | F-Stack | 2字节 | 44字节 | 16字节 | 2字节 | ✅ PASS |
| T2 | UDP | F-Stack | 18字节 | 60字节 | 0字节 | 18字节 | ✅ PASS |

### 根因

FreeBSD 15.0 的 `ip_input.c:556-562` 有以太网填充裁剪逻辑：

```c
if (m->m_pkthdr.len > ip_len) {
    if (m->m_len == m->m_pkthdr.len) {
        m->m_len = ip_len;
        m->m_pkthdr.len = ip_len;
    } else
        m_adj(m, ip_len - m->m_pkthdr.len);
}
```

该逻辑在 F-Stack 默认配置下（`ipforwarding=0`，无防火墙）确实执行（经 code-explorer 子 agent 深度验证）。`M_FASTFWD_OURS` 快速路径在默认配置下不会被触发，不会跳过裁剪。

### 与旧版 F-Stack 的差异

Issue #481 报告于 2020 年，当时 F-Stack 基于 FreeBSD 11.0。可能旧版本的 `ip_input` 没有裁剪逻辑或逻辑不同。当前 FreeBSD 15.0 的裁剪逻辑正确处理了以太网填充字节。

## 4. 修复方案

**无需修复。** 当前版本已正确处理以太网填充字节。
