## 3. ip_input 填充裁剪逻辑详解

### 代码 (ip_input.c:539-562)

```c
ip_len = ntohs(ip->ip_len);          // 从 IP 头读取实际 IP 包长度
if (__predict_false(ip_len < hlen)) {
    IPSTAT_INC(ips_badlen);
    goto bad;
}
if (__predict_false(m->m_pkthdr.len < ip_len)) {
    goto tooshort;
}
if (m->m_pkthdr.len > ip_len) {      // mbuf 比IP包长 → 有填充
    if (m->m_len == m->m_pkthdr.len) {  // 单段 mbuf
        m->m_len = ip_len;              // 直接截断
        m->m_pkthdr.len = ip_len;
    } else                              // 多段 mbuf
        m_adj(m, ip_len - m->m_pkthdr.len);  // 从尾部调整
}
```

### 执行条件验证（经 code-explorer 子 agent 深度验证）

1. **裁剪逻辑未被 #ifdef 排除**：`__predict_false` 只是分支预测提示，不影响编译
2. **F-Stack 版本与上游 FreeBSD 15.0 完全一致**：无任何 F-Stack 特有修改
3. **netisr 是同步直接调用**：`NETISR_DISPATCH_DIRECT` 模式，ether_demux → ip_input 是同步函数调用链
4. **M_FASTFWD_OURS 不触发**：默认 `V_ipforwarding=0`，`ip_tryforward()` 不被调用，`M_FASTFWD_OURS` 不会被设置
5. **pfil hook 不影响**：默认无防火墙注册 pfil hook，直接 `goto passin`

### LRO 路径

当 LRO 启用时，`tcp_lro_trim_mbuf_chain`（tcp_lro.c:444-476）会先裁剪填充：
```c
len = (IP头偏移 + ntohs(ip->ip_len));
if (m->m_pkthdr.len > len)
    m_adj(m, len - m->m_pkthdr.len);
```
LRO flush 后的包回到 ether_input → ip_input，此时填充已被 LRO 去除，ip_input 裁剪为 no-op。

测试环境 LRO=0（禁用），因此填充裁剪完全由 ip_input 执行。

## 4. TCP 层处理

### tcp_input.c:704

```c
tlen = ntohs(ip->ip_len) - off0;  // 从 IP 头计算，不依赖 mbuf 长度
```

`off0` = IP 头长度。`tlen` = IP payload 长度 = TCP 段总长。

### tcp_input.c:767

```c
tlen -= off;  // 减去 TCP 头长度，tlen = TCP payload 长度
```

`off = th->th_off << 2` = TCP 头长度。

### tcp_input.c:811

```c
drop_hdrlen = off0 + off;  // IP头 + TCP头 = 需要剥离的头部总长
```

### tcp_input.c:3183

```c
m_adj(m, drop_hdrlen);  // 剥离所有头部，剩余 = TCP payload
```

由于 ip_input 已裁剪填充，此时 `m_len - drop_hdrlen` = 精确的 TCP payload 长度，无填充残留。

## 5. 与旧版 F-Stack 的可能差异

Issue #481 报告于 2020 年，当时 F-Stack 可能基于 FreeBSD 11.0（推测，issue 未提供版本信息）。可能的原因：

1. **旧版 ip_input 可能没有裁剪逻辑**：FreeBSD 11.0 的 ip_input 可能在某些路径下不裁剪填充
2. **旧版 ether_demux 处理不同**：可能以太网头剥离方式不同
3. **旧版 F-Stack 的 ff_mbuf_gethdr 行为不同**：可能直接传递到协议栈而跳过某些处理

## 6. 修复方案

**无需修复。** 当前版本（FreeBSD 15.0）的 ip_input 填充裁剪逻辑正确工作，所有测试均通过。

如果未来需要在更早的层面（ff_mbuf_gethdr 或 ff_veth_input）添加防御性裁剪，可以考虑在 `ff_mbuf_gethdr` 中根据以太网类型和 IP 头 ip_len 校正 mbuf 长度。但这不是当前版本必需的。
