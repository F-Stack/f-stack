## 性能分析

1. **F-Stack 优化配置 vs 内核差距 3.2%** — 在测量误差范围内，F-Stack TCP 接收性能与内核持平
2. **delayed_ack=1 导致连接失败** — ACK 延迟 40ms + 窗口更新被阻止 = 接收窗口耗尽 → RST
3. **recvspace=8192 不影响** — 小缓冲区下 TCP 自动调整仍能维持高吞吐
4. **buffer_reads 差异** — F-Stack (1,048,701) 比内核 (974,798) 多约 7%，说明 F-Stack 每次 recv 返回的 bytes 略少（avg_bytes 3623 vs 3898），但总耗时接近
