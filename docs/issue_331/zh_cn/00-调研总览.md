# Issue #331 调研总览：kqueue EVFILT_TIMER 精度

## 1. Issue 摘要

- **#331**（2019-02-12 报告，OPEN）：kqueue `EVFILT_TIMER` 精度极差，用户设置 10 秒定时器，实际 30-100 秒才触发，偏差随运行时间增长而加剧。
- **#701**（2022-10-13，CLOSED）：用户自行定位根因——F-Stack 把 BSD callout 改造成接受 ticks 参数，kern_event.c 用相对 sbinuptime 的值导致偏差，hack 改绝对值初步解决。维护者称会检查，无正式修复。
- **#702**（2022-10-14，CLOSED）：rack/bbr PCB 内存泄漏，hpts skip_swi 编译期默认值修复。
- 维护者在 #331 评论称"#701/#702 应已修复但 commit 缺失"。

## 2. 调研结论

### 2.1 提交历史核查

| commit | 说明 | 是否修复 #331 |
|--------|------|---------------|
| `e592cbbfe`（2023-02-14，Ref #701 #702） | 只改 config.ini（bbr 推荐 hz 100000→1000000） | **否**（配置 workaround，未改代码） |
| `a816e8963`（2023-01-06，Fix #702） | 改 tcp_hpts.c skip_swi 编译期默认值 | **否**（修 PCB 泄漏，非 timer 精度） |

两个 commit 都在当前 HEAD（feature/1.26, 48fb0cdf1）中存在。维护者称"commit 缺失"——实际存在但都不是 timer 精度的代码修复。**#331 的代码 bug 至今未修。**

### 2.2 根因（双重 bug）

**Bug 1：callout 调度双重计算（精度问题，#331/#701 直接根因）**

- `freebsd/kern/kern_event.c:949-959` `filt_timerstart`：`kc->next = to + sbinuptime()`（手动算绝对 sbintime，基于 TSC）。
- `freebsd/kern/kern_event.c:787-792` `kqtimer_sched_callout`：`callout_reset_sbt_on(&kc->c, kc->next, ..., C_ABSOLUTE)` 传绝对 sbt。
- `freebsd/sys/callout.h:96-97` F-Stack 宏：`callout_reset_sbt_on(c, sbt, ...) = callout_reset_tick_on((c), (sbt)/tick_sbt, ...)` —— **忽略 C_ABSOLUTE**，绝对 sbt 转绝对 ticks。
- `lib/ff_kern_timeout.c:391` `callout_cc_add`：`c->c_time = ticks + to_ticks` —— 当 `to_ticks` 为绝对 ticks 时**双重计算**（`ticks` 是 F-Stack 启动后计数，`to_ticks` 是 TSC 尺度绝对 ticks，两者尺度不同）。

**Bug 2：普通 callout 轮从不被驱动（callout 永不触发，调研中发现）**

- `lib/ff_kern_timeout.c:355-357` `callout_tick`：`softclock(cc)` 调用在 `#ifndef FSTACK` 内 —— F-Stack 编译时（-DFSTACK）该调用为死代码，`softclock()` 从不被调用。
- F-Stack 只通过 `ff_tcp_hpts_softclock()`（主循环 `ff_dpdk_if.c:2811`）驱动 HPTS 轮，普通 callout 轮（EVFILT_TIMER、sleepq 等）**从不被处理**。
- 因此即使 Bug 1 修复（to_ticks 正确），callout 仍永不触发。

### 2.3 为何 TCP 定时器不受影响

- `lib/ff_stub_14_extra.c:149-153`：`callout_when` 是空函数 stub。
- `tcp_timer.c:920-923` 调 `callout_when` 后 sbt 保持相对 → 宏转相对 ticks → `c->c_time=ticks+相对` 正确（意外）。
- TCP 定时器实际由 HPTS 轮驱动（`ff_tcp_hpts_softclock`），不依赖普通 callout 轮。
- bug 只影响 kern_event.c EVFILT_TIMER（手动算绝对 + 依赖普通 callout 轮）。

## 3. 修复方案（两部分）

### 3.1 Bug 1 修复：kern_event.c kqtimer_sched_callout

将绝对 sbintime 用 sbinuptime()（同尺度）转为相对 ticks，直传 `callout_reset_tick_on`，绕过忽略 C_ABSOLUTE 的宏：

```c
static void
kqtimer_sched_callout(struct kq_timer_cb_data *kc)
{
    sbintime_t now = sbinuptime();
    int to_ticks = kc->next > now ? (kc->next - now) / tick_sbt + 1 : 0;
    callout_reset_tick_on(&kc->c, to_ticks, filt_timerexpire, kc->kn,
        kc->cpuid, 0);
}
```

### 3.2 Bug 2 修复：ff_kern_timeout.c callout_tick

移除 `#ifndef FSTACK` guard，使 `softclock(cc)` 在 F-Stack 下被调用，驱动普通 callout 轮。同时添加 `softclock` 前向声明。

## 6. hz 粒度说明

hz=100 → tick=10ms → EVFILT_TIMER 精度上限 10ms。用户可提高 hz 改善（如 hz=1000→1ms）。这是设计限制非 bug。
