# Issue #331 测试方案与环境

## 1. 测试环境

| 项目 | 配置 |
|------|------|
| 机器 | 双网卡，DPDK 独占网卡 IP <DPDK_NIC_IP> |
| 系统 uptime | 35 天（关键：sbinuptime 基于 TSC，bug 状态下定时器延迟 ≈ uptime） |
| F-Stack | feature/1.26 分支，FreeBSD 15.0 + DPDK 24.11.6 LTS |
| config.ini | hz=100，lcore_mask=1（单线程），TCP functions_default=freebsd |
| 内核栈测试 | 127.0.0.1 lo |
| DPDK 网卡测试 | ssh f-stack-client → <DPDK_NIC_IP> |

## 2. 测试程序

`example/evfilt_timer_test.c`（基于 #701 reproducer 改写）：
- ff_kqueue + EVFILT_TIMER(NOTE_SECONDS, 1)，1 秒周期定时器。
- loop 中 ff_kevent 取事件，用 clock_gettime(CLOCK_MONOTONIC) 独立测量 since_last 间隔。
- 每 10 次触发重设定时器（EV_ADD），测 reschedule 路径。
- 30 次触发后 exit(0)。

## 3. 测试矩阵

| 测试 | 目的 | 配置 | 预期 |
|------|------|------|------|
| 复现 | 确认 bug 存在 | bug 状态 lib（git stash 撤销修复） | 90s 内零触发（定时器延迟 ≈ uptime 35 天） |
| T1 | 验证精度修复 | 修复后 lib，1s 定时器 | 30 次触发，间隔 1.000s ± 10ms |
| T2 | 验证周期重设 | 同 T1，每10次 rearm | rearm 后间隔仍 ~1s |
| T3 | TCP 回归 | csum_test_server + f-stack-client echo | TCP echo 正常 |
| T4 | 默认配置回归 | 无额外配置 | F-Stack 正常启动 + TCP echo（T3 覆盖） |

## 4. 复现方法

1. `git stash push -- freebsd/kern/kern_event.c`（撤销 Bug 1 修复，回到 bug 状态）。
2. `make clean && make`（lib）+ 编译 evfilt_timer_test。
3. 运行 `./evfilt_timer_test --conf=config.ini --proc-type=primary --proc-id=0`，90s 超时。
4. 观察：仅 "START" 无 "TRIGGER"（零触发）。
5. `git stash pop` 恢复修复。

## 5. 验证方法

1. 修复后 `make clean && make` + 编译测试。
2. 运行 evfilt_timer_test，观察 TRIGGER 行的 since_last 值。
3. 运行 csum_test_server + f-stack-client python 客户端验证 TCP echo。

## 6. 关键观测点

- **EAL argv**：`f-stack -c1 -n4 --proc-type=primary`（无 extra_eal_args）。
- **DBG sched**（调试时）：`next`/`now` 为 sbintime（TSC 尺度），`to_ticks` 应为 ~100（1s/10ms）。
- **TRIGGER since_last**：修复后应稳定在 1.000，不随 uptime 增长。
