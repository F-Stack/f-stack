# 运行时实测报告

> 一切以实际执行为准，未实际执行不臆测。本文记录用 f-stack 自带 `tools/sbin/ifconfig`（DPDK secondary 进程）对运行中的 f-stack 网卡实测修改 MTU 的完整证据链。

## 1. 测试环境

- **被测进程**：运行中的 nginx_fstack（primary，`lcore_mask=10`，DPDK 设备 `0000:00:09.0`，绑定 `igb_uio`）。
- **DPDK 网卡**：virtio，`f-stack-0`，IP `<DPDK_NIC_IP>`。
- **测试工具**：`tools/sbin/ifconfig`，以 DPDK secondary 进程 attach 到 primary。
- **调用方式**：`FF_CONFIG=/usr/local/nginx_fstack/conf/f-stack.conf tools/sbin/ifconfig -p 0 f-stack-0 [mtu <N>]`
  - 工具用 `-p <proc_id>` 选定 primary，用 `FF_CONFIG` 指定与 primary 相同的 EAL 配置。

> 说明：日志中出现 `Device 0000:00:05.0 is not driven by the primary process` 属工具默认设备探测提示（`0000:00:05.0` 为内核态 eth1），不影响对 `0000:00:09.0` 上 `f-stack-0` 的 attach 与操作，实测均正常返回。

## 2. 基线：当前 MTU

```
$ ... ifconfig -p 0 f-stack-0
f-stack-0: flags=8843<UP,BROADCAST,RUNNING,SIMPLEX,MULTICAST> metric 0 mtu 1500
	inet <DPDK_NIC_IP> netmask 0xfffff800 broadcast <BROADCAST_IP>
	inet6 fe80::2290:6fff:fe7d:5d08 prefixlen 64 scopeid 0x2
	inet6 <DPDK_NIC_IPV6> prefixlen 128 autoconf
```
- 默认 **mtu 1500**（印证 `ether_ifattach` 初始化 `if_mtu=ETHERMTU`）。

## 3. 测试用例与结果

| 用例 | 命令（MTU 值） | 返回 | 结果 MTU | 结论 |
|---|---|---|---|---|
| T1 减小 | `... f-stack-0 mtu 1400` | exit=0，无报错 | `mtu 1400` | ✅ **成功** |
| T2 jumbo | `... f-stack-0 mtu 9000` | `ifconfig: ioctl SIOCSIFMTU (set mtu): Invalid argument`，exit=1 | 保持 `mtu 1400` | ❌ **失败(EINVAL)** |
| T3 略超标准 | `... f-stack-0 mtu 2000` | `ifconfig: ioctl SIOCSIFMTU (set mtu): Invalid argument`，exit=1 | 保持 `mtu 1400` | ❌ **失败(EINVAL)** |
| 恢复 | `... f-stack-0 mtu 1500` | exit=0 | `mtu 1500` | ✅ 已恢复 |

### 关键原始输出

**T1（减小 1500→1400，成功）**：
```
set1400_exit=0
mtu 1400
```

**T2（增大 →9000，失败）**：
```
ifconfig: ioctl SIOCSIFMTU (set mtu): Invalid argument
set9000_exit=1
mtu 1400          ← 未变化，设置被拒
```

**T3（增大 →2000，失败）**：
```
ifconfig: ioctl SIOCSIFMTU (set mtu): Invalid argument
set2000_exit=1
mtu 1400          ← 未变化，设置被拒
```

## 4. 实测与代码的对应关系

| 实测现象 | 对应代码 |
|---|---|
| 1400 设置成功 | `if_ethersubr.c:1181` `ifp->if_mtu = ifr->ifr_mtu`（≤ETHERMTU 分支） |
| 9000 / 2000 返回 `SIOCSIFMTU ... Invalid argument` | `if_ethersubr.c:1178-1179` `if (ifr->ifr_mtu > ETHERMTU) error = EINVAL`（>1500 分支） |
| 上限恰为 1500 | `ETHERMTU = 1500` |

实测 `EINVAL(22)` 与代码 `ether_ioctl` 的 `> ETHERMTU → EINVAL` 一一对应，证据链闭合。

## 5. 未覆盖项与诚实边界

- **未做**大帧端到端收发吞吐测试：因增大 MTU 在协议栈层即被 `EINVAL` 拒绝（`if_mtu` 无法置为 >1500），无法进入"发大帧"路径，故 jumbo 的端到端收发无从测起——这本身即证明 jumbo 不支持。
- 减小 MTU 后的连通性：`f-stack-0` 保持 `UP,RUNNING`，IP/IPv6 地址不变；减小 MTU 仅收紧本端分片/MSS，不破坏连通（符合 `03` 分析）。
- 本机 DPDK 为 virtio，jumbo 能力还受 PMD/vSwitch 限制；即便未来补齐 f-stack 代码，jumbo 真正可用仍需底层链路统一支持。

## 6. 实测结论

- **减小 MTU（≤1500）**：运行时可成功设置。✅
- **增大 MTU（>1500）**：运行时被 `EINVAL` 拒绝，上限锁定 1500。❌

与代码分析（`01`/`02`/`03`）、外网官方 issue（`04`）三方一致。
