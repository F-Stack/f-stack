# 完整支持 MTU 修改——接口与配置设计

## 1. 配置接口

### 1.1 `[dpdk]` 全局配置

```ini
[dpdk]
# Existing configurations omit this key and retain legacy MTU behavior.
mtu_enable=1
# Upper bound for runtime MTU changes; defaults to 9000 when mtu_enable=1.
max_mtu=9000
# large: one jumbo-capable mbuf; scatter: standard mbufs chained together.
mbuf_mode=large
```

| 配置项 | 类型 | 缺省 | 有效值 | 说明 |
|---|---|---|---|---|
| `mtu_enable` | bool/int | `0` | `0`,`1` | MTU/jumbo 功能总开关；旧配置零回归 |
| `max_mtu` | uint16 | 启用时 `9000` | 模式相关：large 须满足派生的 uint16 `data_room_size`；scatter 可到 65535；均须满足 PMD/frame 能力 | 运行时上限和 pool 容量依据 |
| `mbuf_mode` | enum/string | 启用时 `large` | `large`,`scatter` | mbuf 承载方式；非法字符串启动失败 |

设计说明：`max_mtu=9000` 只在 `mtu_enable=1` 的 feature scope 内作为缺省值。`mtu_enable=0` 时保持 `RTE_MBUF_DEFAULT_BUF_SIZE`，避免旧部署的内存占用突增。

### 1.2 `[portN]` 配置

```ini
[port0]
# Initial protocol-stack and DPDK-port MTU; defaults to 1500.
mtu=9000
```

| 配置项 | 缺省 | 约束 |
|---|---|---|
| `mtu` | `1500` | `IF_MINMTU <= mtu <= dpdk.max_mtu`；还需满足 PMD `min_mtu..max_mtu` |

- `mtu_enable=0` 且配置 `mtu>1500`：配置解析失败，提示需先启用 MTU 功能。
- `mtu_enable=1` 且 `mtu` 缺省：端口以 1500 启动，但 pool 已按所选模式为运行时增大预留能力。
- large 模式在配置校验期计算 `data_room_size = align(HEADROOM + max_mtu + L2_overhead)`；结果超过 `UINT16_MAX` 必须确定性失败，因此 `max_mtu=65535` 在 large 模式不可用。scatter 模式不创建 large room，可继续进入 PMD `max_mtu/max_rx_pktlen` 校验。
- 统一 frame 公式：`frame_bytes = L3_MTU + Ethernet header + configured VLAN/QinQ overhead + FCS`。large 比较 `frame_bytes` 与 `data_room_size - RTE_PKTMBUF_HEADROOM`；`max_rx_pktlen` 与 frame_bytes 比较；不得把含 headroom/alignment 的 pool 参数直接与设备 frame 能力混比。
- 多端口允许不同初始 `mtu`，但共享 pool 的 large 模式按全局 `max_mtu` 分配。

## 2. C 数据结构

### 2.1 `lib/ff_config.h`

在 `struct ff_config.dpdk`（当前 `ff_config.h:260-313`）增加：

```c
enum ff_mbuf_mode {
    FF_MBUF_MODE_LARGE = 0,
    FF_MBUF_MODE_SCATTER,
};

int mtu_enable;
uint16_t max_mtu;
enum ff_mbuf_mode mbuf_mode;
```

在 `struct ff_port_cfg`（当前 `ff_config.h:163`）增加：

```c
uint16_t mtu;
```

### 2.2 有效配置与能力快照

解析值与 PMD 能力值应分离。建议在 `struct ff_dpdk_if_context`（`ff_memory.h:60-65`）增加：

```c
uint16_t mtu;
uint16_t max_mtu;
enum ff_mbuf_mode mbuf_mode;
```

若实现需要记录设备能力，另建只读快照，避免把 `struct rte_eth_dev_info` 暴露给 FreeBSD 适配层：

```c
struct ff_mtu_capability {
    uint16_t min_mtu;
    uint16_t max_mtu;
    uint32_t max_rx_pktlen;
    uint32_t max_rx_bufsize;
    bool rx_scatter;
    bool tx_multi_segs;
};
```

## 3. 配置解析 API

### 3.1 缺省值

`ff_default_config()`（`ff_config.c:1366`）定义：

```c
cfg->dpdk.mtu_enable = 0;
cfg->dpdk.max_mtu = 9000;
cfg->dpdk.mbuf_mode = FF_MBUF_MODE_LARGE;
```

`struct ff_port_cfg` 分配后初始化 `mtu=1500`。注意当前 `port_cfg_handler()` 在第一次遇到 `[portN]` 时批量 `calloc`（`ff_config.c:550-567`），应在该初始化循环内设置每个启用 port 的默认 MTU。

### 3.2 严格解析

禁止直接用 `atoi()` 解析新增数值。新增内部 helper：

```c
int ff_parse_u16(const char *value, uint16_t min, uint16_t max,
    uint16_t *out);
int ff_parse_mbuf_mode(const char *value, enum ff_mbuf_mode *out);
```

要求：
- 使用 `strtoul()` 并检查 `errno`、`endptr`、范围；
- 拒绝空值、负值、尾随字符和溢出；
- 配置解析错误返回 0，使 `ini_parse()` 失败，而不是静默采用默认值。

`ini_parse_handler()`（`ff_config.c:976-1023`）增加 `[dpdk]` 分支；`port_cfg_handler()`（`ff_config.c:542`）增加 `mtu` 分支。

### 3.3 跨字段校验

解析完全部配置后执行独立 `ff_validate_mtu_config()`，避免配置顺序影响：

```c
if (!mtu_enable && any_port_mtu > ETHERMTU) error;
if (mtu_enable && max_mtu < ETHERMTU) error;
if (port.mtu < IF_MINMTU || port.mtu > max_mtu) error;
if (mtu_enable && mbuf_mode == LARGE &&
    ff_mtu_data_room_size(max_mtu, &room) != 0) error;
if (mtu_enable && kernel_coexist_or_kni_enabled) return EOPNOTSUPP;
```

PMD 能力校验必须放在 `rte_eth_dev_info_get()` 之后，不能在纯配置解析阶段臆测硬件能力。

## 4. DPDK 层接口

### 4.1 分层原则

`ff_veth.c` 已包含 `ff_dpdk_if.h`，但不得直接调用 `rte_eth_dev_*`。DPDK 细节封装在 `ff_dpdk_if.c`，对 `ff_veth` 暴露稳定接口：

```c
int ff_dpdk_if_get_mtu(struct ff_dpdk_if_context *ctx, uint16_t *mtu);
int ff_dpdk_if_set_mtu(struct ff_dpdk_if_context *ctx, uint16_t mtu);
int ff_dpdk_if_get_mtu_capability(struct ff_dpdk_if_context *ctx,
    struct ff_mtu_capability *cap);
```

- 返回值使用负 errno 风格（与 DPDK 一致）；`ff_veth_ioctl()` 必须通过统一 helper 转为 FreeBSD 正 errno：`ret < 0 ? ff_dpdk_errno_to_bsd(-ret) : 0`。已知 errno 保持语义，`ENOTSUP` 映射 `EOPNOTSUPP`，未知值归一为 `EIO`，禁止把负值返回 FreeBSD ioctl。
- `ff_dpdk_if_set_mtu()` **仅 primary 调用**；secondary 不调用本接口（不触达任何 DPDK 端口控制接口）。实现负责本 primary 进程内的动态 stop/set/start、回读和硬件回滚。
- `ff_veth_ioctl()` 只负责 ifnet 语义和软件状态事务，不感知 PMD 细节。

### 4.2 多进程 MTU 设置模型（无 IPC）

本期不实现跨进程 MTU 事务协调，进程间不通信、无事务、无 IPC 消息 rings/消息池。多进程一致性由“每进程各自设置一次”达成：

- primary：`ff_veth_ioctl(SIOCSIFMTU)` 内先 `ff_dpdk_if_set_mtu()` 设硬件 MTU（含 EBUSY→stop/set/start 与失败回滚），成功后 `if_setmtu()` 设软 MTU。
- secondary：`ff_veth_ioctl(SIOCSIFMTU)` 内仅 `if_setmtu()` 设软 MTU，不调用 `ff_dpdk_if_set_mtu()`／`rte_eth_dev_set_mtu`／stop/start。
- 每个进程各自触发一次 `SIOCSIFMTU`（应用/运维使用约定）；未在某 proc 设置时该 proc 软 MTU 保持旧值（已知约束）。

角色判定使用 `rte_eal_process_type() == RTE_PROC_PRIMARY`。

## 5. FreeBSD ifnet 接口

### 5.1 `ff_veth_ioctl()`

新增 `case SIOCSIFMTU`：

```c
case SIOCSIFMTU:
    error = ff_veth_change_mtu(sc, ((struct ifreq *)data)->ifr_mtu);
    break;
```

`ff_veth_change_mtu()` 负责：范围校验 → 按进程角色处理（primary：`ff_dpdk_if_set_mtu()` 设硬件成功后 `if_setmtu()`；secondary：仅 `if_setmtu()`，不触达 DPDK）→ 不做任何跨进程协调。运行时 ioctl 的 `if_notifymtu()` 由通用 `freebsd/net/if.c:2729-2755` 在驱动成功返回后统一触发，驱动不得重复通知。启动时则在 `ether_ifattach()` 后、`ff_veth_setaddr()` 以及任何路由/VLAN 建立前设置初始 `if_mtu`。不要修改 `freebsd/net/if_ethersubr.c`。

### 5.2 `SIOCGIFMTU`

保持现有 `if.c` 读取 `ifp->if_mtu` 的语义。调试门禁中额外调用 `ff_dpdk_if_get_mtu()` 比对硬件值；正常查询不应每次访问 PMD，避免热路径控制面调用。

## 6. ff_api 评估

本功能不新增 `ff_set_mtu()` 公共 API。理由：
- Linux/FreeBSD 已有标准 `ioctl(SIOCSIFMTU)` 语义；
- `tools/sbin/ifconfig` 与现有应用无需学习专用 API；
- 新增 API 会扩大维护面并绕开标准 ioctl 路径。

如后续需要无 socket 的管理 API，应复用同一按进程角色区分的设置路径（primary 软+硬、secondary 仅软），不得另建不一致路径。

## 7. 返回码

| 场景 | 对外 errno |
|---|---|
| MTU 超配置/设备上限 | `EINVAL` |
| PMD 不支持 set_mtu 或 scatter/multi-segs | `EOPNOTSUPP` |
| 运行中不可修改且协调 stop/start 失败 | `EBUSY` |
| 设备移除 | `EIO`/`ENODEV`（保留 DPDK 含义） |
| 回滚失败、单进程内软/硬件状态可能不一致 | `EIO`，并输出高优先级日志 |

### 向后兼容

未出现上述新配置时，与当前版本完全一致：MTU 1500、pool API 参数 `RTE_MBUF_DEFAULT_BUF_SIZE=2176`（含 128B headroom，可用 `RTE_MBUF_DEFAULT_DATAROOM=2048`）、无新增 offload、`>1500` 的 ioctl 仍返回 `EINVAL`。
