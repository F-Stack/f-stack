# 外网调研

> 调研 F-Stack 官方 issue、DPDK 文档与技术资料中关于"DPDK 接管网卡后修改 MTU / jumbo frame"的结论，并与本仓库代码交叉核对。冲突处以代码 + 运行时实测为准。

## 1. F-Stack 官方 GitHub Issue（权威、直接相关）

### 1.1 Issue #239 —— [Question] set MTU in example (helloworld)（2018-06，已关闭）

- 链接：https://github.com/F-Stack/f-stack/issues/239
- 提问：能否在 f-stack 中启用 jumbo frame（MTU=9000）？
- **维护者答复（搜索结果摘录）**："tools/ifconfig can set mtu. But there is a problem here, **the mtu value can not be more than 1500 for now**. We will fix it in the near future."
- 要点：
  - 官方确认 `tools/ifconfig` **可以设置 MTU**（印证本仓库 `tools/sbin/ifconfig` 可改 MTU）。
  - 官方明确 **MTU 不能超过 1500**（印证 `ether_ioctl` 的 1500 硬上限）。
  - 承诺"未来修复"，但截至 #720（2022）仍未实现。

### 1.2 Issue #720 —— Enabling jumbo frames in f-stack（2022-12，**至今 OPEN**，标签 `enhancement`）

- 链接：https://github.com/F-Stack/f-stack/issues/720
- 提问者原文（关键）：
  > "It seems like frame size later than 1500, because in function `ether_ifattach()` the `if_mtu` size is statically set to ETHERMTU"
  > "For now I am statically change the `if_mtu` value to `ETHER_MAX_LEN_JUMBO`, and call `rte_eth_dev_set_mtu()` afterwards. But this feels hacky ... having ether_ifattach read the configuration value somewhere maybe?"
  > "jumbo frame enables a 30% performance boost."
- 要点：
  - 直接指出根因在 `ether_ifattach()` 把 `if_mtu` 静态设为 `ETHERMTU`（与本仓库 `if_ethersubr.c:985` 完全一致）。
  - 社区 workaround = **手动改 `if_mtu` + 调 `rte_eth_dev_set_mtu()`**（正好对应本仓库缺失的两处：协议栈上限 + DPDK 下发）。
  - 该 issue 标签为 `enhancement` 且**至今未关闭 / 无官方合入 PR** → jumbo frame **官方仍不支持**。

> 提问者称 ETHERMTU "which is 1518" 为口误，`ETHERMTU=1500`、`ETHER_MAX_LEN=1518`；不影响结论。

## 2. DPDK 官方文档 / 通用实践

### 2.1 DPDK 设置 MTU 的标准 API

- DPDK 提供 `rte_eth_dev_set_mtu(port_id, mtu)` 设置端口 MTU；`rte_eth_dev_get_mtu` 读取。
- DPDK Test Plans《MTU Check Tests》(doc.dpdk.org) 说明 PMD 对 MTU 的支持需 PMD 实现 `mtu_set` 回调，并在 `rte_eth_dev_configure` 时通过 `rxmode.mtu` 指定。

### 2.2 启用 jumbo frame 的通用要求（OVS-DPDK 文档等）

- OVS-DPDK 文档《jumbo-frames.rst》(github.com/openvswitch/ovs)："By default, DPDK ports are configured with standard Ethernet MTU (1500B). To enable Jumbo Frames support for a DPDK port …" —— 即 **DPDK 端口默认 1500**，启用 jumbo 需：
  1. 显式设置更大的 MTU（`rte_eth_dev_set_mtu` / `rxmode.mtu`）。
  2. 放大 mbuf 数据区以容纳大帧（或启用 multi-segment/scatter 接收）。
  3. 底层 NIC / 虚拟交换机 / 对端也需统一支持 jumbo。
- 技术博客（CSDN/博客园关于 DPDK MTU、jumbo frame）一致指出：jumbo 需"物理交换机 + 虚拟交换机 + 端点"三处 MTU 统一，且 DPDK 侧需放大 mbuf、开启 scatter。

## 3. 外网结论与本仓库代码的交叉核对

| 外网结论 | 本仓库代码印证 | 是否一致 |
|---|---|---|
| tools/ifconfig 能设置 MTU | `tools/sbin/ifconfig` + `ff_syscall_wrapper.c:520` ioctl 转换 | ✅ 一致 |
| MTU 不能超过 1500 | `ether_ioctl`（`if_ethersubr.c:1178-1179`）硬上限 | ✅ 一致 |
| `ether_ifattach` 静态设 `if_mtu=ETHERMTU` | `if_ethersubr.c:985` | ✅ 一致 |
| jumbo 需 `rte_eth_dev_set_mtu` + 放大 mbuf | 本仓库 `ff_dpdk_if.c` 两者皆无 | ✅ 一致（f-stack 确实缺失） |
| jumbo 官方仍不支持（#720 OPEN） | 代码中无任何 jumbo/set_mtu 实现 | ✅ 一致 |

## 4. 小结

外网权威资料（尤其 F-Stack 官方 issue #239 / #720）与本仓库代码、运行时实测**三方完全一致**：
- 减小 MTU（≤1500）可通过 `tools/ifconfig` 设置。
- 增大 MTU（jumbo）官方从未实现，需按社区 workaround 手动改 `if_mtu` 上限并补 `rte_eth_dev_set_mtu` + 放大 mbuf 才可能支持。
