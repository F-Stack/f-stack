# 完整支持 MTU 修改——实施与代码改动详设

## 1. 实施原则

1. 不修改 `freebsd/net/if_ethersubr.c`；在 `lib/ff_veth.c` 适配层突破传统 1500 上限。
2. FreeBSD/veth 层不得直接依赖 `rte_eth*`；所有 DPDK 控制封装在 `ff_dpdk_if.c`。
3. 启动配置必须在 `rte_eth_dev_configure()`/`rte_eth_dev_start()` 的正确顺序中完成。
4. 动态修改（primary）必须具备本进程内控制面串行化、数据面 quiesce 和失败回滚；不做跨进程同步。
5. `large` 和 `scatter` 是显式策略；不做隐式降级。

## 2. M1：配置与数据结构

### 2.1 `lib/ff_config.h`

锚点：
- `struct ff_port_cfg`：`ff_config.h:163-204`；
- `struct ff_config.dpdk`：匿名内嵌结构，`ff_config.h:258-313`。

改动：
- 增加 `enum ff_mbuf_mode`；
- `dpdk` 增加 `mtu_enable/max_mtu/mbuf_mode`；
- `ff_port_cfg` 增加 `uint16_t mtu`。

为最小 diff，本次不要求把匿名 `dpdk` 结构抽成具名类型；若后续多个模块需要直接传递完整配置，再单独重构。

### 2.2 `lib/ff_config.c`

- `ff_default_config()`（L1366）设置 `mtu_enable=0,max_mtu=9000,mbuf_mode=large`。
- `[dpdk]` 键由 `ini_parse_handler()` 的 `MATCH` 链直接解析（L976 起），当前并不存在独立 `dpdk_cfg_handler()`，实现不得引用不存在的函数。
- `port_cfg_handler()`（L542）在 `calloc` 后为启用端口设置 `mtu=1500`。
- 增加严格解析 helper，不用 `atoi()`。
- `ff_check_config()` 增加跨字段校验。

伪代码：

```c
if (MATCH("dpdk", "mtu_enable"))
    return parse_bool(value, &cfg->dpdk.mtu_enable);
else if (MATCH("dpdk", "max_mtu"))
    return parse_u16(value, ETHERMTU, UINT16_MAX, &cfg->dpdk.max_mtu);
else if (MATCH("dpdk", "mbuf_mode"))
    return parse_mbuf_mode(value, &cfg->dpdk.mbuf_mode);
```

`ff_check_config()` 必须执行模式相关交叉校验：large 的 `ff_mtu_data_room_size(max_mtu)` 若因 uint16 pool API 上限返回 ERANGE，则启动前失败；scatter 不做该 room 分配，而在端口探测期校验 PMD frame 能力。`mtu_enable=1` 与 KNI/内核共存同时启用时返回 EOPNOTSUPP 语义并提示关闭其一。

错误信息必须包含 section/key/value 和合法范围，但不得包含无关配置。

## 3. M2：mbuf pool 双模式

### 3.1 现有顺序

`ff_dpdk_if.c` 当前顺序：
- `init_mem_pool()`：L385-452；pool 创建 L427-430；
- 之后 `init_port_start()`：L650 起；
- 端口能力 `rte_eth_dev_info_get()`：L702；
- configure：L856；queue setup：L878/L886；start：L918。

因此 pool 创建早于逐端口能力探测。全局 `max_mtu/mbuf_mode` 可决定 pool 大小，但各 PMD 能力必须在端口配置阶段再次严格验证。

### 3.2 large 模式 data room

统一 helper：

```c
static int
ff_mtu_data_room_size(uint16_t max_mtu, uint16_t *out)
{
    size_t frame = (size_t)max_mtu + RTE_ETHER_HDR_LEN +
        2 * RTE_VLAN_HLEN + RTE_ETHER_CRC_LEN;
    size_t room = RTE_PKTMBUF_HEADROOM + frame;
    room = RTE_ALIGN_CEIL(room, RTE_CACHE_LINE_SIZE);
    if (room > UINT16_MAX)
        return -ERANGE;
    *out = (uint16_t)room;
    return 0;
}
```

- `rte_pktmbuf_pool_create(..., data_room_size, ...)` 使用该结果。该参数为 uint16，large 模式须在配置校验阶段提前调用同一 helper；`max_mtu=65535` 必须确定性失败，不得截断。
- legacy pool API 参数 `RTE_MBUF_DEFAULT_BUF_SIZE=2176`（含 128B headroom），可用 `RTE_MBUF_DEFAULT_DATAROOM=2048`。
- 在大内存分配前记录估算：`nb_mbuf * data_room_size`，检查乘法溢出。
- 不将 frame overhead 与 IP MTU 混淆；`max_mtu` 是 L3 MTU。

### 3.3 scatter 模式

- pool 保持 `RTE_MBUF_DEFAULT_BUF_SIZE`。
- 端口能力验证：

```c
if (!(dev_info.rx_offload_capa & RTE_ETH_RX_OFFLOAD_SCATTER) ||
    !(dev_info.tx_offload_capa & RTE_ETH_TX_OFFLOAD_MULTI_SEGS))
    return -ENOTSUP;
port_conf.rxmode.offloads |= RTE_ETH_RX_OFFLOAD_SCATTER;
port_conf.txmode.offloads |= RTE_ETH_TX_OFFLOAD_MULTI_SEGS;
```

- `rxq_conf.offloads` 与 `txq_conf.offloads` 已在 L877/L885 从 port mode 继承，无需重复裸赋值。
- 当前 RX 已遍历 `rte_mbuf->next`（`ff_dpdk_if.c:1557-1588`）；TX 已创建多段 rte_mbuf（L2209-2249、L2333-2364），但实现任务仍须逐条验证：`pkt_len/nb_segs/data_len/next` 正确、部分分配失败释放完整、零拷贝 ext mbuf 生命周期正确。

### 3.4 large TX 单段化与 zero-copy

现有 copy/raw TX 路径按固定 `RTE_MBUF_DEFAULT_DATAROOM` 分段；large 模式必须改为按每个新 mbuf 的实际 `rte_pktmbuf_tailroom()` 填充。对一个可容纳于 large room 的 9000 MTU frame，普通 copy/raw 路径必须产生 `nb_segs==1`，否则 large 模式失去设计价值且仍依赖 MULTI_SEGS。

page-array/zero-copy 路径可能天然形成多段：
- PMD 支持 `RTE_ETH_TX_OFFLOAD_MULTI_SEGS` 时允许多段，并验证段数/引用生命周期；
- PMD 不支持时，large 模式必须回退为单个 large mbuf copy（不是切换 scatter），或在该 zero-copy API 上返回 EOPNOTSUPP；实现阶段必须选定并单测，推荐 copy fallback 保持功能可用。
- scatter 模式始终要求 TX_MULTI_SEGS。

## 4. M2：端口能力与启动 MTU

### 4.1 DPDK 24.11 能力字段

当前头文件已确认：
- `rte_eth_rxmode.mtu`：`dpdk/lib/ethdev/rte_ethdev.h:427-430`；
- `dev_info.min_mtu/max_mtu/max_rx_bufsize/max_rx_pktlen`：L1778-1790；
- scatter/multi-segs：L1562/L1612；
- get/set MTU：L3637/L3656。

`max_rx_bufsize` 是不含 rte_mbuf headroom 的单 RX buffer 能力，不能等同端口 MTU；large 比较 `data_room_size - RTE_PKTMBUF_HEADROOM` 与 frame bytes/device buffer capability。`max_rx_pktlen` 是 L2 frame length 上限，必须与 `L3 MTU + Ethernet/VLAN/FCS overhead` 比较，不能直接与 L3 MTU 比较；pool alignment/padding 不得造成误拒绝。

### 4.2 `init_port_start()` 插入点

在 `rte_eth_dev_info_get()` 成功、`rte_eth_dev_configure()` 之前：

```c
requested = pconf->mtu;
frame_bytes = ff_mtu_frame_bytes(requested, vlan_depth);
if (requested < dev_info.min_mtu || requested > dev_info.max_mtu)
    return -EINVAL;
if (requested > ff_global_cfg.dpdk.max_mtu ||
    frame_bytes > dev_info.max_rx_pktlen)
    return -EINVAL;
if (mbuf_mode == FF_MBUF_MODE_LARGE &&
    frame_bytes > ff_large_usable_room(data_room_size))
    return -EINVAL;
port_conf.rxmode.mtu = requested;
configure_mtu_offloads(&port_conf, &dev_info, mbuf_mode);
```

启动时首选 `port_conf.rxmode.mtu`；在端口尚未 start 时调用 `rte_eth_dev_set_mtu()` 并回读，以覆盖 PMD 对 configure 字段处理差异：

```c
ret = rte_eth_dev_configure(...);
if (ret == 0)
    ret = rte_eth_dev_set_mtu(port_id, requested);
if (ret == 0)
    ret = rte_eth_dev_get_mtu(port_id, &actual);
if (ret || actual != requested)
    fail_port_init();
```

调用顺序必须在 `rte_eth_dev_start()`（L918）前；部分 PMD 在 started 状态返回 `-EBUSY`。

### 4.3 virtio 特性

当前 DPDK virtio PMD：
- `virtio_mtu_set()`：`drivers/net/virtio/virtio_ethdev.c:548`；
- `VIRTIO_NET_F_MTU` 能力：`virtio_ethdev.h:30`；
- `dev_info.max_mtu`：`virtio_ethdev.c:2630`；
- scatter/multi-segs 能力：L2635/L2648。

后续测试必须读取实际 `dev_info`，不能仅因源码存在能力就断言当前 backend 支持 9000。

## 5. M3：DPDK MTU 控制封装

### 5.1 公共接口

在 `ff_dpdk_if.h` 新增不暴露 DPDK 类型的接口（详见 `08`）。`ff_dpdk_if_set_mtu()` 内部从 opaque context 获取 `port_id`（context 当前在 `ff_memory.h:60-65` 保存该字段）。接口返回 DPDK 风格负 errno；`ff_veth_ioctl()` 必须经统一 `ff_dpdk_errno_to_bsd()` 转成 FreeBSD 正 errno：`ENOTSUP→EOPNOTSUPP`，未知错误→`EIO`，禁止把负值直接返回 ioctl。

### 5.2 运行态快速路径与 EBUSY

首先尝试在 primary 上直接 `rte_eth_dev_set_mtu()`：
- 成功：回读验证，完成；
- `-EBUSY`：进入显式 quiesce/stop/set/start 状态机；
- `-ENOTSUP/-EINVAL/-EIO/-ENODEV`：原样转换并保持旧状态。

DPDK 文档明确 `set_mtu` 可返回 `-EBUSY`（`rte_ethdev.h:3647-3655`）；virtio/MLX5 可能运行态成功，i40e/ice 明确可能要求 stopped。不得假定所有 PMD 相同。

### 5.3 stop/set/start 状态机

为每个 port 增加控制状态与锁：

```c
enum ff_port_ctrl_state {
    FF_PORT_RUNNING,
    FF_PORT_QUIESCING,
    FF_PORT_RECONFIGURING,
    FF_PORT_FAILED,
};
```

流程（仅 primary 进程内，quiesce 范围限本 primary 进程的多 lcore，不涉及其他 proc）：
1. CAS/锁把端口从 RUNNING 置 QUIESCING，拒绝本进程内并发 MTU 修改；
2. 通知本 primary 进程的所有 lcore 停止从该 port 收包/发包；
3. flush `tx_mbufs`，等待 in-flight burst 完成并设超时；
4. primary 执行 `rte_eth_dev_stop()`；
5. `rte_eth_dev_set_mtu(new)` + `get_mtu` 回读；
6. `rte_eth_dev_start()`；恢复 promiscuous/RSS 等 PMD 不保证保留的状态；
7. 恢复 lcore 数据面，状态 RUNNING。

失败回滚：set/start 任一步失败，尝试 stopped 状态恢复 old MTU 并 start；仍失败则状态 `FF_PORT_FAILED`、接口保持 down、返回 `EIO` 并输出高优先级日志。禁止带病恢复数据面。

## 6. M3：ff_veth ioctl 事务

`ff_veth_softc`（`ff_veth.c:69-93`）已有 `host_ctx`；无需复制 `port_id`。启动时 `ff_veth_setup_interface()` 必须在 `ether_ifattach()` 返回后、`ff_veth_setaddr()` 以及任何路由/VLAN 创建前设置配置 `if_mtu`，确保地址/MSS/路由从首次可见起即使用正确值。在 `ff_veth_ioctl()`（L234-253）增加 `SIOCSIFMTU`：

```c
case SIOCSIFMTU:
    mtu = ((struct ifreq *)data)->ifr_mtu;
    if (!ff_global_cfg.dpdk.mtu_enable) {
        error = ether_ioctl(ifp, cmd, data);
        break;
    }
    error = ff_veth_validate_mtu(sc, mtu);
    if (error != 0)
        break;
    if (rte_eal_process_type() == RTE_PROC_PRIMARY) {
        dpdk_ret = ff_dpdk_if_set_mtu(sc->host_ctx, mtu);
        error = dpdk_ret < 0 ? ff_dpdk_errno_to_bsd(-dpdk_ret) : 0;
        if (error == 0)
            if_setmtu(ifp, mtu);      /* primary: 先硬件成功，再提交软件值 */
    } else {
        if_setmtu(ifp, mtu);          /* secondary: 仅设软 MTU，不触达 DPDK */
    }
    break;
```

按进程角色区分（`rte_eal_process_type()`）：
- primary：先 `ff_dpdk_if_set_mtu()`（硬件，含 EBUSY→stop/set/start 与回滚）成功后再 `if_setmtu()`（软件），**先硬件成功再提交软件值**。
- secondary：仅 `if_setmtu()`（软件），不调用 `ff_dpdk_if_set_mtu`／不触达 DPDK 端口控制。硬件 MTU 由 primary 唯一负责。

通用 `if.c:2729-2755` 会在驱动 ioctl 返回成功且 MTU 变化后执行 `if_notifymtu()`；驱动层不要重复通知。

只有 `mtu_enable==0` 才继续走 `ether_ioctl()` 兼容路径。功能启用后，primary 的所有合法 MTU（包括 1500、1400 以及从 9000 回落）都必须先设硬件再设软件，避免本进程内软件 MTU 回落而硬件仍为 jumbo 的不一致；不做跨进程事务。多进程一致性通过每进程各自设置达成（见第 7 节）。

## 7. M4：多进程 MTU 一致性（无 IPC 协调）

### 7.1 静态一致性模型

本期不实现跨进程 MTU IPC 事务协调。多进程 MTU 一致性通过“每个 f-stack 进程各自在启动/运行时各调用一次 MTU 设置”达成，进程间不通信、无事务、无消息 rings/消息池：

- 只有 DPDK primary 能执行端口 stop/config/start 及 `rte_eth_dev_set_mtu`。
- primary 收到 `SIOCSIFMTU`：设硬件 MTU（含 EBUSY 状态机与回滚）成功后设本进程软 MTU。
- secondary 收到 `SIOCSIFMTU`：仅设本进程软 MTU，不触达任何 DPDK 端口控制接口。
- 当前工具 ioctl 通过 `FF_IOCTL` 只发给 `-p` 指定的单 proc（`tools/compat/ioctl.c:101-146`）；本期即以此为准：需在每个 proc 分别执行一次设置。

### 7.2 使用约定与已知约束

- 应用/运维需对每个 f-stack 进程分别触发一次 `SIOCSIFMTU`（例如对每个 `-p` 目标各执行一次 `tools/sbin/ifconfig`）。
- 未在某 proc 设置时，该 proc 的软 MTU 视图保持旧值；本期不以 IPC 弥补，属已知使用约束。
- 硬件 MTU 是共享状态，由 primary 唯一负责，只需在 primary 设置一次。

### 7.3 为何本期不做 IPC 协调

范围收敛决策：跨进程 request/prepare/commit/ack 两阶段事务、专用消息 rings/消息池、协调器等 IPC 机制复杂度与风险高，本期完全不做，降级为后续独立里程碑。当前以静态“每进程各设一次”模型满足一致性需求。

### 7.4 bond/vdev 与 KNI

- bond/vdev 由 primary 在本进程内处理：先收集所有 member 能力，上限取最小值；对各 member 依次 `set_mtu`，任一失败逆序回滚已修改成员（primary 进程内操作，无跨进程事务）。
- vdev 由其 PMD `dev_info`/`set_mtu` 决定，禁止硬编码设备名称判断。
- 本期不实现 KNI/内核共存接口联动：`ff_check_config()` 检测 `mtu_enable=1` 与 KNI/内核共存同时启用时返回 `EOPNOTSUPP` 语义并给出关闭建议，防止内核接口与 DPDK/ifnet MTU 不一致。

## 8. M5：日志与观测

启动日志：

```text
port=0 mtu_enable=1 requested_mtu=9000 max_mtu=9000 mbuf_mode=large data_room=...
```

运行时成功：

```text
port=0 mtu change old=1500 new=9000 mode=large path=runtime
```

失败：

```text
port=0 mtu change failed old=1500 new=9000 stage=set_mtu dpdk_errno=-16 rollback=success
```

使用 `ff_log()`；不在热路径逐包打印。

## 9. 单元测试 seam

- `test_ff_config.c`：默认、合法配置、非法 mode、非数字/负数/溢出、`port.mtu>max_mtu`、功能未启用却请求 jumbo。
- `test_ff_dpdk_if.c`：wrap `rte_eth_dev_set_mtu/get_mtu/stop/start`，覆盖 primary set_mtu 状态机的成功、`EBUSY`→stop/set/start、`ENOTSUP`、回读不一致、回滚成功/失败。
- veth ioctl 测试：区分 primary/secondary 分支——primary mock `ff_dpdk_if_set_mtu`，证明失败不改 `if_mtu`、成功后才提交软件值；secondary 只改 `if_mtu` 且不调用 `ff_dpdk_if_set_mtu`。
- multi-seg 测试：链长、`pkt_len/nb_segs/data_len`、部分分配失败、释放计数。

## 10. 明确禁止

- 不在 `ff_veth.c` include `rte_ethdev.h`。
- 不先改 `if_mtu` 再尝试硬件设置。
- 不因 PMD 不支持 large/scatter 而静默回退另一模式。
- 不允许 secondary 直接 stop/start 共享端口。
- 不修改 `freebsd/net/if_ethersubr.c` 解除全局上限。
