# 软硬件断层与差异分析

> 综合 `01-协议栈层分析.md`（软件层）与 `02-DPDK硬件层分析.md`（硬件层），本文分析"减小 MTU"与"增大 MTU"两种场景的不同后果与断层本质。

## 1. 断层本质

f-stack 的 MTU 处理存在两个相互独立、且都未打通到硬件的环节：

```
应用 ff_ioctl(SIOCSIFMTU)
   │  ff_syscall_wrapper.c:520 (LINUX_SIOCSIFMTU→SIOCSIFMTU)
   ▼
if.c:2729 (priv_check + IF_MINMTU/IF_MAXMTU 宽校验)
   │
   ▼
ff_veth_ioctl (ff_veth.c:248 default 分支)
   │
   ▼
ether_ioctl (if_ethersubr.c:1178)
   ├── ifr_mtu ≤ 1500 → 写 ifp->if_mtu（软件值）✅
   └── ifr_mtu > 1500 → EINVAL ❌（硬上限）
   │
   ✗ 断层：没有任何路径调用 rte_eth_dev_set_mtu
   ▼
DPDK 端口硬件 MTU 恒为 PMD 默认（1500），mbuf buf=2048
```

**断层点**：协议栈层修改的 `if_mtu` 是**纯软件值**，不会下发到 DPDK 硬件端口。f-stack 缺少"软件 MTU 变更 → `rte_eth_dev_set_mtu` 硬件下发"的桥接。

## 2. 减小 MTU（≤1500）：可用

**协议栈层**：`ether_ioctl` 接受，写入 `if_mtu`（`if_ethersubr.c:1181`）。之后协议栈按更小的 `if_mtu` 进行 TCP MSS 协商、IP 分片决策——即出方向的数据按新的更小 MTU 组织。

**硬件层**：DPDK 端口 MTU 仍是 1500，mbuf buf=2048。由于新 MTU（如 1400）**小于**硬件承载能力，硬件收发不受任何影响：
- 发送：协议栈已按 ≤1400 组织报文，帧长更小，硬件正常发送。
- 接收：硬件仍能收 ≤1500 的帧，协议栈按 `if_mtu` 处理。

**结论**：减小 MTU **可用**。软硬件断层在"减小"方向无害——因为硬件的承载能力（1500/2048）本就 ≥ 新的软件 MTU。运行时实测 1400 设置成功、连通正常（见 `05-运行时实测报告.md`）。

> 注意：减小 MTU 只改变本端协议栈的分片/MSS 行为，不改变硬件；这与"物理链路 MTU"是两个概念。对减小场景无副作用。

## 3. 增大 MTU（>1500，jumbo）：不支持

**协议栈层**：`ether_ioctl` 对 `ifr_mtu > ETHERMTU(1500)` 直接 `EINVAL`（`if_ethersubr.c:1178-1179`）。请求在**协议栈层就被拒绝**，`if_mtu` 保持不变。运行时实测 9000、2000 均返回 `Invalid argument`。

**即使绕过协议栈上限**（例如直接改 `ether_ifattach` 的 `if_mtu`，如 issue #720 的 hacky 做法），硬件层仍会失败：
- mbuf `data_room_size` 固定 2048，无法承载 9000B 帧（`ff_dpdk_if.c:430`）。
- 端口 `rxmode` 未配 jumbo/scatter、未调 `rte_eth_dev_set_mtu`，PMD 按 1500 初始化。
- 收方向：>1500 的帧会被 PMD 丢弃或截断；发方向：单 mbuf 装不下大帧且未启用分段。

**结论**：增大 MTU **不支持**，且是"协议栈上限 + 硬件缺口"双重阻断，两处都需改造才能支持（见 `06-方案与结论.md`）。

## 4. 与三层架构文档/知识图谱的一致性核对

- 三层架构文档（`docs/03-LAYER3-FUNCTIONS.md` 等）描述 `ff_veth_ioctl`/`ff_syscall_wrapper` 的 ioctl 转换职责，与本调研一致；文档未单列 MTU 能力，本调研补充明确"MTU 修改仅软件层、≤1500"。
- 知识图谱（`KNOWLEDGE_GRAPH_WIKI.md`）未记录 MTU/jumbo 相关符号；本调研新增结论可作为增量补充（若后续需要）。
- **一致性原则**：如文档与代码有出入，以本调研引用的实际代码 `文件:行号` 为准。

## 5. 差异总结表

| 维度 | 减小 MTU（≤1500） | 增大 MTU（>1500 jumbo） |
|---|---|---|
| 协议栈层 `ether_ioctl` | 接受，写 `if_mtu` | `EINVAL` 拒绝 |
| 是否下发 DPDK 硬件 | 否（但无害） | 否（且有害） |
| mbuf 2048 能否承载 | 能（新 MTU 更小） | 不能 |
| PMD 端口默认 1500 | 兼容 | 不兼容 |
| 运行时实测 | 成功 | 失败（EINVAL） |
| 总体结论 | ✅ 支持 | ❌ 不支持 |
