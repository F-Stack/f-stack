# 完整支持 MTU 修改——里程碑与工作清单

## 1. 执行原则

- 每个里程碑独立提交、独立门禁；门禁失败必须打回上一步修复。
- 同一步骤 bounce 最多 3 次，仍失败转人工决策。
- 代码编写者与 reviewer 必须不同 agent。
- 本文是后续编码任务清单，本次 spec 任务不执行这些步骤。

## M2：DPDK 启动路径与双 mbuf 模式

### 工作项
- large data room 计算 helper、溢出与内存估算。
- scatter 能力检查与 RX_SCATTER/TX_MULTI_SEGS 配置。
- 设置 `port_conf.rxmode.mtu`，按 frame bytes 校验 `max_rx_pktlen` 和 large 可用 room，启动前 set/get MTU。
- 审核 RX/TX 多段 mbuf 转换和失败释放路径。
- large 普通 copy/raw TX 改为按实际 tailroom 填充，9000 frame 在 large room 内必须单段；page-array/zero-copy 明确 TX_MULTI_SEGS capability 或 copy fallback。
- 扩展 `test_ff_dpdk_if.c` wrappers。

### DoD
- large/scatter 两模式均完成确定性单测。
- PMD 能力不足时启动失败，不静默降级。
- large 9000 普通 copy/raw TX `nb_segs==1`；scatter 段数按实际 tailroom，`pkt_len/nb_segs/data_len` 一致。
- `mtu_enable=0` 生成与旧版相同 data room/offload/端口配置。
- ASan/Valgrind（可运行范围内）无泄漏、越界、双重释放。

### 门禁
- DPDK capability 与配置交叉验证；所有错误码覆盖。
- reviewer 逐条核对 `pkt_len/nb_segs/data_len/next`。

### 回滚点
- 功能由 `mtu_enable=0` 可运行时关闭；代码回退 M2 commit 恢复旧 pool。

## M3：ff_veth 软件 MTU 与 DPDK 封装

### 工作项
- `ff_dpdk_if.h/.c` 增加 opaque MTU get/set/capability API与 DPDK负 errno→FreeBSD正 errno helper。
- `ff_veth_ioctl` 拦截 `SIOCSIFMTU`；只有功能关闭时走 legacy；启用后包括1500/1400/回落均先硬件事务后软件提交。
- `ff_veth_setup_interface` 在 `ether_ifattach()` 后、地址/路由/VLAN 建立前设置配置 MTU。
- 单测成功/失败/EBUSY/回读不一致/未知errno→EIO，验证软件不分裂。

### DoD
- 启动时 `if_mtu == rte_eth_dev_get_mtu == port.mtu`。
- 运行态 PMD 原生支持 set_mtu 时 1500↔9000 成功。
- `mtu_enable=0` 与 ≤1500 legacy 路径零回归。

### 门禁
- `ff_veth.c` 不出现 `rte_eth*` 符号；FreeBSD 树无修改。
- reviewer 验证错误返回与 `if_notifymtu` 不重复。

### 回滚点
- 关闭功能开关恢复 legacy；必要时回退 M3 commit。

## M4：多进程 MTU 一致性（无 IPC）与 EBUSY 控制状态机

### 工作项
- `ff_veth_ioctl(SIOCSIFMTU)` 按 `rte_eal_process_type()` 区分 primary/secondary 分支：primary 设软+硬、secondary 仅设软。
- primary 内新增 per-port control state/lock 与本进程 dataplane quiesce；实现 stop/set/get/start 和失败回滚（仅 primary 进程内）。
- bond member（primary 内）依次 set 与逆序回滚。
- 文档化“每进程各设一次”使用约定与已知约束（未设置的 proc 软 MTU 保持旧值）。
- 本期不实现跨进程 IPC 事务：不新增 MTU 消息 rings、共享消息池、transaction/coordinator。
- 测试：primary EBUSY→stop/set/start 与回滚、secondary 仅改软 MTU、本进程内并发 ioctl 串行化。

### DoD
- i40e/ice 类 `EBUSY` PMD 可通过 primary 内安全 stop/set/start 修改。
- 每个 proc 各自设置后各 proc 软 MTU 视图一致；硬件 MTU 由 primary 唯一设置；无跨进程事务代码。
- secondary 分支不调用任何 DPDK 端口控制接口。
- 端口重启后 RSS/promiscuous/VLAN 等状态符合基线。

### 门禁
- 压测期间（单/主进程）连续 MTU 往返，无死锁、无悬挂、无端口半恢复。
- primary 状态机 EBUSY/回滚用例通过；grep 确认无 request/prepare/commit/ack 事务、rings、transaction、coordinator 残留。

### 回滚点
- 控制状态机失败时恢复旧 MTU；无法恢复则接口 down 并停止推进。

## 2. 依赖关系

```text
M0 → M1 → M2 → M3 → M4 → M5
```

- M2 依赖 M1 配置字段。
- M3 依赖 M2 已为 max_mtu 预留数据面能力。
- M4 依赖 M3 单进程内事务正确（M4 不引入跨进程 IPC 事务）。
- 禁止跳过 M2 直接解除 `ether_ioctl` 上限，否则产生软硬件分裂。
