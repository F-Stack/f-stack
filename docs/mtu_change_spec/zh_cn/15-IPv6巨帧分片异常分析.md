# 15 — IPv6 巨帧分片异常分析

> 本文件分析 f-stack `mtu_enable=1` 配置 MTU=9000 后，**不开 KNI（走用户态 FreeBSD 协议栈回包）时 IPv6 echo reply 被按 1448 字节分片**的根因。
> 所有结论以实际代码 file:line 为准（FreeBSD 15.0 用户态协议栈 + f-stack lib 层），外网资料交叉验证。
> 本轮为纯调研分析，不改代码、不提交。

---

## 一、现象

| 测试项 | 结果 |
|--------|------|
| IPv4 双向 8500 ping | 正常（不分片）|
| IPv6 收 8500 ping（开 KNI，走内核栈）| 正常 |
| IPv6 收 8500 ping（**不开 KNI**，走用户态 FreeBSD 协议栈回包）| **回包被拆分为 6 个 1448 字节分片** |

物理机 `ff_ifconfig`：
```
f-stack-0: flags=8843<UP,BROADCAST,RUNNING,SIMPLEX,MULTICAST> metric 0 mtu 9000
    inet6 2402:4e00:2e80:1030::b prefixlen 64 autoconf
    nd6 options=123<PERFORMNUD,ACCEPT_RTADV,AUTO_LINKLOCAL,NO_DAD>
```

客户端 `ping6 -M do -s 8500 2402:4e00:2e80:1030::b` 抓包：
```
IP6 ::c > ::b: ICMP6, echo request, seq 1, length 8508
IP6 ::b > ::c: frag (0|1448)  ICMP6, echo reply, seq 1, length 1448
IP6 ::b > ::c: frag (1448|1448)
IP6 ::b > ::c: frag (2896|1448)
IP6 ::b > ::c: frag (4344|1448)
IP6 ::b > ::c: frag (5792|1448)
IP6 ::b > ::c: frag (7240|1268)
```
6 片：`1448×5 + 1268 = 8508`（8500 payload + 8 ICMP6 header）。

## 二、抓包数字反推

分片 size 计算见 `freebsd/netinet6/ip6_output.c:1204`：
```c
len = (mtu - unfragpartlen - sizeof(struct ip6_frag)) & ~7;
```
- `unfragpartlen` = 40（IPv6 header，无扩展头时）
- `sizeof(struct ip6_frag)` = 8（分片头）
- `& ~7` = 8 字节对齐

反推 `mtu`：
- 若 `mtu=1500`：`len = (1500-40-8)&~7 = 1452&~7 = 1448`（1452=0b10110101100，`&~7`=0b10110101000=1448）✓
- 若 `mtu=9000`：`len = (9000-48)&~7 = 8952`，仅需 1 片（8508<8952），不分片

**抓包 1448 对应 `mtu=1500`，而非 ifnet 的 9000。** 问题核心：IPv6 分片用的 `mtu` 变量为何是 1500。

## 三、根因代码链（12 个 file:line，代码为准）

### 3.1 初始化阶段：ndi->maxmtu 被设成 1500

| 步骤 | file:line | 代码 |
|------|-----------|------|
| ① ether_ifattach 设 if_mtu=1500 | `freebsd/net/if_ethersubr.c:985` | `ifp->if_mtu = ETHERMTU;`（ETHERMTU=1500）|
| ② ether_ifattach 调 if_attach | `freebsd/net/if_ethersubr.c:986` | `if_attach(ifp);` → 触发 domain `.dom_ifattach` |
| ③ in6 domain 注册 dom_ifattach | `freebsd/netinet6/in6_proto.c:115` | `.dom_ifattach = in6_domifattach,` |
| ④ in6_domifattach 调 nd6_ifattach | `freebsd/netinet6/in6.c:2607` | `ext->nd_ifinfo = nd6_ifattach(ifp);` |
| ⑤ nd6_ifattach 调 nd6_setmtu0 | `freebsd/netinet6/nd6.c:324-325` | `/* XXX: we cannot call nd6_setmtu since ifp is not fully initialized */ nd6_setmtu0(ifp, nd);` |
| ⑥ nd6_setmtu0 设 maxmtu=if_mtu | `freebsd/netinet6/nd6.c:369` | `ndi->maxmtu = ifp->if_mtu;` → **maxmtu=1500** |

f-stack ff_veth 初始化调用 ether_ifattach（`lib/ff_veth.c:937`），此时 if_mtu=1500，ndi->maxmtu 被初始化为 1500。

### 3.2 ff_veth 改 MTU 绕过标准同步路径

| 步骤 | file:line | 代码 |
|------|-----------|------|
| ⑦ ff_veth if_setmtu(9000) | `lib/ff_veth.c:967` | `if_setmtu(sc->ifp, init_mtu);`（init_mtu=9000）|
| ⑧ if_setmtu 只设 if_mtu | `freebsd/net/if.c:4431-4434` | `ifp->if_mtu = mtu; return (0);` — **不含 nd6_setmtu** |
| ⑨ 标准 if_notifymtu 含 nd6_setmtu | `freebsd/net/if.c:4440-4443` | `#ifdef INET6 nd6_setmtu(ifp); #endif rt_updatemtu(ifp);` — **未被调用** |
| ⑩ ff_veth 运行时 SIOCSIFMTU 同样绕过 | `lib/ff_veth.c:248-253` | `if_setmtu(ifp, new_mtu);` 直接调，不经 ifhwioctl/if_notifymtu |

**f-stack lib 层全文搜索 `nd6_setmtu` = 0 命中**：确认 lib 层从未调用 nd6_setmtu/if_notifymtu/rt_updatemtu。

标准 FreeBSD 内核路径（被 f-stack 绕过）：`ifhwioctl SIOCSIFMTU`（`if.c:2754`）→ `if_notifymtu`（`if.c:4440`）→ `nd6_setmtu`（`nd6.c:354`）→ `nd6_setmtu0`（`nd6.c:364`）→ `ndi->maxmtu = ifp->if_mtu`。

### 3.3 IN6_LINKMTU 返回 1500 → 分片 1448

| 步骤 | file:line | 代码 |
|------|-----------|------|
| ⑪ IN6_LINKMTU 宏 | `freebsd/netinet6/nd6.h:102-106` | `(ndi->linkmtu && ndi->linkmtu < if_mtu) ? linkmtu : ((ndi->maxmtu && ndi->maxmtu < if_mtu) ? maxmtu : if_mtu)` → maxmtu(1500)<if_mtu(9000) → **返回 1500** |
| ⑫ 路由 nh_mtu=IN6_LINKMTU | `freebsd/netinet6/in6_rmx.c:117-120` | `nh->nh_mtu = IN6_LINKMTU(nh->nh_ifp);` = 1500 |
| ⑬ ip6_getpmtu 取 nh_mtu | `freebsd/netinet6/ip6_output.c:1519-1521` | `nh = fib6_lookup(...); mtu = nh->nh_mtu;` = 1500 |
| ⑭ ip6_calcmtu 对 ICMP6 查 hostcache | `freebsd/netinet6/ip6_output.c:1540-1567` | proto=ICMP6≠TCP/SCTP → `mtu = tcp_hc_getmtu(&inc);`；`if(mtu) mtu=min(mtu,rt_mtu); else mtu=rt_mtu;` → 无论 hostcache 有无记录均得 1500（rt_mtu=1500 是上限）|
| ⑮ 分片 size 计算 | `freebsd/netinet6/ip6_output.c:1204` | `len = (1500-40-8)&~7 = 1448` → 6 片 1448×5+1268=8508 ✓ |

### 3.4 根因总结

```
ether_ifattach(if_mtu=1500) → nd6_ifattach → nd6_setmtu0(ndi->maxmtu=1500)
        ↓
ff_veth if_setmtu(9000) → if_mtu=9000，但【未调 nd6_setmtu】→ ndi->maxmtu 停 1500
        ↓
IN6_LINKMTU = maxmtu(1500) < if_mtu(9000) → 返回 1500
        ↓
路由 nh_mtu = 1500 → ip6_getpmtu mtu=1500 → ip6_calcmtu mtu=1500
        ↓
ip6_output 分片 len=(1500-48)&~7=1448 → 6 片
```

## 四、为何 IPv4 正常 / 为何开 KNI 正常

- **IPv4 正常**：IPv4 输出路径（`ip_output.c`）用 `ifp->if_mtu=9000` 判断分片，不走 `IN6_LINKMTU`。if_mtu 已被 ff_veth 正确设成 9000，故 8500 包不分片。
- **开 KNI 正常**：KNI 走 Linux 内核栈回包，内核 veth 接口的 `nd_ifinfo` 由 Linux 内核 `ifioctl`/`if_notifymtu` 等价路径正确同步，MTU=9000 生效。问题仅在 f-stack 用户态 FreeBSD 协议栈的 `nd_ifinfo` 未同步。

## 五、次因（可能共存，待运行时验证）

用户 `ff_ifconfig` 显示 `ACCEPT_RTADV` 开启。若路由器通告 MTU=1500，`nd6_rtr.c:540-561` 会设 `ndi->linkmtu=1500`：

```c
// nd6_rtr.c:544
mtu = (u_long)ntohl(ndopts.nd_opts_mtu->nd_opt_mtu_mtu);
// nd6_rtr.c:557-559
if (mtu <= maxmtu) {
    if (ndi->linkmtu != mtu) {
        ndi->linkmtu = mtu;
```

`IN6_LINKMTU` 优先级：`linkmtu` > `maxmtu` > `if_mtu`。即使主因修复（maxmtu 同步成 9000），若 `linkmtu=1500` 仍会压低 `IN6_LINKMTU` 返回 1500。

**运行时验证方法**（待后续执行）：
- `ndp -i f-stack-0` 查看 `linkmtu` / `maxmtu` 实际值
- 若 `linkmtu=0`：主因（maxmtu 未同步）是唯一根因，修复 maxmtu 即可
- 若 `linkmtu=1500`：需额外处理 RA（sysctl `net.inet6.ip6.accept_rtadv=0` 或忽略 RA MTU 选项）

## 六、修复方向（方案 A 已实施）

| 方案 | 改动 | 优缺点 |
|------|------|--------|
| **A（已实施）** | `ff_veth.c:968` 和 `:253` 的 `if_setmtu` 后补调 `if_notifymtu(ifp)` | 含 nd6_setmtu + rt_updatemtu，一次同步；与标准内核语义一致 |
| B | `ff_veth.c` 补调 `nd6_setmtu(ifp)` + `rt_updatemtu(ifp)` 分别调 | 等效 A，但需两行 |
| C | 改用标准 `ifhwioctl(SIOCSIFMTU)` 路径替代直接 `if_setmtu` | 改动大，可能引入副作用 |

需评估的次因处理：
- 若运行时确认 `linkmtu=1500`（RA 通告），需额外：sysctl 关 `accept_rtadv`，或 `ndp -i f-stack-0` 手动设 linkmtu，或在 f-stack 侧忽略 RA MTU 选项
- 若 `linkmtu=0`，方案 A 即可完全修复

## 七、外网参考

FreeBSD 标准接口 MTU 变更同步路径（交叉验证，与代码一致）：
```
SIOCSIFMTU (ioctl)
  → ifhwioctl (if.c:2729)
    → if_setmtu (if.c:4431, 只设 if_mtu)
    → if_notifymtu (if.c:4440)
      → nd6_setmtu (nd6.c:354, IPv6 同步 ndi->maxmtu)
      → rt_updatemtu (更新路由 MTU)
```
- FreeBSD 源码 `github.com/freebsd/freebsd-src` `sys/netinet6/nd6.c`：`nd6_setmtu0` 是 `ndi->maxmtu` 的唯一赋值点（`nd6.c:369`），由 `nd6_ifattach`（初始化）和 `nd6_setmtu`（运行时变更）调用。
- f-stack `github.com/F-Stack/f-stack` `freebsd/netinet6/nd6_rtr.c`：RA MTU 选项处理与上游一致。

## 八、诚实边界

- 主因（`ndi->maxmtu` 未同步）已通过补调 `if_notifymtu` 修复（方案 A 已实施，见 git log）。`ndi->linkmtu` 的运行时实际值须由 `ndp -i f-stack-0` 确认。
- 若 `linkmtu=0`：主因修复后 `IN6_LINKMTU` 返回 `if_mtu=9000`，IPv6 不再分片。
- 若 `linkmtu=1500`（RA 通告）：即使 maxmtu 已同步成 9000，`linkmtu=1500` 仍压低 `IN6_LINKMTU` 返回 1500，需额外处理 RA（sysctl 关 `accept_rtadv` 或忽略 RA MTU 选项）。
