# F-Stack DPDK 接管网卡后修改 MTU 调研 —— 结论总览

> 结论先行文档。所有结论均以**实际代码**（`lib/` + `freebsd/`）+ **运行时实测** + **外网权威资料**三方交叉验证，冲突处以代码与实测为准。
> 调研对象：`/data/workspace/f-stack/`，DPDK 24.11.6，运行时环境为本机 DPDK 独占网卡（virtio，`0000:00:09.0`，IP `<DPDK_NIC_IP>`）。

## 一句话结论

**部分支持**：f-stack DPDK 接管网卡后，**减小 MTU（≤1500）可用**；**增大 MTU（>1500，即 jumbo frame）不支持**，`ff_ioctl(SIOCSIFMTU)` 对 >1500 直接返回 `EINVAL(22)`。

## 分场景结论

| 场景 | 是否支持 | 直接依据 |
|---|---|---|
| **减小 MTU**（如 1500→1400） | ✅ **支持** | 运行时实测 `mtu 1400` 设置成功（exit=0）；代码上 `ether_ioctl` 对 ≤ETHERMTU 的值直接写入 `ifp->if_mtu`（`if_ethersubr.c:1181`） |
| **增大 MTU 到 jumbo**（如 9000） | ❌ **不支持** | 运行时实测返回 `ioctl SIOCSIFMTU (set mtu): Invalid argument`；代码上 `ether_ioctl` 对 `ifr_mtu > ETHERMTU` 直接 `EINVAL`（`if_ethersubr.c:1178-1179`） |
| **增大 MTU 到 2000**（略超标准帧） | ❌ **不支持** | 同上，实测同样 EINVAL；上限锁定在 `ETHERMTU=1500` |

## 根因（软硬件断层）

1. **协议栈层硬编码 1500 上限**：f-stack 的 `ff_veth_ioctl`（`lib/ff_veth.c:235`）把 `SIOCSIFMTU` 委托给 FreeBSD `ether_ioctl`（L248）。`ether_ioctl`（`freebsd/net/if_ethersubr.c:1174-1181`）对 `ifr_mtu > ETHERMTU(1500)` 硬编码返回 `EINVAL`。且 `ether_ifattach`（`if_ethersubr.c:985`）在网卡挂载时把 `if_mtu` 静态设为 `ETHERMTU=1500`。
2. **DPDK 硬件层完全无 MTU 接线**：`lib/ff_dpdk_if.c` 端口初始化/配置流程中**没有** `rte_eth_dev_set_mtu` 调用，`rxmode` 无 `mtu`/`max_rx_pkt_len`/jumbo 相关设置；mbuf 池用 `RTE_MBUF_DEFAULT_BUF_SIZE`(=2048) 创建，未按大 MTU 放大 `data_room_size`。即使绕过协议栈的 1500 上限，DPDK 硬件也无法收发大帧。
3. **软硬件不联动**：即便 `if_mtu`（软件值）被改，也不会下发到 DPDK 硬件端口。对 ≤1500 无影响（硬件默认 2048 buf 足以承载标准帧）；对 jumbo 则收发必然失败。

## 三方证据一致性

| 证据来源 | 结论 |
|---|---|
| **代码**（`ff_veth.c`/`if_ethersubr.c`/`ff_dpdk_if.c`） | ether_ioctl 硬编码 1500 上限；DPDK 无 set_mtu/jumbo/大 mbuf |
| **运行时实测**（`tools/sbin/ifconfig`） | 1400 成功；9000/2000 均 EINVAL；上限 1500 |
| **外网**（F-Stack 官方 issue #239 / #720） | 维护者明确"mtu 不能超过 1500"；jumbo 支持 issue 至今 OPEN（enhancement，未实现） |

## 若要完整支持 jumbo（增大 MTU）的改造点

详见 `06-方案与结论.md`。核心四处（缺一不可）：
1. `ff_dpdk_if.c`：端口配置调用 `rte_eth_dev_set_mtu` + 开启 jumbo `rxmode`（`RTE_ETH_RX_OFFLOAD_SCATTER` 或放大 `mtu`）。
2. `ff_dpdk_if.c`：mbuf 池 `data_room_size` 按最大 MTU 放大（或多池/分段接收）。
3. `ff_veth.c` / `ether_ifattach` 路径：使 `if_mtu` 上限可配（突破 `ether_ioctl` 的 ETHERMTU 硬校验，通常需在 `ff_veth_ioctl` 中拦截 `SIOCSIFMTU` 自行处理并同步下发 DPDK）。
4. `config.ini`：新增 `mtu` 配置项供 `ff_veth_setup_interface` 读取并初始化。
