# 协议栈层分析：SIOCSIFMTU 全链路

> 本文分析 f-stack 用户态 FreeBSD 协议栈对 MTU 修改（`SIOCSIFMTU`/`SIOCGIFMTU`）的处理链路。所有引用均为实际代码 `文件:行号`。

## 1. 应用层 → f-stack 的 ioctl 转换

f-stack 对外提供 Linux 语义的 `ff_ioctl`，需把 Linux 的 `SIOCSIFMTU`/`SIOCGIFMTU` 转换为 FreeBSD 的对应命令。

`lib/ff_syscall_wrapper.c`：
```c
177: #define LINUX_SIOCGIFMTU      0x8921
178: #define LINUX_SIOCSIFMTU      0x8922
...
518:        case LINUX_SIOCGIFMTU:
519:            return SIOCGIFMTU;
520:        case LINUX_SIOCSIFMTU:
521:            return SIOCSIFMTU;
```

- 读 MTU：`LINUX_SIOCGIFMTU(0x8921)` → FreeBSD `SIOCGIFMTU`
- 设 MTU：`LINUX_SIOCSIFMTU(0x8922)` → FreeBSD `SIOCSIFMTU`

即协议栈层**具备**接收 MTU 修改请求的转换通路，`tools/sbin/ifconfig` 亦通过此路径改 MTU。

## 2. 通用 ifioctl 层（if.c）

转换后的 `SIOCSIFMTU` 进入 FreeBSD 通用接口 ioctl 派发。

`freebsd/net/if.c`：
```c
2729:  case SIOCSIFMTU:
2733:      error = priv_check(td, PRIV_NET_SETIFMTU);   // 权限校验
2736:      if (ifr->ifr_mtu < IF_MINMTU || ifr->ifr_mtu > IF_MAXMTU)  // 宽泛边界
              ... (越界 EINVAL)
          // 调用驱动的 if_ioctl 回调
2755:          if_notifymtu(ifp);   // 成功且变化后通知 MTU 变更
```
读 MTU：
```c
2515:      ifr->ifr_mtu = ifp->if_mtu;   // SIOCGIFMTU 返回软件值
```

- `if.c` 层只做 `priv_check` 与**宽泛**边界校验（`IF_MINMTU`~`IF_MAXMTU`，`IF_MAXMTU` 高达 65535），不是 1500 上限的来源。
- 通过 `priv_check`/边界后，转调驱动的 `if_ioctl` 回调（即 `ff_veth_ioctl`）。

## 3. 驱动层 ff_veth_ioctl（关键委托点）

`lib/ff_veth.c`：
```c
234: static int
235: ff_veth_ioctl(if_t ifp, u_long cmd, caddr_t data)
236: {
238:     struct ff_veth_softc *sc = if_getsoftc(ifp);
240:     switch (cmd) {
241:     case SIOCSIFFLAGS:            // 仅显式处理 UP/DOWN
242:         if (if_getflags(ifp) & IFF_UP) { ff_veth_init(sc); }
244:         else if (...) ff_veth_stop(sc);
246:         break;
247:     default:
248:         error = ether_ioctl(ifp, cmd, data);   // SIOCSIFMTU 落此分支
249:         break;
250:     }
252:     return (error);
253: }
```

回调注册（`ff_veth_setup_interface`）：
```c
923:     if_setioctlfn(ifp, ff_veth_ioctl);
```

- `ff_veth_ioctl` **不单独处理 `SIOCSIFMTU`**，全部委托给 FreeBSD 以太网通用处理 `ether_ioctl`。
- 这意味着：**f-stack 没有在驱动层为 MTU 修改做任何 DPDK 硬件下发钩子**（无 `rte_eth_dev_set_mtu` 调用）。

## 4. ether_ioctl 的 1500 硬上限（EINVAL 真源）

`freebsd/net/if_ethersubr.c`：
```c
1174:  case SIOCSIFMTU:
1178:      if (ifr->ifr_mtu > ETHERMTU) {
1179:          error = EINVAL;              // >1500 直接拒绝
1181:      } else ifp->if_mtu = ifr->ifr_mtu;   // ≤1500 写入软件值
```

- `ETHERMTU = 1500`。这是**修改 MTU 的真正上限来源**：
  - `ifr_mtu ≤ 1500`：接受，写入 `ifp->if_mtu`（软件值）。
  - `ifr_mtu > 1500`：返回 `EINVAL`，`if_mtu` 不变。

## 5. MTU 初始值

`ether_ifattach` 在网卡挂载时把 MTU 静态初始化为 1500：
```c
985:      ifp->if_mtu = ETHERMTU;
```
`ff_veth_setup_interface`（`ff_veth.c:927`）调用 `ether_ifattach(ifp, sc->mac)`，故 f-stack 网卡默认 MTU=1500。

## 小结（协议栈层）

- **能改**：协议栈层支持通过 `ff_ioctl(SIOCSIFMTU)` 修改 `if_mtu` 软件值，前提是 **≤1500**。
- **不能改大**：`ether_ioctl` 硬编码 `> ETHERMTU(1500)` 即 `EINVAL`，f-stack 未在 `ff_veth_ioctl` 中拦截覆盖，故 jumbo 在协议栈层即被拒绝。
- **不下发硬件**：无论成功与否，`if_mtu` 软件值都不会通过 `rte_eth_dev_set_mtu` 下发到 DPDK 端口（见 `02-DPDK硬件层分析.md`）。
