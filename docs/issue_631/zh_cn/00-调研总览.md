# Issue #631 调研总览

## 1. Issue 信息

| 项目 | 内容 |
|------|------|
| Issue | F-Stack/f-stack #631 |
| 标题 | ff_shutdown() not working on UDP sockets |
| 作者 | sarosharif |
| 日期 | 2021-12-29 |
| 状态 | Open |
| 问题 | 对 UDP 套接字调用 `ff_shutdown(sockfd, 0)`（SHUT_RD）后仍可继续接收数据；TCP 正常 |

## 2. 结论摘要

**Issue #631 在当前 F-Stack 1.26 + FreeBSD 15.0 + DPDK 24.11.6 环境中不复现。**

`ff_shutdown(SHUT_RD)` 在 UDP 套接字上工作正常：
- 返回 0（成功）
- 后续 `ff_recvfrom` 立即返回 0（EOF），不再收到数据
- 3 次重复测试结果一致

对比测试显示 F-Stack 的行为实际上优于 Linux 内核栈：Linux 内核对未连接 UDP `shutdown(SHUT_RD)` 返回 `ENOTCONN` 并继续接收数据，而 F-Stack 返回 0 并正确停止接收。

## 3. 测试结果总览

| 测试 ID | 栈类型 | how | shutdown 返回值 | 后续行为 | 结果 |
|---------|--------|-----|----------------|---------|------|
| T1 (x3) | F-Stack | SHUT_RD | 0 | recvfrom→0 (EOF) | ✅ PASS |
| T2 | F-Stack | SHUT_WR | 0 | sendto→EPIPE | ✅ PASS |
| T5 | 内核栈 | SHUT_RD | -1 (ENOTCONN) | 继续接收数据 | ❌ 内核行为 |

## 4. 根因分析

### 4.1 调用链

```
ff_shutdown (lib/ff_syscall_wrapper.c:1862)
  → sys_shutdown → kern_shutdown (freebsd/kern/uipc_syscalls.c:1328)
    → soshutdown (freebsd/kern/uipc_socket.c:3673)
      → udp_shutdown (freebsd/netinet/udp_usrreq.c:1741)
        → sorflush (freebsd/kern/uipc_socket.c:3688)     [SHUT_RD]
          → socantrcvmore (freebsd/kern/uipc_sockbuf.c:408)
            → 设置 so->so_rcv.sb_state |= SBS_CANTRCVMORE
          → sbrelease(so, SO_RCV)
        → socantsendmore (SHUT_WR)
```

### 4.2 关键发现

1. `udp_shutdown` 对未连接 UDP 返回 `ENOTCONN`，但**仍然调用 `sorflush(so)`**（`udp_usrreq.c:1768`）
2. `sorflush` 调用 `socantrcvmore` 设置 `SBS_CANTRCVMORE` 标志
3. `soreceive_dgram`（`uipc_socket.c:3537`）检查 `SBS_CANTRCVMORE`，设置后返回 0（EOF）
4. `kern_shutdown`（`uipc_syscalls.c:1349-1351`）将 `ENOTCONN` 转为 0（因为 F-Stack 的 `p_osrel=0 < P_OSREL_SHUTDOWN_ENOTCONN=1100077`）

### 4.3 与旧版本差异

FreeBSD 15.0 的 `soshutdown` 完全委托给 `pr_shutdown`（协议回调），而旧版 `soshutdown` 自行处理 `sorflush`/`socantsendmore`。`udp_shutdown` 在所有版本中都调用 `sorflush`，但 `soreceive_dgram` 对 `SBS_CANTRCVMORE` 的检查在 15.0 中更加完善。

## 5. 建议

1. Issue #631 可考虑关闭，标注"在最新版本中不复现"
2. 建议用户升级到最新 F-Stack dev 分支（FreeBSD 15.0 + DPDK 24.11.6）重试
3. 如果仍有问题，请提供完整的 config.ini 和测试代码
