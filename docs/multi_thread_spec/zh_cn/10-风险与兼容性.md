# 10 · 风险与兼容性

> 本文汇总多线程模式的风险（锁开销、故障隔离、多进程零回归、API 兼容、全局单例竞态）与 opt-in 策略。所有风险点带 `file:line` 溯源。

---

## 0. 结论先行

- **最大风险来自路线 B（多线程共栈）**：全局单例竞态（`msg_iov_tmp`/`pcpup`/`lcore_conf`）、协议栈锁竞争、故障隔离弱化。
- **兼容性铁律**：多线程为 **opt-in**，默认多进程模式行为逐字节不变（零回归）。
- 推荐路线 A（adapter 多 worker）风险显著低于路线 B，天然满足零回归。

---

## 1. 全局单例竞态风险（路线 B 核心风险）

| 单例 | file:line | 竞态场景 | 后果 | 缓解 |
|---|---|---|---|---|
| `msg_iov_tmp/msg_iovlen_tmp` | `ff_syscall_wrapper.c:225-226` | 多线程并发 sendmsg/recvmsg 共用暂存 iovec（`:864,893-897`） | iovec 数据交叉损坏 | 恢复 `__thread`（注释已预留，P0） |
| `pcpup` | `ff_freebsd_init.c:69` | 多线程共用 PCPU 指针，`PCPU_GET/SET`（`pcpu.h:44-50`）非原子 | per-CPU 统计/状态错乱 | per-thread 化（P2，改造量中） |
| `lcore_conf` | `ff_dpdk_if.c:123` | 多线程共享 rx/tx queue 配置 | queue 状态覆盖、收发错乱 | per-thread queue（P3，改造量大） |
| `thread0` 共享 td | `ff_thread.c:44` / `ff_init_main.c:98` | `ff_pthread_create` 多子线程共享父 td | `td` 字段互踩（td_retval/errno） | 改用 `ff_adapt_user_thread_add`（`ff_compat.c:96`，P1） |

> 优先级 P0~P3 见 `05-FreeBSD栈全局状态per-thread化清单.md` 第 4 节。

---

## 2. 锁开销风险

- FreeBSD 协议栈内部（socket table `in_pcbinfo`/tcbinfo、route table、callout wheel）自带 mtx/rwlock/epoch 锁。
- **现状**：单线程 RTC（一进程一 lcore），锁基本无竞争（见 `05` 第 3 节）。
- **多线程共栈后**：锁真正开始竞争，热点在 pcb 查找、路由查找、定时器插入。
- **风险**：锁竞争可能抵消多进程 share-nothing 的免锁优势，导致多线程性能不如多进程。
- **缓解**：需性能基线实测驱动（见 `09`）；若退化显著则维持 share-nothing 决策。

---

## 3. 故障隔离风险

| 模型 | 隔离粒度 | 一处崩溃影响 |
|---|---|---|
| 多进程（现状/路线 A） | 进程级 | 单进程崩溃不影响其他进程，隔离强 |
| 多线程共栈（路线 B） | 线程级 | 一线程崩溃/段错误拖垮整个进程内所有线程，隔离弱 |

- **风险**：路线 B 下单点故障放大为全进程故障。
- **缓解**：路线 B 仅在对隔离要求低、追求内存节省的场景使用；关键业务优先路线 A。

---

## 4. 多进程零回归风险（一票否决）

- **要求**：默认不开多线程 opt-in 时，多进程行为逐字节不变。
- **风险点**：per-thread 化改动（路线 B）若无条件生效，会污染多进程路径。
- **缓解**：
  - 所有多线程改动以编译宏 / 运行时配置 opt-in 门控（类比 `FF_THREAD_SOCKET`/`FF_MULTI_SC` 宏，`ff_hook_syscall.c:227,241`）。
  - `msg_iov_tmp` 恢复 `__thread` 在多进程下等价（每进程单线程，TLS==全局），零回归天然成立。
  - KNI 仍 primary-only（`ff_dpdk_if.c:2661-2663`），SC/SP ring flag（`:618`）多进程路径不变。
  - proc_type 仍只放行 primary/secondary/auto（`ff_config.c:1316-1321`），新模式走独立 opt-in（见 `06-配置与接口设计.md`）。
- **验收**：见 `08-测试与验收规格.md` 第 4 节（多进程零回归门禁）。

## 5. API 兼容风险

| 风险 | 溯源 | 缓解 |
|---|---|---|
| 现有导出符号签名变更 | `ff_api.h` / `ff_api.symlist` | 只增不改：新 API 追加，不动现有签名 |
| `ff_rss_self_queue_info` 语义变化 | `ff_api.h:124-126`（现为"本进程"） | 多线程下重定义为"本线程/worker"需保持旧调用兼容或新增变体 |
| `ff_pthread_create` 行为变化 | `ff_thread.c:32-46` | 若改为独立 td，需评估既有依赖"共享父 td"行为的调用方（应无正确用例） |
| SOCK_FSTACK/SOCK_KERNEL 语义 | `ff_api.h:96,99` | 保持不变 |

---

## 6. opt-in 策略（兼容性总纲）

1. **默认关闭**：不配置任何多线程选项时，行为 == 当前多进程 share-nothing，逐字节不变。
2. **编译期 opt-in**：路线 A 沿用现有编译宏（`FF_THREAD_SOCKET`/`FF_MULTI_SC`）；路线 B 新增独立宏门控 per-thread 化改动。
3. **运行期 opt-in**：如引入新配置项，须与现有 `lcore_mask`/`nb_procs`/`proc_type` 语义共存，旧 config.ini 不受影响（详见 `06-配置与接口设计.md`）。
4. **渐进交付**：先交付路线 A（零回归、低风险），路线 B 作为独立预研分阶段推进，任一阶段不达零回归门禁即打回（bounce≤3）。

---

## 7. 风险汇总矩阵

| 风险 | 路线 A | 路线 B | 严重度 |
|---|---|---|---|
| 全局单例竞态 | 无 | 有（P0~P3） | 高（B） |
| 锁竞争开销 | 无 | 有 | 高（B） |
| 故障隔离弱化 | 无（进程级） | 有（线程级） | 中（B） |
| 多进程零回归 | 天然成立 | 需门控保障 | 高（一票否决） |
| API 兼容 | 低（只增不改） | 中（语义可能变） | 中 |
| 内存占用 | 高（各实例一份栈） | 低（共享） | 低 |

**总结论**：推荐先行路线 A，路线 B 需在充分 per-thread 化 + 性能实测 + 严格 opt-in 门控下方可推进，且始终以多进程零回归为不可逾越的红线。
