# 08 · 测试与验收规格

> 本文给出多线程模式的单测 mock 点、集成测试、端到端测试与多进程零回归验收规格。测试拓扑遵循本机双网卡约定：**DPDK 独占网卡 IP 9.134.214.176（需 ssh f-stack-client 测），内核栈测 127.0.0.1 lo**。所有测试点带 `file:line` 定位。

---

## 0. 结论先行

- 测试分四层：**单测（mock）→ 集成（复用 adapter 多 worker）→ 端到端（lo + DPDK 网卡）→ 多进程零回归验收**。
- 多进程零回归是**一票否决门禁**：默认多进程行为必须逐字节不变。

---

## 1. 单元测试（mock 点）

> 遵循 Unity 测试框架（参考 workspace 规则 `c-unittest-expert`）。单测聚焦纯函数与标志位转换，不依赖 DPDK 运行时。

| 测试点 | 目标函数 | file:line | mock/构造 | 断言 |
|---|---|---|---|---|
| socket 组合标志位转换 | `linux2freebsd_socket_flags` | `ff_syscall_wrapper.c:672-684` | 输入 `LINUX_SOCK_NONBLOCK\|LINUX_SOCK_CLOEXEC` 各组合 | 输出正确置 `SOCK_NONBLOCK/SOCK_CLOEXEC`，清除 Linux 位 |
| 领地判定剥离标志位 | `fstack_territory` | `ff_hook_syscall.c:359-374` | `SOCK_STREAM\|SOCK_NONBLOCK\|SOCK_CLOEXEC\|SOCK_FSTACK` | 正确判为 f-stack 领地，不误判类型 |
| lcore_mask 解析 | `parse_lcore_mask` | `ff_config.c:73-142` | 多种 hex 掩码 + 不同 proc_id | `nb_procs`/`proc_lcore[]`/`proc_mask` 正确；proc_id 越界返回 0 |
| proc_type 校验 | proc_type 解析段 | `ff_config.c:1300-1326` | primary/secondary/auto/非法值 | 合法放行、非法拒绝、默认 auto |
| RSS 队列=proc_id 映射 | `init_lcore_conf` 逻辑 | `ff_dpdk_if.c:434-448` | mock proc_lcore/lcore_list | queueid == proc_id 对应 index |
| per-thread iovec（路线 B B-M1） | recvmsg/sendmsg 暂存 | `ff_syscall_wrapper.c:225-226,864,893-897` | 恢复 `__thread` 后并发场景 mock | 每线程独立暂存，无交叉 |
| curthread 切换/恢复 | `ff_switch_curthread`/`ff_restore_curthread` | `ff_compat.c:131-148` | 构造多 td | 切换后 `pcurthread` 正确、恢复无误 |

**mock 策略**：DPDK 相关（`rte_*`）用 stub；FreeBSD 内核符号（`sys_socket`/`kern_accept4`）用 mock，仅验证参数变换。

## 2. 集成测试（复用 adapter 多 worker 启动）

复用 `adapter/syscall/main_stack_thread_socket.c`（kqueue 版）与 `main_stack_epoll_thread_socket.c`（epoll 版）作为多 worker 启动载体。

| 用例 | 载体 | 关键点 file:line | 验收 |
|---|---|---|---|
| 多 worker kqueue 启动 | `main_stack_thread_socket.c` | `main:214-262`（worker_num 参数、绑核 `:239-250`） | N 个 worker 各自 socket/bind/listen/kqueue 成功 |
| 多 worker epoll + SO_REUSEPORT | `main_stack_epoll_thread_socket.c` | `loop:79`（`SOCK_STREAM\|SOCK_FSTACK`）、`:92`（SO_REUSEPORT） | 多 worker 并发 accept 均可收连接 |
| worker→后端进程映射 | adapter | `ff_hook_syscall.c:3297`（`worker_id % nb_procs`） | worker 正确 attach 到对应 sc 上下文 |
| FF_THREAD_SOCKET per-thread sc | 编译宏 | `ff_hook_syscall.c:227` `__FF_THREAD` | 各 worker sc 独立，不串扰 |
| FF_MULTI_SC 多 sc | 编译宏 | `ff_hook_syscall.c:241` | 单实例挂多 worker（≤32，`ff_socket_ops.h:44-45`） |
| issue #430 场景回归 | adapter | `SOCK_STREAM\|SOCK_NONBLOCK\|SOCK_CLOEXEC` | socket 进入 f-stack 栈，非回退 kernel |

**启动规约**：worker 初始化通过 `pthread_spinlock` 串行化（`main_stack_thread_socket.c:98,229,252`），保证 `ff_adapter_init` 不并发。

## 3. 端到端测试（lo 内核栈 + DPDK 网卡）

### 3.1 内核栈路径（127.0.0.1 lo）

- 场景：`SOCK_KERNEL` 标记或 `kernel_coexist` 配置下走 host 内核栈。
- 测试：本机 `127.0.0.1` 起 server/client，验证内核栈路径连通（不经 DPDK）。
- 关键点：`ff_socket` FF_KERNEL_COEXIST 段（`ff_syscall_wrapper.c:922-940`）、`ff_hook_socket` kernel 分支（`ff_hook_syscall.c:387-390`）。

### 3.2 DPDK 网卡路径（9.134.214.176，需 ssh f-stack-client）

- 场景：f-stack 用户态栈通过 DPDK 独占网卡收发，多 worker 各绑核。
- 拓扑：
  - **被测端**：本机 f-stack（DPDK 网卡 IP 9.134.214.176），启动 N worker（多 worker adapter 或多进程）。
  - **对端**：`ssh f-stack-client`，向 9.134.214.176 发起 TCP 连接/压测。
- 验收：
  - 多连接经 RSS 分流到不同 worker/进程（RSS 队列=proc_id，`ff_dpdk_if.c:434-448`）；
  - 连接建立、数据收发、关闭全链路正常；
  - IPv4/IPv6 均覆盖。

> **规约提示**：DPDK 网卡被独占，无法用本机回环测，必须经 `ssh f-stack-client`。

## 4. 多进程零回归验收（一票否决门禁）

| 验收项 | 方法 | 通过标准 |
|---|---|---|
| 默认配置行为不变 | 不开任何多线程 opt-in，跑现有多进程 helloworld/nginx | 与改造前逐字节一致（RSS 分流、mempool/ring 共享、KNI primary-only 行为不变） |
| KNI 仍 primary-only | 校验 `ff_dpdk_if.c:2661-2663`、`ff_config.c:1392-1410` 逻辑未变 | 仅 proc_id=0 处理 KNI |
| SC/SP ring flag 不变 | 多进程路径 dispatch_ring `RING_F_SC_DEQ`（`ff_dpdk_if.c:618`）不变 | 单消费者语义保留 |
| 配置解析兼容 | proc_type 仍只 primary/secondary/auto（`ff_config.c:1316-1321`），新增项 opt-in | 旧 config.ini 行为不变 |
| API 兼容 | `ff_api.h` 现有导出符号不删改签名 | 现有 APP 无需重编即可跑 |

> 若路线 B 引入 per-thread 化改动，须在开启多线程 opt-in 前后分别验证多进程路径零回归；任一项失败即门禁不过，按 bounce≤3 打回修复。

## 5. 测试执行规约

- 编译前先 `make clean` 再全量编译（clean build 规约），不依赖增量。
- 删临时文件走 `/data/workspace/rm_tmp_file.sh`；杀进程走 `/data/workspace/kill_process.sh`；改权限走 `/data/workspace/chmod_modify.sh`。
- config.ini 本地测试值（lcore_mask/IP/idle_sleep 等）不入库。
- 本轮为 spec 阶段，暂不编码；本文为后续编码阶段的测试蓝图。
