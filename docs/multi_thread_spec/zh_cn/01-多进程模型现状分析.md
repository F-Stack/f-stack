# 01 · 多进程模型现状分析

> 本文基于代码事实素材 `_material_code.md` 第 1 节，所有关键论断均带 `file:line` 证据（均指向 `/data/workspace/f-stack` 实际代码）。外网与代码冲突以代码为准。

---

## 0. 结论先行

- **f-stack 原生并发模型是「多进程 run-to-completion（RTC）shared-nothing」，不是「单进程多线程共栈」。** 每个 f-stack 进程绑定**恰好一颗** DPDK lcore，`lcore_conf` 是**全局单例**（`lib/ff_dpdk_if.c:123`）。
- 并发扩展方式：`lcore_mask` 里置多个 bit → 拉起多个进程（`proc_id = 0..N-1`），每进程各占一颗核、各收一条 RSS 队列，进程间通过 DPDK 共享大页内存（mempool/ring）协作，**协议栈实例彼此独立、锁基本无竞争**。
- **RSS 队列号 = proc_id**（`lib/ff_dpdk_if.c:434-448`），这是"一进程一队列一核"亲和的直接体现。
- KNI 仅 primary（proc_id=0）进程处理（`lib/ff_dpdk_if.c:2661-2663`、`lib/ff_config.c:1392-1410`）。

## 2. lcore_mask 解析：`parse_lcore_mask()`

`parse_lcore_mask()`（`lib/ff_config.c:73-142`）把 `lcore_mask` 十六进制掩码逐 bit 展开：

- `proc_lcore[count] = idx;`（`:118`）—— 逐个记录被启用的 lcore；
- 当 `proc_id == count`（`:119`）时，为**本进程**生成单 bit 的 `proc_mask`（`:123-125`：`cfg->dpdk.proc_mask = strdup(buf)`）；
- `cfg->dpdk.nb_procs = count;`（`:139`）—— 进程数 = 掩码中 bit 总数；
- `if (cfg->dpdk.proc_id >= count) return 0;`（`:136-137`）—— proc_id 越界校验。

**关键点**：每个进程虽然读同一份 `lcore_mask`，但通过自己的 `proc_id` 从中取出**仅属于自己的那一颗 lcore**，据此生成单 bit 的 `proc_mask` 传给 EAL。这就是"一进程一核"的配置起点。

## 3. proc_type 解析与校验

`lib/ff_config.c:1300-1326`：

- `-p` → `proc_id = atoi(optarg)`（`:1300-1301`）；
- `-t` → `proc_type = strdup(optarg)`（`:1303-1305`）；
- 默认 `proc_type = "auto"`（`:1312-1314`）；
- 合法性校验：**仅允许 primary/secondary/auto**（`:1316-1321`）；
- `proc_id > RTE_MAX_LCORE` 兜底为 0（`:1323-1326`）。

DPDK argv 拼接（`lib/ff_config.c:1150-1170`）：

- `-c<proc_mask>`（`:1151-1153`）—— 传给 EAL 的 coremask 是**本进程单 bit** 的 proc_mask（不是整个 lcore_mask）；
- `--proc-type=<proc_type>`（`:1167-1169`）。

> **多线程改造影响点**：现有 proc_type 校验只放行 primary/secondary/auto。若未来引入"多线程模式"，需评估是否新增枚举值或独立配置项（见 `06-配置与接口设计.md`）。

| 机制 | file:line | 说明 |

| mempool 共享 | `ff_dpdk_if.c:480+` | `init_mem_pool()` 遍历 `nb_procs` 个 lcore；`if PRIMARY` 则 `rte_pktmbuf_pool_create`（`:522-523`），SECONDARY lookup |

| 网卡配置只 PRIMARY | `ff_dpdk_if.c:1002-1006` | `if (rte_eal_process_type()!=RTE_PROC_PRIMARY) continue;`；`nb_queues = pconf->nb_lcores`（`:785`）作为 rx/tx 队列数 |

**PRIMARY-SECONDARY 语义**：PRIMARY（proc_id=0）负责全部 DPDK 资源初始化（mempool/ring/网卡配置/KNI）；SECONDARY 进程通过共享大页内存 lookup 已建资源，直接复用。

## 5. RSS 队列 = proc_id：`init_lcore_conf()`

`init_lcore_conf()`（`lib/ff_dpdk_if.c:400-464`）是"一进程一队列一核"亲和的核心：

- `lcore_conf.proc_id = ff_global_cfg.dpdk.proc_id;`（`:415`）；
- `uint16_t lcore_id = proc_lcore[lcore_conf.proc_id];`（`:424`）—— 本进程只认自己那颗 lcore；
- 在 `pconf->lcore_list` 中按 `proc_id` 找到自己的 index 作为 `queueid`（`:434-448`）—— **RSS 队列号 = proc_id**；
- `lcore_conf.nb_queue_list[port_id] = pconf->nb_lcores;`（`:459`）—— 总队列数 = 进程数；
- 若本 lcore 无 rx queue 则 `rte_exit`（`:462-463`）。

RSS reta 表（`lib/ff_dpdk_if.c:736-751`）：`reta_conf[i].reta[j] = hash++ % nb_queues`（`:750`），仅当 `nb_queues > 1` 时设置（`:1110-1114`）。网卡按 RSS hash 把不同流分到不同队列，即分到不同进程，实现连接亲和、进程间零共享。

## 6. 主 polling 循环 `main_loop()`

`main_loop()`（`lib/ff_dpdk_if.c:2566-2760+`）：

- `while (1)`（`:2587`），`qconf = &lcore_conf;`（`:2585`，取全局单例），`stop_loop` 退出（`:2589`）；
- TX drain（`:2634-2650`）；
- 逐 rx queue：`process_dispatch_ring`（`:2666`）→ `rte_eth_rx_burst`（`:2668`）→ `process_packets`（`:2688,2693`）；
- KNI 处理：`if (enable_kni && rte_eal_process_type()==RTE_PROC_PRIMARY) ff_kni_process(...)`（`:2661-2663`）；
- `process_msg_ring(qconf->proc_id, ...)`（`:2699`）；
- LRO flush（`:2671-2672,2695-2696`）。

启动：`ff_dpdk_run()`（`lib/ff_dpdk_if.c:2764-2771`）—— `rte_eal_mp_remote_launch(main_loop, lr, CALL_MAIN)`（`:2770`）+ `rte_eal_mp_wait_lcore()`（`:2771`）。

> **重要辨析**：虽然用了 `rte_eal_mp_remote_launch`（会向所有 EAL lcore 分发 `main_loop`），但每个 f-stack 进程的 EAL coremask 只含**一颗** lcore（proc_mask 单 bit），故实际每进程只有一个 lcore 执行 `main_loop`。这**不是**"单进程多 lcore 多线程"，而是"多进程各占一 lcore"。

## 8. 现状总评

| 维度 | 现状 |
|---|---|
| 并发单元 | 进程（每进程一颗 lcore） |
| 连接亲和 | RSS 队列 = proc_id，网卡按 hash 分流 |
| 内存共享 | DPDK 大页：mempool/ring（PRIMARY 建、SECONDARY attach） |
| 锁竞争 | 基本无（协议栈单线程 RTC，per-process 独立实例） |
| KNI | 仅 primary 处理 |
| 扩展方式 | lcore_mask 加 bit → 加进程 |

**这一模型是"反多线程共享"的：** 队列/核/进程一一绑定、SC/SP ring flag、全局单例 `lcore_conf`，都建立在"一进程一消费者"前提上。要支持"单进程多线程共栈"必须打破这些前提（见 `05` 与 `07`）。
