# 07 · 里程碑与编码工作分解（WBS）

> 本文基于 `_material_code.md` 第 7 节最小改造清单，给出后续实际编码里程碑（按危险度排序）与工作分解。区分**推荐路线（完善 adapter 多 worker）**与**高风险路线（改协议栈为共享多线程）**两套里程碑。所有改造点带 `file:line`。

---

## 0. 结论先行

- **推荐路线 = 完善 adapter 多 worker（FF_THREAD_SOCKET + FF_MULTI_SC + SO_REUSEPORT）+ 底层维持多进程 RSS 模型**。这是低风险、代码改动集中在 `adapter/syscall/` 与配置层、不动 FreeBSD 全局状态的路线。
- **高风险路线 = 改协议栈为一进程多线程共栈**，需系统性 per-thread 化 FreeBSD 全局单例（`pcpup`/`msg_iov_tmp`/`lcore_conf`），风险极高，仅作为长期备选。
- 两条路线**都必须以"多进程模式零回归"为前置门禁**（opt-in，默认行为逐字节不变，见 `10-风险与兼容性.md`）。

---

## 1. 路线 A（推荐）：完善 adapter 多 worker

### 1.1 目标

在**不改协议栈线程模型**（底层仍多进程 share-nothing）前提下，把"应用侧多线程"能力做完整、做文档化、做验收，覆盖 issue #430 类场景（pthread + 组合 socket 标志位）。

### 1.2 现实基础（已有，见 02 第 5-6 节）

- `main_stack_thread_socket.c`（kqueue 版）/ `main_stack_epoll_thread_socket.c`（epoll 版）多 worker 示例已可运行。
- `FF_THREAD_SOCKET`（per-thread sc，`ff_hook_syscall.c:227`）、`FF_MULTI_SC`（多 sc 数组，`:241`）、worker→后端进程映射（`:3297`）已具备。
- socket 组合标志位处理完备（`ff_syscall_wrapper.c:672-684`）。

### 1.3 里程碑

| 里程碑 | 内容 | 主要改动点 | 危险度 |
|---|---|---|---|
| A-M1 | 梳理并固化 adapter 多 worker 编译宏矩阵（FF_THREAD_SOCKET / FF_MULTI_SC / SO_REUSEPORT 组合）与使用文档 | `adapter/syscall/README.md`、Makefile 宏 | 低 |
| A-M2 | 补齐 `ff_rss_self_queue_info` 在多 worker 下的"本 worker/本线程"语义或文档说明 | `ff_api.h:124-126` | 低 |
| A-M3 | 集成测试：复用 `main_stack_thread_socket.c` 多 worker 启动，验证组合标志位 + 多线程 accept | 见 `08` | 低 |
| A-M4 | 性能基线：多 worker vs 多进程对比 | 见 `09` | 低 |

### 1.4 WBS（路线 A）

1. 编译宏矩阵梳理与 README 补充（A-M1）。
2. worker_id / RSS 队列自检 API 语义澄清（A-M2）。
3. 集成测试脚本编写（A-M3，复用 adapter 示例）。
4. 性能基线脚本与对照组（A-M4）。

> 路线 A **不触及** FreeBSD 全局单例，多进程零回归天然成立（默认路径不变）。

---

## 2. 路线 B（高风险）：一进程多线程共栈

### 2.1 目标

在单进程内起多个线程共享一份 FreeBSD 协议栈实例。**风险极高**，需系统性 per-thread 化全局单例并处理协议栈锁竞争。仅作长期备选。

### 2.2 里程碑（按危险度递增）

| 里程碑 | 内容 | 主要改动点 | 危险度 |
|---|---|---|---|
| B-M1 | 恢复 `msg_iov_tmp/msg_iovlen_tmp` 的 `__thread` | `ff_syscall_wrapper.c:225-226` | 低（注释已预留） |
| B-M2 | `ff_pthread_create` 改用 `ff_adapt_user_thread_add` 建独立 td | `ff_thread.c:44` / `ff_compat.c:96` | 中 |
| B-M3 | `pcpup` per-thread 化 | `ff_freebsd_init.c:69`、`pcpu.h:44-50` | 高 |
| B-M4 | `lcore_conf` per-thread queue 配置 + 每线程独立 rx/tx queue | `ff_dpdk_if.c:123,400-464` | 高 |
| B-M5 | dispatch_ring/msg_ring 的 SC/SP flag 改每线程独立 ring 或 MC/MP | `ff_dpdk_if.c:618` | 高 |
| B-M6 | 协议栈锁竞争压测与优化（socket table/route/callout） | 见 `05` 第 3 节 | 高 |
| B-M7 | KNI/IPC 在多线程下归属处理（KNI 仍 primary-only） | `ff_dpdk_kni.c`、`ff_dpdk_if.c:2661-2663` | 中 |

### 2.3 WBS（路线 B，按危险度排序）

**阶段 1（低危，可独立完成）**

1. B-M1：恢复 `__thread`（`ff_syscall_wrapper.c:225-226`），加单测覆盖并发 sendmsg/recvmsg（mock）。

**阶段 2（中危）**

2. B-M2：`ff_thread.c` 改造为每子线程独立 `struct thread`（对齐 `ff_adapt_user_thread_add`）。
3. B-M7：KNI/IPC 归属明确（KNI 仍 primary-only，多线程下由指定线程处理）。

**阶段 3（高危，需实测驱动）**

4. B-M3：`pcpup` per-thread 化，审查所有 `PCPU_GET/SET`。
5. B-M4：`lcore_conf` per-thread 化 + 队列模型重构。
6. B-M5：ring flag 重构。
7. B-M6：协议栈锁竞争压测 + 热点优化。

> 每个高危里程碑均须通过"多进程零回归门禁"后方可合入（`10` 第 5 节）；每阶段先 `make clean` 再全量编译（遵守 clean build 规约）。

## 3. 两路线对比与推荐

| 维度 | 路线 A（adapter 多 worker） | 路线 B（多线程共栈） |
|---|---|---|
| 改动范围 | `adapter/syscall/` + 配置 | 深入 lib 协议栈全局状态 |
| 触及 FreeBSD 全局单例 | 否 | 是（`pcpup`/`msg_iov_tmp`/`lcore_conf`） |
| 多进程零回归 | 天然成立 | 需专门门禁保障 |
| 锁竞争风险 | 无（仍 share-nothing） | 高（协议栈锁真正竞争） |
| 隔离性/故障隔离 | 强（进程级） | 弱（线程级，一线程崩全进程） |
| 内存占用 | 高（每实例一份栈） | 低（共享一份栈） |
| 交付周期 | 短 | 长 |
| **推荐度** | **首选** | 长期备选 |

**结论**：先交付路线 A（A-M1~A-M5），路线 B 作为独立技术预研分阶段推进，不阻塞路线 A。
