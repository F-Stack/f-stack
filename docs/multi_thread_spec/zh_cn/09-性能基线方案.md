# 09 · 性能基线方案

> 本文给出**多线程（adapter 多 worker）vs 多进程**性能基线对比方案：指标、测试拓扑、对照组设计。测试拓扑遵循本机双网卡约定（DPDK 网卡 9.134.214.176 需 ssh f-stack-client 测）。

---

## 0. 结论先行

- 性能基线核心目的：验证**推荐路线（adapter 多 worker，底层仍 share-nothing 多进程）**相对纯多进程模式**无性能退化**，并量化高风险路线（多线程共栈）的锁竞争代价（若开展）。
- 关键预期：多进程 share-nothing 是免锁基线；任何引入共享/锁的方案都需证明性能不劣于它，否则不值得改造。

---

## 1. 对比指标

| 指标 | 说明 | 采集手段 |
|---|---|---|
| 吞吐（Throughput） | 每秒请求数 / bps | 压测工具（wrk/自研 client） |
| 时延（Latency） | P50/P99/P999 | 压测工具统计 |
| CPU 利用率 | 每核 user/sys/idle | mpstat / top |
| Cache miss | LLC/L1 miss 率 | perf stat（`cache-misses`/`cache-references`） |
| 每核连接数扩展性 | 核数 1→N 时吞吐线性度 | 多组核数对比 |
| 锁竞争（仅路线 B） | 自旋/等待时间 | perf lock / 火焰图 |

---

## 2. 测试拓扑

```
+---------------------------+           +---------------------------+
|  被测端（本机）           |           |  对端 f-stack-client      |
|  f-stack + DPDK 网卡      | <=======> |  (ssh f-stack-client)     |
|  IP 9.134.214.176         |  以太网   |  压测发起方               |
|  N 个 worker / N 个进程   |           |  wrk / 自研 TCP client    |
+---------------------------+           +---------------------------+
```

- 被测端 DPDK 网卡被独占，**不能用本机回环**，压测流量必须由 `ssh f-stack-client` 从对端发起，打到 9.134.214.176。
- 内核栈对照（127.0.0.1 lo）仅用于功能连通性验证，不作为吞吐主基线（回环不经网卡，无 DPDK 意义）。

---

## 3. 对照组设计

| 对照组 | 配置 | 目的 |
|---|---|---|
| **基线组 G0（多进程）** | 纯多进程 share-nothing，N 进程各绑一核（lcore_mask N bit），RSS 分流 | 免锁黄金基线 |
| **实验组 G1（adapter 多 worker）** | 路线 A：adapter N worker + SO_REUSEPORT，底层仍多进程 | 验证相对 G0 无退化 |
| **实验组 G2（多线程共栈，若开展）** | 路线 B：单进程 N 线程共栈 | 量化锁竞争代价 |

**控制变量**：核数（1/2/4/8）、连接数、消息大小（短连接小包 / 长连接大包）、IPv4/IPv6 分别测。

**关键对齐**：G0 与 G1 用**相同核数、相同 RSS 队列数、相同网卡**；差异仅在应用侧线程 vs 进程组织方式，确保对比公平。

---

## 4. 测试矩阵

| 维度 | 取值 |
|---|---|
| 核数 | 1, 2, 4, 8 |
| 消息模式 | 短连接小包（如 64B echo）、长连接大包（如 64KB） |
| 协议 | IPv4 TCP、IPv6 TCP |
| 对照组 | G0 / G1 (/ G2 可选) |

每格重复 3 次取中位数，记录吞吐 + P50/P99/P999 + CPU + cache-miss。

---

## 5. 关键代码相关性（性能敏感点）

| 敏感点 | file:line | 性能含义 |
|---|---|---|
| RSS reta 分布 | `ff_dpdk_if.c:736-751` | 分流是否均匀，决定各 worker 负载均衡 |
| dispatch_ring SC 消费 | `ff_dpdk_if.c:618` | 单消费者免锁，路线 B 改 MC 会引入竞争 |
| 主循环 rx_burst 批量 | `ff_dpdk_if.c:2668,2688` | 批处理规模影响吞吐 |
| idle_sleep | `ff_dpdk_if.c:82` | 空转睡眠影响时延/CPU（config 本地测试值，不入库） |
| worker 绑核 | `main_stack_thread_socket.c:239-250` | cache 亲和，避免跨核迁移 |

---

## 6. 通过判据

| 组别 | 判据 |
|---|---|
| G1 vs G0 | 同核数下吞吐退化 < 5%、P99 时延增幅 < 10%（推荐路线可接受阈值） |
| G2 vs G0 | 若退化显著（如吞吐 -20% 以上），佐证"多线程共栈得不偿失"，支持维持 share-nothing 决策 |
| 扩展性 | G0/G1 吞吐随核数近线性（1→8 核扩展比 > 6x 为佳） |

- config.ini 中 lcore_mask/idle_sleep/IP 等本地测试值仅用于压测，**不入库**。
