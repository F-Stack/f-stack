## 0. Prerequisite: f-stack's Kernel-Option / Header-Override Mechanism (Evidence-Based)

M1-C required "exhaustively re-checking `mk/` and `lib/opt/opt_global.h`"; conclusions below.

### 0.1 Kernel-Option Propagation Mechanism

| Fact | Evidence |
|---|---|
| Kernel-mode source files uniformly `-include opt_global.h` | `mk/kern.pre.mk:51` `KERNEL_CFLAGS= -D__FreeBSD__ -D_KERNEL -DHAVE_KERNEL_OPTION_HEADERS -include opt_global.h -fno-builtin` |
| `opt_global.h` provided by `-I./opt` | `lib/Makefile:75` `INCLUDES+= -I./opt` |
| Current content of `lib/opt/opt_global.h` (**no SMP**) | `MUTEX_NOINLINE 1`, `RWLOCK_NOINLINE 1`, `SX_NOINLINE 1`, `DEV_RANDOM 1`, `NO_EVENTTIMERS 1`, `VIMAGE 1` |
| **No `opt_smp.h`** under `lib/opt/` | `ls lib/opt/ \| grep -i smp` → no output |
| Therefore kernel options have two equivalent entry points | ① write into `lib/opt/opt_global.h`; ② `lib/Makefile`'s `CFLAGS+=` |

> Note: `FF_HOST_SRCS` (`ff_dpdk_if.c` / `ff_config.c` / `ff_host_interface.c` etc., 10 files) goes through `HOST_C` (`lib/Makefile:179`), **without** `KERNEL_CFLAGS`, **not** including `opt_global.h`, nor FreeBSD kernel headers (`HOST_INCLUDES= -I.`). So kernel options only affect `SRCS` (238 files), not `HOST_SRCS` (10 files).

### 0.2 Header-Override Mechanism and the `-I` Order

`lib/Makefile:72-75`'s final order (earlier wins):

```
-I${CURDIR}/include        # lib/include  ← override root
-undef -imacros ... -nostdinc -I. -I$S -I$C     # (kern.pre.mk:48) i.e. -I lib, -I freebsd, -I freebsd/contrib/ck/include
-I./machine_include       # generated by the machine_includes target copying from $S/amd64/include/*
-I./opt
```

**Key evidence (correcting a hidden assumption in plan-17)**: `lib/include/machine` is a **git-tracked symbolic link**:

```

```
（`ls -la lib/include/`；`git ls-files lib/include` lists `lib/include/machine`）

So `lib/include/amd64/include/*.h` takes effect exactly via `<machine/*.h>`. Verified with the real dependency lists of the 248 translation units (`gcc -M`); the override files actually read by the preprocessor number 15:

### 2.5 Candidate A Conclusion

**At the compile level: feasible, extremely low cost — only 1 stub needed (`smp_topo`, `lib/ff_glue.c`).**

plan-17 §0.3's prediction "candidate A may need many stubs" **is disproven by measurement**: the real cost is **1** stub, and both `lib` and `example` clean-build with zero errors, zero new warnings, and the binary produced successfully.

Reason (code-level): among the 238 kernel-mode source files f-stack compiles, `#ifdef SMP` sites are very few (see §4, only 7 in `.c` files), and most SMP branches are either only macros/declarations (`sys/mutex.h`, `sys/smp.h`), or their **call sites** have been eliminated by `lib/include/sys/mutex.h:31-76`'s `#undef` + redefinition to `DO_NOTHING` after `#include_next`; and all `.c` files calling `spinlock_enter()` are not in `lib/Makefile`'s SRCS, so neither the SMP nor the non-SMP branch produces references to those symbols — no cascading missing symbols.

> Wording correction (per `_m17_gate_plan.md` §8.5): the draft of this section once wrote "its dependencies were pre-stubbed by f-stack (`spinlock_enter`/`_mtx_lock_spin_cookie` etc. overridden by `lib/ff_lock.c`, `lib/include/sys/mutex.h`)", **the attribution was inaccurate** — `lib/ff_lock.c` does not define these two symbols anywhere, and `lib/` has no definition of `spinlock_enter` at all. ### 2.6 Convergence of the Semantic Risks (beyond compile evidence, independently verified by leader / `gate-plan`; backfilled per them)

This agent only produced compile evidence; the following three semantic conclusions were code-level substantiated by the leader and `gate-plan`, now converged, **no longer listed as to-be-verified**:

1. **`smp_topo()` returning NULL is safe — equivalent to the original non-SMP behavior.**
   `freebsd/netinet/tcp_hpts.c:1867-1871` is `#ifdef SMP cpu_top = smp_topo(); #else cpu_top = NULL; #endif`, and `:1890if (cpu_top == NULL) { tcp_pace.grp_cnt = 1; }` explicitly handles NULL. So this probe stub is semantically identical to the non-SMP branch, introducing no new behavior.

2. **The "`-DSMP` flips spin-lock expansion" risk — disproven; candidate A is semantically neutral at the spin-lock layer.**
   `lib/include/sys/mutex.h:31-48` `#undef`s `__mtx_lock_spin`/`_mtx_lock_spin_flags`/`thread_lock*`/the trylock family after `#include_next`, and `:59-76` redefines them all to `DO_NOTHING` / constant 1; and all definitions and callers of `spinlock_enter`/`spinlock_exit` are in `.c` files not in `SRCS` (otherwise the baseline build would already have failed at link). So the 4 SMP branches of `freebsd/sys/mutex.h:110/185/254/329`, though flipped by `-DSMP`, are short-circuited by the f-stack override, **producing no actual semantic change** — consistent with §2.3's measured "zero new missing symbols (except `smp_topo`)".

3. **The "`CK_MD_UMP` invalidation" risk — partially holds, and wording must be constrained.**
   `-DSMP` invalidates `freebsd/contrib/ck/include/ck_md.h:95`'s `#ifndef SMP → #define CK_MD_UMP`, restoring the `lock` prefix on CK atomic operations. But the impact scope is converged after verification: `ck_queue.h` and `net/if.c`'s CK usage is all load/store (unaffected by the `lock` prefix); `ck_epoch` is entirely stubbed by `lib/ff_glue.c:1366-1404`; `contrib/ck/src/*.c` does not participate in compilation. **The only substantively affected party is `freebsd/netpfil/ipfw/ip_fw_dynamic.c`'s RMW operations** (`ck_pr_inc_32`/`dec_32`/`or_32`/`xor_32`).
   → This item should be stated as "**a correctness gain eliminating a potential atomicity defect**", **not claimed as fixing a reproduced bug** (no reproduced-evidence).

### 2.7 The Only Remaining Cost-Class Facts of Candidate A (not correctness issues)

- `MAXCPU=1024` grows `freebsd/kern/subr_pcpu.c`'s `cpuid_to_pcpu[MAXCPU]`, `dpcpu_off[MAXCPU]` static arrays from 1 slot to 1024 slots (pure BSS growth), and `cpuset_t` from 8 to 128 bytes (§0.3 measured). Memory cost, not a correctness issue.
- If that cost is unacceptable, there is a **candidate-A-only downgrade step**: with `-DSMP`, also `#define MAXCPU 64` inside `lib/opt/opt_global.h`. Basis: `freebsd/amd64/include/param.h:60-66`'s SMP branch is
  ```c
  #ifdef SMP
  #ifndef MAXCPU
  #define MAXCPU		1024
  #endif
  #else
  #define MAXCPU		1
  #endif
  ```
  The SMP branch carries `#ifndef MAXCPU` protection, **externally overridable** (while the `#else` branch defines unconditionally — exactly why `-DMAXCPU=N` fails under non-SMP). This step can drop the slot count to 64 and `cpuset_t` back to 8 bytes, **still without touching the `freebsd/` upstream tree**.
