# 07 接口与配置设计

> 来源 `_material_C_lifecycle.md §1,§2`。原则：opt-in、与多进程互斥、零回归、API 向后兼容。

## 1. 配置层现状

- `struct ff_config.dpdk`（`ff_config.h:269-328`）：`proc_type`(:272)/`lcore_mask`(:274)/`proc_mask`(:276)/`nb_procs`(:290)/`proc_id`(:291)/`proc_lcore`(:311)。**无任何线程模式字段。**
- `parse_lcore_mask`（`ff_config.c:73-142`）：置位 bit 数 = `nb_procs`（:139），每 bit 一进程一 lcore。
- proc_type 校验只接受 primary/secondary/auto（`ff_config.c:1316-1321`）。
- `--proc-type=` 与 `-c<proc_mask>` 拼接进 EAL argv（`ff_config.c:1167-1170,1151-1154`），每进程只把自己那颗 lcore 传 EAL。

## 2. thread 模式配置扩展（设计）

### 2.1 新增字段
在 `struct ff_config.dpdk`（`ff_config.h:269-328`）新增：
- `int thread_mode`：运行模式开关，**默认 0（关，多进程模式）**。opt-in。
- `int nb_threads`：thread 模式下线程数（= lcore_mask 置位 bit 数）。**新增字段，不改写 `nb_procs` 语义**，降低回归面。

config.ini 示例（新增段/项）：
```ini
[dpdk]
lcore_mask=0xf        ; 4 个 lcore
thread_mode=1         ; 新增: 1=单进程多线程多栈实例; 0(默认)=多进程
```

### 2.2 语义分叉（thread_mode=1 时）
| 项 | 多进程模式(默认) | thread 模式 |
|---|---|---|
| lcore_mask M bit | M 个进程，每进程 1 lcore | **1 个进程，M 个线程**（`nb_threads=M`，`nb_procs=1`） |
| `proc_mask`（EAL `-c`） | 只点亮本进程 1 颗核（`ff_config.c:1151-1154`） | **点亮 lcore_mask 全部 bit**（让 EAL 建 M 个 lcore 供 `rte_eal_mp_remote_launch`） |
| `proc_type` | primary/secondary | **强制 primary**（无 secondary） |
| 实例状态 | 各进程一份全局 | 各线程一份（VNET + per-thread 全局，见 `03`/`05`） |

### 2.3 需改动的配置代码点
1. `parse_lcore_mask`（`ff_config.c:73-142`）：thread 模式下把置位 bit 映射为「同进程 N 线程」，填 `nb_threads`，`proc_mask` 点亮全部 bit。
2. proc_type 校验（`ff_config.c:1316-1321`）：thread 模式拒绝 secondary/auto，强制 primary。
3. `--proc-type=`/`-c` 拼接（`ff_config.c:1151-1170`）：thread 模式拼全 bit coremask。
4. KNI 校验（`ff_config.c:1392-1412`）：由「primary lcore」改判「KNI owner 线程 lcore」（见 `08`）。

## 3. 零回归策略

- **开关默认关**：`thread_mode=0` 时上述所有路径走既有 primary/secondary 分支，**字节级不变**。
- **两模式互斥**：配置期校验 `thread_mode=1` 时 proc_type 必须 primary 且不得再 fork 多进程；`thread_mode=1` 与 `secondary` 组合直接报错。
- **新增而非改写**：用 `nb_threads` 承载线程数，不污染 `nb_procs` 多进程语义。

## 4. 生命周期接口

### 4.1 现状
- `ff_init(int argc, char*const argv[])`（`ff_init.c:36`）；`ff_run(loop_func_t loop, void *arg)`（`ff_init.c:59`）→ `ff_dpdk_run`（`ff_dpdk_if.c:2763`）。
- helloworld 每进程 `main()` 调一次 `ff_init`（`example/main.c:128`）+ 一次 `ff_run`（`:217`）。

### 4.2 API 兼容性（不破坏现有接口）
- `ff_init`/`ff_run` 签名**不变**（不含进程/线程标识），thread 模式对应用**透明**：应用仍调一次 `ff_init`+`ff_run`，由库内根据 `thread_mode` 决定是拉一个 loop 还是 N 个 loop。**API 向后兼容**（`01` A4/G6）。
- `rte_eal_init`（`ff_dpdk_if.c:1594`）全进程一次，故 `ff_init` 只调一次（`04 §3`），不要求应用改调用方式。
- 正向信号：`pcurthread` 已 `__thread`（`ff_api.h:55`），已有 `ff_switch/restore_curthread`、`ff_adapt_user_thread_add`（`ff_api.h:481-487`）线程上下文 API 可复用。

### 4.3 符号导出
`ff_api.symlist` 若新增对外线程/实例管理 API 需同步登记；本方案倾向 thread 模式对应用透明，**尽量不新增对外符号**（仅配置驱动），最大化兼容。

## 5. 配置接口契约表

| 配置项 | 类型 | 默认 | 含义 | 约束 |
|---|---|---|---|---|
| `thread_mode` | int | 0 | 0=多进程；1=单进程多线程多栈 | 与 secondary 互斥 |
| `nb_threads` | int（推导） | — | thread 模式线程数=lcore_mask bit 数 | thread_mode=1 时有效 |
| `lcore_mask` | hex | 既有 | 启用的 lcore 集 | thread 模式=线程绑核集 |
| `proc_type` | str | auto | thread 模式强制 primary | — |
