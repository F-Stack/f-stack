## 1. FreeBSD VNET/VIMAGE = 原生「多协议栈实例」机制（决定性）

### 1.1 源码坐实
| 事实 | file:line |
|---|---|
| `struct vnet` 是完整栈实例，挂全局 vnets 链表 | `freebsd-src-releng-15.0/sys/net/vnet.h:69-75` |
| `vnet_alloc()` 分配栈实例 | 声明 `vnet.h:169`，实现 `sys/net/vnet.c:239` |
| 启动创建默认实例 vnet0 | `sys/net/vnet.c:336`（`curvnet=prison0.pr_vnet=vnet0=vnet_alloc()`） |
| jail 创建时分配独立栈实例 | `sys/kern/kern_jail.c:1814`（`pr->pr_vnet=vnet_alloc()`） |
| **栈实例选择 per-thread** | `sys/net/vnet.h:176`（`#define curvnet curthread->td_vnet`） |
| thread 结构自带 td_vnet | `sys/kern/kern_fork.c:473-474` |
| `VNET_DEFINE` 全局按 vnet 数据段虚拟化 | `vnet.h:279-306` |

### 1.2 无 VIMAGE 退化行为
- `vnet.h:51-53` 注释：无 VIMAGE 时虚拟化全局→普通全局、虚拟化 sysinit→普通 sysinit。
- `vnet.h:398-458`（`!VIMAGE` 分支）：`curvnet≡NULL`(:403)、`CURVNET_SET/RESTORE` no-op(:406-408)、`VNET_DEFINE(t,n)≡t n`(:429)、`VNET_SYSINIT`→普通 sysinit(:442-444)。
- f-stack 现状 `opt_global.h` 无 VIMAGE（`_material_A §0.2`），故 `V_*` 全退化为进程级全局。

### 1.3 外网印证
- vimage(9) man（unix.com）：VNET = "list of virtual network stack instances"，`VNET_FOREACH` 遍历、读锁保护。
- vnet(9)（betterman）：*"To start or tear down a virtual network stack instance the internal functions vnet_alloc() and vnet_destroy() are provided and called from the jail framework."*

### 1.4 结论
> VNET/VIMAGE 是 FreeBSD 为「一地址空间内跑 N 份隔离完整网络栈实例」而生的原生子系统，实例选择 = `curthread->td_vnet`（per-thread），与 f-stack 已 TLS 的 `pcurthread` 契合。→ **原生多栈实例技术首选路径**。⚠️ 但 VIMAGE 在 f-stack 阉割用户态可用性**须运行时验证**（`04 §2`/`11`）。

## 2. DPDK per-lcore（交叉验证，与 `06` 一致）
- `RTE_DEFINE_PER_LCORE(t,n) ≡ __thread t per_lcore_##n`（`rte_per_lcore.h:33`）。
- `rte_lcore_id() ≡ RTE_PER_LCORE(_lcore_id)`（`rte_lcore.h:77-81`，TLS）。
- lcore=pthread+核绑定，`rte_eal_remote_launch` 启动原语（`rte_launch.h:37-99`）。
- 外网（旧素材，摘要级）：lcore 本质 pthread 封装 + CPU 亲和；mempool/ring 支持 MP/MC 与 SP/SC。

## 3. 业界 thread-per-core 对比

### 3.1 mTCP（已抓取，NSDI 2014 + 官网）
- thread-per-core + share-nothing：每应用线程配独立 TCP 线程绑同核，所有 API 传 `mctx`（线程栈上下文），避免共享 accept 队列，8 核近线性扩展。
- 启示：`mctx` ≈ f-stack 每线程一份栈实例句柄（VNET/per-thread 上下文），「每线程一份完整栈上下文 + 同核绑定」是业界验证过的可扩展模型。

### 3.2 Seastar / VPP（社区常识，未深抓，不杜撰细节）
- Seastar：thread-per-core + share-nothing，每核一 reactor，核间无锁消息传递，配 DPDK。
- VPP：main + 多 worker 线程，RSS/handoff 分流，graph node 向量批处理。
- 诚实标注：官方文档本轮未深入抓取，细节需要时另查。

### 3.3 f-stack 官方（已抓取，多来源）
- 官方模型 = 多进程 share-nothing（primary/secondary + rte_ring + 共享大页）；**未检索到官方「单进程多线程栈运行模式」设计文档或 PR**（不杜撰）。

## 5. 交叉验证结论（供方案）
1. 原生多协议栈实例 = VNET/VIMAGE（首选路径），per-thread 契合 `pcurthread`。
2. VIMAGE 只覆盖 `VNET_DEFINE` 网络栈全局；f-stack 自造全局须另行 per-thread 化。
3. DPDK per-lcore/launch/ring/mempool 齐备，与 `06` 一致。
4. 业界 mTCP/Seastar 一致 thread-per-core + share-nothing，佐证方向。
5. 全程不涉及 adapter（应用侧机制，非栈侧运行模型）。
