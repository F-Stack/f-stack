# 10 里程碑与工作清单

> 按危险度递增排序。原则：从低垂果实与可行性验证起步，高危项（VIMAGE、init 重构）先做 PoC 验证再全量。每里程碑设回滚点，thread_mode 开关默认关保多进程零回归。

## 1. 里程碑总览

| 里程碑 | 目标 | 危险度 | 前置 |
|---|---|---|---|
| CM0 | 低垂果实 + 脚手架 | 低 | — |
| CM1 | 配置层 thread_mode 开关（不接实现） | 低 | CM0 |
| CM2 | `lcore_conf` per-lcore 化 + DPDK 拉 N lcore | 中 | CM1 |
| CM3 | f-stack 自造底座全局 per-thread 化（pcpu/thread0/callout） | 高 | CM2 |
| CM4 | **VIMAGE 可行性 PoC**（关键卡点验证） | 高/存疑 | CM3 |
| CM5 | 初始化重构（ff_init 一次 + per-thread 栈实例 init） | 极高 | CM4 |
| CM6 | KNI owner 线程 + 工具链 IPC（C1 保兼容） | 中 | CM5 |
| CM7 | 端到端联调 + 多进程零回归回归 + 性能基线 | 中 | CM6 |

## 2. 工作分解（WBS）

### CM0 低垂果实 + 脚手架（低危）
1. 恢复 `msg_iov_tmp/msg_iovlen_tmp` 的 `__thread`（`ff_syscall_wrapper.c:225-226`）——确定性数据错乱修复，多进程模式亦无害。
2. 引入统一「当前栈实例」访问抽象（如 `ff_cur_lcore_conf()` 宏，暂等价 `&lcore_conf`），为后续 per-lcore 化预留间接层。
3. 回滚点：纯 `__thread` 恢复 + 抽象宏，行为不变。

### CM1 配置层开关（低危，不接实现）
1. `struct ff_config.dpdk` 新增 `thread_mode`/`nb_threads`（`ff_config.h:269-328`）。
2. `parse_lcore_mask`（`ff_config.c:73-142`）thread 模式分支（填 nb_threads、proc_mask 全 bit）；proc_type 校验强制 primary（`:1316-1321`）；`--proc-type=`/`-c` 拼接分叉（`:1151-1170`）。
3. 互斥校验：thread_mode=1 与 secondary 冲突报错。
4. 回滚点：开关默认 0，走既有分支字节不变。

### CM2 lcore_conf per-lcore + 拉 N lcore（中危）
1. `lcore_conf` 单例→`lcore_conf[RTE_MAX_LCORE]`（`ff_dpdk_if.c:123`），改 30+ 引用点 + `ff_memory.c` extern。
2. `init_lcore_conf`（`:400-467`）每线程填自己那份。
3. thread 模式给 EAL N-bit coremask，`rte_eal_mp_remote_launch`（`:2770`）拉 N loop，各 loop 用 `&lcore_conf[rte_lcore_id()]`。
4. 回滚点：thread_mode=0 时 `lcore_conf[proc_id]` 退化为单份。

### CM3 底座全局 per-thread（高危）
1. `pcpup`（`ff_freebsd_init.c:69`）→每线程一份 pcpu。
2. `thread0`/`proc0`（`ff_init_main.c:96,98`）→每实例一份。
3. `cc_cpu`（`ff_kern_timeout.c:180`）→每实例 callout_cpu/callwheel，`CC_CPU/CC_SELF`（`:181-182`）改按线程索引。
4. `stop_loop`/`freebsd_clock`/`seed` 等 P1 项 per-thread。

### CM4 VIMAGE 可行性 PoC（关键卡点）
1. `opt_global.h` 加 `VIMAGE`，评估 f-stack 编译单元 VNET 基建完整性。
2. PoC：单进程内 `vnet_alloc()` 2 份 + 设 `td_vnet`，验证 `VNET_SYSINIT`（tcp/ip/pcb）能否每 vnet 各跑一份、`V_tcbinfo`/`V_rt_tables` 是否隔离。
3. **门禁**：PoC 不通过则 VIMAGE 路线（乙）改走路线甲（手工 per-thread 化数百个 `V_*`）——此为重大分叉，须转人工决策。
4. ⚠️ 本里程碑结论**须运行时验证**，静态不可断言成功。

### CM5 初始化重构（极高危）
1. `ff_init`（`ff_init.c:35`）拆分：全局一次性 init（EAL/UMA/mutex/vnet0）+ per-thread 栈实例 init（vnet_alloc/td_vnet/VNET_SYSINIT/pcpu_i/thread0_i）。
2. `mi_startup`（`ff_init_main.c:173-285`）非-vnet 部分一次 + vnet 部分每线程（依赖 CM4 结论）。
3. 每线程入口串起：绑 lcore→建上下文→栈 init→`main_loop`。

### CM6 KNI + 工具链（中危）
1. KNI 门控由 `RTE_PROC_PRIMARY`（`ff_dpdk_if.c:2661`、`ff_dpdk_kni.c:379/426`）改 owner 线程判定；配置校验（`ff_config.c:1396-1411`）改判 owner lcore。
2. 工具链优先 C1（保留外部工具进程 attach，见 `08`）。

### CM7 联调 + 回归 + 基线（中危）
1. 端到端：lo 127.0.0.1 内核栈对照 + DPDK 网卡 <DPDK_NIC_IP> 经 f-stack-client 实测（见 `11`）。
2. 多进程零回归全量回归（thread_mode=0）。
3. 性能基线：thread 模式 vs 多进程（见 `11`）。

## 3. 回滚与门禁

- 每里程碑 thread_mode=0 必须字节级零回归（一票否决）。
- CM4 VIMAGE PoC 是路线分叉门禁：不通过转人工决策路线甲/乙。
- 改代码先 `make clean` 再编译；lib 最小注释；commit message 英文 1-3 句；config.ini 本地测试值不入库；rm/kill/chmod 走脚本。

## 4. 关键路径与风险提示

- **关键路径**：CM4（VIMAGE 可行性）是全局最大不确定项，决定路线甲/乙，建议尽早 PoC。
- CM5（init 重构）极高危，依赖 CM3/CM4 全部就绪。
- 低危 CM0/CM1 可先落地积累（`msg_iov_tmp` 修复独立有益）。
