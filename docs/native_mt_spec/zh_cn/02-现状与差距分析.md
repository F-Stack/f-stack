# 02 现状与差距分析

> 以 `lib/` 代码 file:line 为准。素材来源：`_material_A_globalstate.md`、`_material_B_dpdk.md`、`_material_C_lifecycle.md`。

## 1. 现状：多进程 share-nothing 模型

### 1.1 一进程 = 一 lcore = 一栈实例
- `ff_init()`（`ff_init.c:35-56`）串行调用 `ff_load_config → ff_dpdk_init → ff_freebsd_init → ff_dpdk_if_up`，**整个进程只跑一次**。
- 多核并发靠 **DPDK 多进程**（primary/secondary）：每实例一个 `proc_id`，配置 `proc_lcore[]`/`nb_procs`（`ff_config.c:79-139`），每进程绑一个 lcore。
- `ff_dpdk_run()`（`ff_dpdk_if.c:2764-2773`）：`rte_eal_mp_remote_launch(main_loop, lr, CALL_MAIN)` + `rte_eal_mp_wait_lcore()`；但每进程 coremask 单 bit（`ff_config.c:1151-1154`），实际每进程只跑一个 `main_loop`。
- `main_loop`（`ff_dpdk_if.c:2585`）里 `qconf = &lcore_conf` 取**全局单例**。
- 因进程隔离，`pcpup`/`lcore_conf`/`cc_cpu`/所有 `VNET_*` 全局各进程一份，天然 share-nothing，从不冲突。

### 1.2 配置模型
- `struct ff_config.dpdk`（`ff_config.h:269-328`）：`proc_type`(:272)/`lcore_mask`(:274)/`proc_mask`(:276)/`nb_procs`(:290)/`proc_id`(:291)/`proc_lcore`(:311)。
- `parse_lcore_mask`（`ff_config.c:73-142`）：lcore_mask 置位 bit 数 = `nb_procs`（:139），每 bit 对应一个进程一个 lcore。
- proc_type 校验只接受 primary/secondary/auto（`ff_config.c:1316-1321`）。

### 1.3 数据面/控制面 ring
- `dispatch_ring[port][queue]`（数据面，`ff_dpdk_if.c:129`）：`RING_F_SC_DEQ`（`:619`），多源 lcore 写、单 owner 读（MP+SC）。
- `msg_ring[RTE_MAX_LCORE]`（控制面 IPC，`:177`）：`RING_F_SP_ENQ|RING_F_SC_DEQ`（`:670`），已按 proc_id 数组化。
- mempool `pktmbuf_pool[NB_SOCKETS]`（`:125`）按 NUMA socket 共享，`cache_size=MEMPOOL_CACHE_SIZE`（`:540`），flag=0（MP/MC）。

### 1.4 KNI / 工具链
- KNI 严格 primary-only：`ff_kni_init/alloc`（`ff_dpdk_kni.c:379/426`）、主循环（`ff_dpdk_if.c:2661`）、配置校验（`ff_config.c:1392-1412`）。
- 工具链（`tools/`）强依赖 secondary 进程：`ff_ipc_init` 硬编码 `--proc-type=secondary`（`tools/compat/ff_ipc.c:67`），经 `msg_ring` 与栈通信。

## 2. 已有线程基础设施（可复用的正向信号）

| 能力 | file:line | 说明 |
|---|---|---|
| `pcurthread` TLS | `ff_compat.c:59` | 每线程独立 current thread 指针，**已 `__thread`**；`ff_api.h:55` extern |
| `ff_pthread_create` | `ff_thread.c:32-46` | 封装 pthread_create，把父线程 pcurthread 传播给子线程 |
| `ff_adapt_user_thread_add/exit` | `ff_compat.c:96-128` | 为用户线程建独立 proc/thread 上下文（独立 fd 表/cred/limit）；注释标注 "Only used by LD_PRELOAD mode"（`ff_compat.c:90`） |
| `ff_switch/restore_curthread` | `ff_compat.c:131-148` | 临时切换 pcurthread |
| pcap per-thread | `ff_dpdk_pcap.c:55-57` | `static __thread` 范式参考 |

**关键意义**：`curthread` 已 TLS，这与 FreeBSD VNET 的 `curvnet=curthread->td_vnet`（`vnet.h:176`）精确契合——是原生多栈实例的最大可行性支点。

## 3. 差距分析（要实现原生多栈实例还差什么）

| 差距 | 现状 | 目标 | 详见 |
|---|---|---|---|
| D1 栈实例数 | 一进程一实例 | 一进程 N 线程 N 实例 | `04` |
| D2 初始化 | `mi_startup`/SYSINIT 一次性、跑完打勾（`ff_init_main.c:271`），不可 N 次 | 每线程一份独立初始化（VNET_SYSINIT 每 vnet 一次 + per-thread 全局） | `04` |
| D3 网络栈全局 | 数百个 `V_*` 退化为进程级全局（无 VIMAGE，`opt_global.h` 无 VIMAGE） | 启 VIMAGE，按 `curvnet` per-thread 隔离 | `03`/`05` |
| D4 f-stack 自造全局 | `lcore_conf`/`pcpup`/`cc_cpu`/`thread0`/`msg_iov_tmp` 全局单例 | per-thread 化（数组/`__thread`/每实例） | `03` |
| D5 DPDK 拉起 | 每进程单 lcore | 单进程 N lcore（N-bit coremask） | `06` |
| D6 配置 | 无线程模式字段 | 新增 thread_mode + nb_threads，opt-in 互斥 | `07` |
| D7 KNI | primary 进程门控 | owner 线程门控 | `08` |
| D8 工具链 | 依赖 secondary 进程 | thread 模式无 secondary，IPC 需重设计 | `08` |

## 4. adapter 现状（客观记录，非本方案目标）

`adapter/syscall/` 下的 LD_PRELOAD 适配（`FF_THREAD_SOCKET`/`FF_MULTI_SC` 编译宏、`main_stack_thread_socket.c`、`ff_hook_syscall.c` worker_id 映射）是**应用侧**机制：让未改造的应用程序通过 LD_PRELOAD 劫持 socket 调用、以多 worker 方式使用底层**多进程** f-stack。它解决的是「应用如何接入 f-stack」，**不是「协议栈本身以多线程运行」**。本轮目标是后者，adapter 不在方案范围内，仅此记录以免混淆两个层面。
