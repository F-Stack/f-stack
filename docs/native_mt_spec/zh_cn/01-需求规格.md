# 01 需求规格

## 1. 背景与动机

f-stack 当前只支持 DPDK Primary-Secondary **多进程** 模型（一进程一 lcore 一栈实例，share-nothing）。用户要求库内**原生**支持一种新的运行模式：**单进程内多线程，每线程运行一份独立的协议栈实例**（多协议栈实例、share-nothing、无锁）。

需求来源：多进程模型在部分部署场景存在不便（进程管理、共享大页与 IPC 开销、与宿主应用共进程集成困难等）；业界（mTCP/Seastar）普遍采用 thread-per-core + share-nothing 的单进程多线程模型；issue #430 反映真实用户在 pthread 多线程环境使用 f-stack 的诉求（应用侧佐证）。

## 2. 目标（In Scope）

| # | 目标 |
|---|---|
| G1 | 在 `lib/` 内原生新增「单进程多线程多协议栈实例」运行模式：一个进程内起 N 个 pthread（每线程绑一个 lcore），各跑一份独立 FreeBSD 协议栈实例 |
| G2 | 实例间 share-nothing、无锁（数据面靠 RSS 分队列、跨线程分发用无锁 ring） |
| G3 | 复用 FreeBSD 原生 VNET/VIMAGE 作为「多协议栈实例」的隔离基座（首选技术路径） |
| G4 | 把非-VNET 的 f-stack 自造全局 per-thread 化（`lcore_conf`/`pcpup`/`cc_cpu`/`thread0`/`msg_iov_tmp` 等） |
| G5 | 配置层 opt-in 开关，与既有多进程模式**互斥**且**零回归** |
| G6 | 保持对现有 `ff_api.h` 应用接口的向后兼容 |

## 3. 非目标（Out of Scope）

| # | 非目标 |
|---|---|
| N1 | **不采用 LD_PRELOAD adapter / 多 worker 路线**作为解决方案（仅作现状记录） |
| N2 | **不采用「共享单栈 + 细粒度锁」**（违背 share-nothing，仅作被否决对比） |
| N3 | 本轮不做实际编码与编译，仅输出调研 + spec |
| N4 | 不改动多进程模式的既有行为（零回归红线） |
| N5 | 本轮不生成英文版文档 |

## 4. 术语表

| 术语 | 定义 |
|---|---|
| **协议栈实例（stack instance）** | 一份完整、独立的 FreeBSD 用户态网络栈状态（ifnet、PCB 表、路由 FIB、端口分配、协议计数器、callout 等） |
| **应用侧多线程** | 应用程序用多个 pthread 调用 f-stack socket API（issue #430 场景）；与栈运行模型无关 |
| **栈侧多线程运行模型** | 协议栈本身以多线程方式运行、每线程一份独立实例（**本轮目标**） |
| **VNET/VIMAGE** | FreeBSD 原生的虚拟网络栈子系统，一个地址空间内可跑 N 份互相隔离的完整网络栈实例 |
| **per-thread 化** | 把全局单例变量改造为每线程一份独立副本（`__thread` / `RTE_PER_LCORE` / 按 lcore_id 索引数组） |
| **share-nothing** | 各执行单元不共享可变状态，无锁、线性扩展 |
| **thread_mode** | 本方案拟新增的运行模式开关（opt-in，默认关） |

## 5. 验收标准

| # | 验收项 |
|---|---|
| A1 | spec 完整覆盖：全局状态清单、栈实例初始化机制、架构方案、DPDK 对接、配置接口、KNI/IPC 归属、里程碑、测试、风险 |
| A2 | 所有关键技术论断附实际 file:line，且与代码一致（门禁抽验） |
| A3 | 方案聚焦原生多栈实例，无「推荐 adapter」结论残留 |
| A4 | 明确区分应用侧多线程 vs 栈侧多线程运行模型，issue #430 定位正确 |
| A5 | 多进程零回归论证闭环；opt-in 开关默认关 |
| A6 | 诚实标注静态无法定论、须运行时验证的项，不臆断 |
| A7（后续编码阶段） | thread_mode 开关关闭时，多进程模式行为字节级不变；开启时 N 线程各起独立栈实例并正常收发（lo 127.0.0.1 内核栈对照 + DPDK 网卡 9.134.214.176 经 f-stack-client 实测） |

## 6. 约束

- 代码为准、交叉验证不一致以代码为准、诚实边界不臆测。
- 后续编码遵循：lib 最小注释、改代码先 `make clean` 再编译、commit message 英文 1-3 句、config.ini 本地测试值不入库、rm/kill/chmod 走脚本。
